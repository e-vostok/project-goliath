# 02_SYSTEM_SPECS / 00_core_nat_vk_facts — Проверка фактов о VK API (задача NAT-0)

> Исполнитель: IDE Execution Agent (Devin). Дата проверки: 2026-10-17.
> Источники: только первоисточники — `dev.vk.com` / `dev.vk.ru` (официальная документация ВК), официальные справки `vk.com/faq*` и `expert.vk.com`, репозитории `github.com/VKCOM/*` (`vk-api-schema`, `vk-bridge`, `vk-miniapps-deploy`). Реальные вызовы VK API и проверки в живом интерфейсе не выполнялись (docs-only задание).
> Каждый пункт N1–N7 отвечает на вопрос задания NAT-0 — что платформа реально позволяет для графики, музыки и взаимодействия с картой государства до проектирования «Регистрации 2.0» (флаг, портрет правителя, гимн, столица).

## Сводка по вопросам (без таблиц)

1. Загрузка картинки из мини-приложения (десктоп) — **возможно**: приложение в iframe — обычная веб-страница, `<input type=file>` работает штатными средствами, запрета в документации и правилах нет; но как только картинка видна другим игрокам, включаются правила о пользовательском контенте (соглашение с определением неприемлемого контента, регулярная модерация, кнопка жалобы при постмодерации, удаление не позже 48 часов).
2. Фотоальбомы сообщества как хранилище — **загрузка через API невозможна** (все методы загрузки в альбом принимают только ключ пользователя с правом `photos`, которое выдаётся «в исключительных случаях» через Поддержку); **чтение альбома возможно** сервисным ключом — годится для галереи готовых флагов, которую Project Owner наполняет руками через интерфейс ВК.
3. Свой файловый storage у ВК для мини-приложений — **нет пригодного**: статический хостинг ВК принимает только сборку приложения (ZIP ≤ 300 МБ, ≤24 выкладок в сутки, аудио и видео запрещены); `docs.*` грузит файлы до 4 ГБ в документы сообщества ключом сообщества с правом `docs`, но выдаёт подписанные ссылки для скачивания, а не прямые URL для `<img>`; `storage.*` — это строки ≤4096 символов, не файлы.
4. Музыка ВК — **внутри приложения невозможно**: методов `audio.*` нет ни в документации, ни в официальной JSON-схеме API, событий плеера в VK Bridge нет; допустимая альтернатива — ссылка на трек/плейлист (открывается в новой вкладке и играет в интерфейсе ВК) или вложение `audio{owner_id}_{media_id}` в сообщении бота.
5. Свои картинки с нашего сервера — **возможно без всяких функций ВК**: Caddy уже отдаёт статику из `/srv` до fallback на `index.html`, а `/api/*` проксирует в backend; документированные рамки деплоя — «больше 3 ГБ свободного места на диске», файл подкачки 2 ГБ при малой памяти, один воркер FastAPI, и бэкап покрывает только дамп БД — папку с загрузками существующий `backup.sh` не сохраняет.
6. Правая кнопка мыши на карте — **не подтверждено документально (UNVERIFIED)**: по стандарту событие `contextmenu` доходит до документа внутри iframe и `preventDefault` его гасит, запрета в правилах платформы не найдено, но прямого описания у ВК нет — нужна ручная проверка на живом сайте.
7. Ссылки на статьи ВК — **подтверждена форма `https://vk.com/@…`**; `vk.ru/@…` — тот же вид на каноническом домене, `m.vk.com/@…` — мобильное зеркало; сейчас `nation.history_url_allowed_hosts` принимает только `vk.com` и `vk.ru` — игрок, скопировавший ссылку из мобильного браузера (`m.vk.com/@…`), получит отказ.

### N1 — `<input type=file>` внутри iframe на десктопе; обязанности за пользовательские изображения

- Status: CONFIRMED (механизм — по архитектуре платформы; обязанности — по правилам)
- Fact: Платформа фиксирует, что на `vk.com` и `m.vk.com` мини-приложение — это «веб-страница с элементом `iframe`», в которую загружается клиентская часть приложения, т.е. обычный HTML-документ. Ни документация, ни правила размещения не ограничивают стандартные элементы страницы: специального события VK Bridge для выбора локального файла у пользователя не существует (в полном списке событий есть только `VKWebAppDownloadFile` — скачивание, `VKWebAppShowImages` — просмотр, `VKWebAppShare` — поделиться), значит загрузка файла делается только обычным `<input type=file>` / File API, как на любом сайте.
- Fact (правила UGC): Раздел 2.5 «Пользовательский контент» правил размещения (редакция от 17.03.2026) определяет пользовательский контент как «текстовые материалы, изображения, видео и тому подобное, в том числе видимые другим пользователям» и требует: 2.5.1 — при наличии загрузки пользователь обязан явно принять пользовательское соглашение приложения с определением неприемлемого контента; 2.5.2 — контент должен «регулярно и оперативно модерироваться», допустимы предварительная, пост- и автоматизированная модерация, но «только автоматизированной модерация ограничиваться не должна», а при постмодерации обязательна «возможность пожаловаться на неприемлемый Пользовательский контент»; 2.5.3 — неприемлемые материалы удаляются «не позднее 48 часов после подачи жалобы», а аккаунты нарушителей — удаляются или блокируются; 2.5.5 — перечень недопустимого контента (насилие, эротика, экстремизм, наркотики и пр.). Дополнительно п. 1.1.x требует пользовательское соглашение и политику конфиденциальности в Панели управления и согласие на обработку данных (см. факт R8 в `03_registry_vk_facts.md`).
- Source: https://dev.vk.com/ru/mini-apps/development/iframe-webview (таблица платформ: vk.com — iframe), https://dev.vk.com/ru/bridge/overview (полный список событий — методов выбора файла нет), https://dev.vk.com/ru/mini-apps-rules (пп. 2.5.1–2.5.5), https://dev.vk.ru/ru/bridge/VKWebAppDownloadFile
- Spec impact: для нас это значит, что флаг и портрет игрок загружает обычной кнопкой «Выбрать файл» внутри приложения — никакой отдельной функции ВК не нужно; но в спецификацию «Регистрации 2.0» обязаны войти соглашение с запретом неприемлемого контента, экран модерации/жалобы и процедура удаления по жалобе за 48 часов.

### N2 — Фотоальбомы сообщества через `photos.*`: ключи, загрузка, лимиты, стабильность URL

- Status: NOT POSSIBLE (загрузка через API); CONFIRMED (чтение альбома сервисным ключом); UNVERIFIED (срок жизни и хотлинк URL)
- Fact (ключи и методы): Все методы записи в альбомы принимают только **ключ доступа пользователя** с правом `photos`, которое «выдаётся в исключительных случаях через запрос в поддержку по электронной почте devsupport@corp.vk.com»: `photos.getUploadServer`, `photos.save`, `photos.createAlbum`. Ключ доступа сообщества на этих страницах не упомянут вовсе — хотя у ключа сообщества формально существует право `photos` («Доступ к фотографиям сообщества»), единственный найденный метод, который оно реально открывает, — `photos.getMessagesUploadServer` (фото в личное сообщение, служебный альбом `aid=-64`, привязка к `peer_id`). Чтение альбомов при этом открыто шире: `photos.get` и `photos.getAlbums` принимают ключ пользователя **или сервисный ключ доступа** (создаётся в кабинете приложения, бессрочный). Лимиты загрузки: до 5 фото за запрос, JPG/PNG/GIF, файл ≤ 50 МБ, сумма сторон ≤ 14 000 px, сторона ≤ 8 192 px, соотношение сторон не уже 1:20; в альбоме — до 10 000 фотографий (официальная справка). Отдельно: загрузку может блокировать ошибка 13000 «Content upload was denied due to active community strikes».
- Fact (URL): Объект `photo` отдаёт массив `sizes[]` с полями `type`, `url`, `width`, `height`; реальные URL вида `https://sun9-west.userapi.com/sun9-45/s/v1/ig2/<длинный-хеш>.jpg?size=…&quality=…&type=album` — содержат подписанный хеш в пути. Документация не заявляет ни срока жизни, ни условий хотлинка/`Referer` для этих URL — тот же пробел, что и для аватарок (факт R7 в `03_registry_vk_facts.md`).
- Source: https://dev.vk.ru/ru/method/photos.getUploadServer, https://dev.vk.ru/ru/method/photos.save, https://dev.vk.ru/ru/method/photos.createAlbum (только ключ пользователя, `photos` «в исключительных случаях»), https://dev.vk.ru/ru/method/photos.get, https://dev.vk.ru/ru/method/photos.getAlbums (ключ пользователя или сервисный), https://dev.vk.ru/ru/method/photos.getMessagesUploadServer (ключ сообщества + право `photos`), https://dev.vk.ru/ru/api/privacy (права ключа сообщества), https://dev.vk.ru/ru/api/upload/album-photos (лимиты загрузки), https://vk.com/faq18545 (до 10 000 фото в альбоме, сторона ≤ 8 192 px), https://dev.vk.ru/ru/reference/objects/photo (`sizes[].url`)
- Spec impact: использовать альбомы сообщества как «хостинг флагов, заливаемый игроками через API» нельзя; рабочий гибрид — Project Owner вручную заливает в альбом набор эталонных флагов/гербов, а сервер читает их сервисным ключом через `photos.get` и показывает как выбор «из галереи», причём URL надо перечитывать периодически (по TTL), а не хранить вечно.

### N3 — Файловое хранилище для мини-приложений (`docs.*`, статический хостинг, `storage.*`, VK Cloud)

- Status: CONFIRMED (варианты и их пределы); для нашей задачи — подходящего нет
- Fact: (а) **Хостинг статики** `vk-miniapps-deploy` — официальный бесплатный CDN для файлов мини-приложения: ZIP ≤ 300 МБ, выкладка не более 24 раз в сутки, хранятся до 10 production- и до 100 staging-версий; **«Размещать аудио- и видеофайлы на хостинге нельзя»** — это место для сборки приложения, а не для файлов игроков. (б) **Документы `docs.*`**: `docs.getWallUploadServer` принимает ключ сообщества с правом `docs` (и ключ пользователя с правом `docs`, тоже «в исключительных случаях»), `docs.save` — ключ пользователя или сообщества; файл попадает в папку «Отправленные» сообщества/пользователя для последующей отправки на стену или в сообщение; форматы — «любые, кроме MP3», размер ≤ 4 ГБ. Возвращаемый `url` вида `https://vk.ru/doc{owner}_{id}?hash=…&dl=…:1674050872:…&api=1&no_preview=1` — подписанная ссылка на скачивание/просмотр документа, а не документированный стабильный URL картинки для `<img>`. (в) **`storage.*`** — key-value хранилище приложения: до 1 000 переменных на пользователя, значение обрезается до 4 096 символов, не более 1 000 вызовов в час на пользователя — для файлов не предназначено. (г) **VK Cloud** упомянут в «Первых шагах» как один из вариантов хостинга приложения («Разместить мини-приложение в облаке VK Cloud») — это внешний платный облачный сервис общего назначения, а не функция платформы мини-приложений.
- Source: https://dev.vk.ru/ru/mini-apps/development/hosting («Ограничения»: 24 выкладки/сутки, 300 МБ, 10+100 версий, запрет аудио/видео), https://dev.vk.ru/ru/mini-apps/getting-started (раздел 4, VK Cloud), https://dev.vk.ru/ru/method/docs.getWallUploadServer, https://dev.vk.ru/ru/method/docs.save (допустимые ключи), https://dev.vk.ru/ru/api/upload/document-in-profile (≤4 ГБ, любые форматы кроме MP3, подписанный `url`), https://dev.vk.ru/ru/method/storage.set (4096 символов, 1000 переменных, 1000 вызовов/час)
- Spec impact: официального «файлового хранилища с прямыми ссылками» у платформы нет — картинки флагов и портретов придётся хранить и раздавать с нашего сервера (см. N5); `docs.*` годится разве что как обходной путь «отправить файл игроку вложением», а не как CDN.

### N4 — `audio.*` и музыка ВК: выбор трека, проигрывание в приложении, ссылки

- Status: NOT POSSIBLE (API музыки и проигрывание внутри мини-приложения); CONFIRMED (ссылки и вложения как альтернатива)
- Fact (нет методов): В справочнике методов `dev.vk.ru` раздела `audio` нет — страница `audio.get` отдаёт 404; в официальной JSON-схеме VK API (`VKCOM/vk-api-schema`) папка `audio/` содержит только `objects.json` — объект «Аудиозапись» существует как вложение, но `methods.json` для `audio` отсутствует, т.е. ни одного метода `audio.*` в публичном API нет. Право `audio` (+8) осталось в таблице прав ключа пользователя, но пользоваться им нечем. В VK Bridge событий для музыки нет вообще — ни выбора трека, ни встраиваемого плеера (полный список событий на странице «Обзор» не содержит audio/music-методов). Дополнительно: статический хостинг мини-приложений прямо запрещает аудиофайлы (N3), а загрузка документов запрещает MP3 — то есть «подсунуть гимн через файловые механизмы ВК» тоже не выйдет.
- Fact (альтернативы): Тип вложения `audio` документирован для `messages.send` и `wall.post` — формат `audio{owner_id}_{media_id}` (для чужого вложения добавляется `_{access_key}`); в пост можно приложить «до 10 музыкальных треков или 1 плейлист/альбом/подкаст», существует тип `audio_playlist`. Такие вложения играются в штатном интерфейсе ВК (диалог, запись), а не внутри приложения. Публичные форматы ссылок в документации для разработчиков не описаны; по официальной статье ВК Музыки рабочая прямая ссылка на плейлист выглядит как `vk.com/music/playlist/{owner_id}_{playlist_id}_{ключ}` и берётся из «Поделиться → Экспортировать → Прямая ссылка» (та же механика «Скопировать ссылку» есть у треков; точные формы ссылок на трек — UNVERIFIED-фрагмент). Правило 2.5.4 обязывает выводить игрока на внешние сайты через `vk.ru/away.php?to=…`, но ссылки на `vk.com`/`vk.ru` — внутренние и под него не подпадают. Если гимн — наш собственный файл с нашего сервера, проигрывать его в приложении может обычный HTML5 `<audio>`; тогда срабатывает правило 2.2.5: при наличии звуковых эффектов «должна быть возможность быстрого включения и отключения звука или регулировка его громкости».
- Source: https://dev.vk.ru/ru/method/audio.get (404 — метода нет), https://github.com/VKCOM/vk-api-schema/tree/master/audio (только `objects.json`), https://dev.vk.com/ru/bridge/overview (нет audio-событий), https://dev.vk.ru/ru/reference/objects/audio (объект вложения), https://dev.vk.ru/ru/method/messages.send (`attachment`: `audio{owner_id}_{media_id}`, access_key), https://dev.vk.com/ru/method/wall.post (до 10 треков или 1 плейлист, тип `audio_playlist`), https://vk.com/@vkmusicbotds-kak-poluchit-rabochuu-ssylku-na-pleilist (прямая ссылка на плейлист с ключом доступа), https://dev.vk.com/ru/mini-apps-rules (пп. 2.2.5, 2.5.4)
- Spec impact: «проиграть гимн внутри приложения через ВК Музыку» сделать нельзя; реалистичный дизайн — либо свой аудиофайл с нашего сервера + обязательный выключатель звука, либо поле «ссылка на трек/плейлист ВК» которое ведёт наружу, либо бот присылает гимн вложением `audio{owner}_{id}` в сообщение (играется в диалоге); встроенного выбора трека из каталога ВК не будет — игрок вставляет ссылку руками.

### N5 — Свои картинки с нашего сервера: что уже есть в деплое и практические пределы

- Status: CONFIRMED (архитектура и задокументированные рамки; абсолютный объём диска/памяти в runbook не задан)
- Fact: По runbook и текущему деплою: Caddy на 80/443 отдаёт собранный фронтенд из `/srv` с `try_files {path} /index.html` (файл, лежащий на диске внутри `/srv`, отдаётся раньше SPA-запасного варианта; `/assets/*` кэшируется как immutable) и проксирует `/api/*` в `backend:8000` (FastAPI, один воркер); сжатие zstd/gzip включено, `X-Frame-Options`/`frame-ancestors` сознательно не ставятся (приложение живёт в iframe ВК). Ограничений по памяти контейнеров в `docker-compose.prod.yml` нет. Документированные рамки: чек-лист требует «свободно больше 3 ГБ» на `/` (`df -h`); на дешёвом VPS «памяти мало» — настраивается swap 2 ГБ (`swappiness=10`); диск чистится через `docker system df`/`docker system prune`. Бэкап: `backup.sh` делает только `pg_dump` (14 ежедневных дампов + шифрованная внешняя копия через age+rclone) — **файлы на диске сервера существующий механизм не сохраняет**.
- Source: docs/deploy_runbook.md (§1 схема и тома, §2.4 swap, §8 бэкапы, §10 «Кончилось место», §11 чек-лист «>3 ГБ»), deploy/Caddyfile (root `/srv`, `try_files`, `/api/*` → backend:8000, immutable `/assets/*`, комментарий про отсутствие frame-заголовков), deploy/backup.sh (`pg_dump` единственный объект копирования), docker-compose.prod.yml (лимитов памяти нет)
- Spec impact: флаги и портреты раздаём сами — либо как статику через Caddy (папка внутри `/srv`), либо эндпоинтом `/api/v1/...` у единственного воркера; размеры и формат режем на приёме (лимит байтов, проверка магических байтов, пережатие/resize до маленькой картинки), а в спеку обязательно добавляем, как такие файлы попадают в бэкап, — иначе при восстановлении из дампа картинки просто исчезнут.

### N6 — Правая кнопка мыши (`contextmenu`) внутри VK iframe на десктопе

- Status: UNVERIFIED
- Fact: Документировано лишь, что на `vk.com` приложение работает в `iframe` (N1). Ни dev.vk.com, ни правила платформы ничего не говорят ни о доставке события `contextmenu` в документ iframe, ни о запрете его отменять (`preventDefault`). По стандарту веб-платформы событие доходит до документа внутри iframe и отменяет контекстное меню только внутри него — внешняя страница ВК его не получает; но официального подтверждения, что ВК не перехватывает правый клик и не накладывает свои элементы, нет. В репозиториях `VKCOM/vk-bridge` и документации упоминаний contextmenu/правого клика не найдено.
- Source: https://dev.vk.com/ru/mini-apps/development/iframe-webview (iframe на vk.com), https://dev.vk.com/ru/bridge/overview, https://dev.vk.com/ru/mini-apps-rules (поиск по тексту — ничего про контекстные меню)
- Spec impact: ПКМ/контекстные меню на карте остаются планируемой механикой, но перед спецификацией надо один раз проверить на живом ВК (чек-лист ниже); страховка в дизайне — продублировать ПКМ-действия видимой кнопкой/меню, как того требует хорошая практика.

### N7 — Какие URL статьи ВК игрок может вставить; сверка с `history_url_allowed_hosts`

- Status: CONFIRMED (форма `/@…`); UNVERIFIED (формы на `vk.ru` и `m.vk.com`)
- Fact: Официальная документация фиксирует адрес статьи как «страница с адресом, начинающимся с `https://vk.com/@`» (раздел «Публикации»: статья открывается внутри ВК по автоматически сформированному адресу `vk.com/@…`); справка редактора статей — «статья доступна по уникальной ссылке». Наш Spec уже жёстко требует путь `^/@[^/\s]+$` и хосты `vk.com`/`vk.ru` (`nation.history_url_allowed_hosts`), т.е. принимает `vk.com/@автор-статья` и `vk.ru/@автор-статья`. Задокументированные же зеркала: `m.vk.com` — официальный мобильный хост платформы (таблица платформ iframe/WebView), т.е. игрок с телефона может скопировать `m.vk.com/@…`, который сейчас отвергается; `vk.ru/@…` как форма статьи в документации не встречается (документирован канонический переезд домена в целом — факт F1 в `04_orders_vk_facts.md`), но работает как зеркало. Также не покрыты поддомены (`www.vk.com`) и служебные хосты (`vk.me` — диалоги, не статьи).
- Source: https://dev.vk.ru/ru/api/posts («адрес, начинающийся с `https://vk.com/@`»), https://vk.com/faq18196 («доступна по уникальной ссылке»), https://dev.vk.com/ru/mini-apps/development/iframe-webview (m.vk.com как платформа), configs/00_core.yaml (`history_url_allowed_hosts`, regex пути `/@…` — Spec 00_core п. 244), https://dev.vk.com/ru/mini-apps/getting-started («добавьте домен vk.ru в список доверенных сайтов»)
- Spec impact: текущие хосты оставляем (`vk.com`, `vk.ru` — обе формы валидны), а для «Регистрации 2.0» решаем отдельной правкой конфига (трек «А»): либо добавить `m.vk.com` в `history_url_allowed_hosts`, либо при приёме нормализовать `m.vk.com` → `vk.com`; валидатор пути `/@…` менять не нужно.

## Что Project Owner может проверить руками (без программиста)

1. **Правая кнопка мыши на карте (N6).** Откройте игру внутри ВКонтакте на компьютере → нажмите F12 (панель разработчика) → вкладка Console → вставьте строку `document.addEventListener('contextmenu', e => { e.preventDefault(); console.log('CONTEXT-OK') })` и нажмите Enter → кликните правой кнопкой по карте. Если в консоли появилось `CONTEXT-OK` и меню браузера НЕ открылось — ПКМ можно использовать для своих меню; если меню браузера открылось — ВК/браузер перехватывает, нужен запасной жест.
2. **Ссылка на статью с телефона (N7).** Откройте любую статью (например, из сообщества) в мобильном браузере на m.vk.com → скопируйте адрес → проверьте, что он начинается с `m.vk.com/@…`; затем в той же статье замените в адресе `m.vk.com` на `vk.com` и на `vk.ru` — обе должны открывать ту же статью.
3. **Альбом сообщества как галерея (N2).** В сообществе проекта: Управление → Разделы → включите «Фотографии» → создайте альбом, загрузите пару картинок → откройте фото и скопируйте ссылку на картинку (ПКМ → «Копировать адрес изображения») → откройте её в окне «инкогнито» (Ctrl+Shift+N) — если картинка открывается без входа в ВК, хотлинк работает; вернитесь к этой же ссылке через несколько дней — если открывается, URL живёт долго.
4. **Ссылка на трек (N4).** В разделе «Музыка» найдите трек → меню «…» → «Поделиться»/«Экспортировать» → «Прямая ссылка» → скопируйте и откройте в окне инкогнито и у второго тестового аккаунта — если трек открывается и играется всем, ссылку можно хранить у государства как «гимн-ссылку».
5. **Выбор файла внутри приложения (N1).** Откройте игру внутри ВК → F12 → Console → вставьте `var i=document.createElement('input'); i.type='file'; document.body.appendChild(i); i.click()` и Enter — если открылся системный диалог выбора файла, загрузка картинок внутри приложения работает.
