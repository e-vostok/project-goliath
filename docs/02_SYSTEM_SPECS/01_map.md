# 02_SYSTEM_SPECS / 01_map

> Терминология: «узел» Bible ⇔ строка таблицы `provinces` (поле `kind`: `LAND` — провинция суши, `SEA` — морская зона). «Провинция» в коде `00_core` по-прежнему означает строку этой таблицы; для суши используется `kind = LAND`.
> Пакеты и пути: бэкенд `backend/src/modules/_01_map/`, фронтенд `frontend/src/modules/01_map/`, конфиг `configs/01_map.yaml`, данные карты `data/map/`.

## ЧАСТЬ 1: ДОМЕННАЯ МОДЕЛЬ

### Таблицы БД

#### `provinces` (владелец `00_core`; расширение этой спецификацией)

| Поле        | Тип         | Ограничения                                                                     |
| ----------- | ----------- | ------------------------------------------------------------------------------- |
| `id`        | INTEGER     | PK, не UUID. Присваивается файлом `ids.lock.json`, не переиспользуется          |
| `nation_id` | UUID        | FK → `nations.id`, NULLABLE (`NULL` = свободна), без изменений                  |
| `kind`      | VARCHAR(4)  | NOT NULL, default `'LAND'`, `CHECK (kind IN ('LAND','SEA'))`                    |

Дополнительное ограничение `ck_provinces_sea_unowned`: `CHECK (kind = 'LAND' OR nation_id IS NULL)` — морская зона не может принадлежать государству (INV-M4). Изменение выполняется одной миграцией через `batch_alter_table` (чисто на SQLite и PostgreSQL).

Наполнение таблицы — не миграцией, а идемпотентной синхронизацией при старте (INV-M5, Часть 2). Плейсхолдеры `id = 1..100` из миграции 0001 удаляются миграцией этой спецификации при условии, что ни один из них не закреплён за государством; иначе миграция прерывается сообщением «сначала выполните сброс мира». Идентификаторы настоящих узлов начинаются с `1001`, чтобы не пересекаться со старыми тестовыми данными.

#### `map_ownership_log` (владелец `01_map`)

| Поле               | Тип           | Ограничения                                                            |
| ------------------ | ------------- | ---------------------------------------------------------------------- |
| `id`               | BIGINT        | PK, autoincrement (на SQLite — через `with_variant(Integer, "sqlite")`) |
| `province_id`      | INTEGER       | FK → `provinces.id`, NOT NULL                                          |
| `turn_number`      | BIGINT        | NOT NULL — `game_clock.current_turn` на момент смены                   |
| `prev_nation_id`   | UUID (String(36)) | NULLABLE, **без FK** (логическая ссылка; государство может быть удалено) |
| `new_nation_id`    | UUID (String(36)) | NULLABLE, без FK; `NULL` = провинция стала свободной               |
| `new_nation_name`  | VARCHAR(100)  | NULLABLE — название государства на момент события                      |
| `new_nation_color` | CHAR(7)       | NULLABLE — цвет государства на момент события                          |
| `created_at`       | TIMESTAMPTZ   | NOT NULL                                                               |

Ограничение `ck_log_new_nation_consistent`: три поля `new_nation_*` одновременно NULL или одновременно NOT NULL. Индексы: `(province_id, turn_number, id)`, `(turn_number)`. Таблица append-only: сервис не выполняет UPDATE и DELETE (исключение — хук сброса мира, Часть 2). Первичный ключ обязателен и проверяется защитным тестом расхождения моделей и миграций.

### Файловые данные карты (`data/map/`)

Это не баланс, а контент; они не лежат в `configs/`, но проходят такую же строгую проверку при старте (INV-M9). Размеры ограничены `limits.*` в конфиге.

| Файл                     | Кто пишет            | Содержимое                                                                                                    |
| ------------------------ | -------------------- | ------------------------------------------------------------------------------------------------------------- |
| `source/map.svg`         | зафиксирован         | исходный SVG MapChart (6,6 МБ), коммитится один раз, не редактируется                                          |
| `boundary.yaml`          | Project Owner        | утверждённый перечень провинций игрового поля (`include`) и явные исключения (`exclude_explicit`)              |
| `overrides.yaml`         | Project Owner        | морские «семена», проливы, ручные добавления/удаления связей, технические контуры, русские названия           |
| `ids.lock.json`          | инструмент дописывает | соответствие `key → id`; только добавление строк                                                              |
| `manifest.json`          | инструмент генерирует | узлы, связи, версия геометрии, геопривязка, хэши входных файлов                                                |
| `geometry.json`          | инструмент генерирует | контуры узлов и контур «земель за краем»                                                                      |

**`manifest.json`:**

```jsonc
{
  "schema_version": 1,
  "geometry_version": "a3f91c07be2d",          // первые 12 hex SHA-256 канонического geometry.json
  "view_box": [0, 0, 1200, 680],               // базовое пространство исходного SVG
  "playable_bbox": [x0, y0, x1, y1],           // рамка игрового поля в базовых единицах
  "georef": { "projection": "gall_stereographic", "x0": 562.53, "k": 3.339, "y0": 353.34, "m": 459.3 },
  "inputs_sha256": { "source": "…", "boundary": "…", "overrides": "…", "ids_lock": "…" },
  "nodes": [
    { "id": 1001, "key": "moscow", "kind": "LAND", "name": "Moscow", "name_ru": null,
      "source_name": "Moscow", "anchor": [690.3, 109.6], "bbox": [x0,y0,x1,y1], "area": 24.5 }
  ],
  "edges": [
    { "a": 1001, "b": 1002, "type": "land", "len": 3.4 },
    { "a": 1003, "b": 2001, "type": "coast", "len": 2.1 },
    { "a": 2001, "b": 2002, "type": "sea",  "len": 5.0 },
    { "a": 1010, "b": 1011, "type": "strait", "name": "Дувр", "multiplier": null }
  ]
}
```

Правила: `a < b` в каждой связи; пара `(a, b)` встречается один раз; типы связей — `land` (суша—суша), `coast` (суша—море), `sea` (море—море), `strait` (суша—суша через узкий пролив); `multiplier = null` означает `strait.default_crossing_multiplier` из конфига. `key` — латинский slug (`[a-z0-9_]+`), уникальный и неизменный; у морской зоны начинается с `sea_`. Отображаемое имя узла — `name_ru`, если задано, иначе `name` (название из источника с пробелами вместо подчёркиваний).

**`geometry.json`:** `{ "version": "<geometry_version>", "paths": { "<id>": "<SVG path d>" }, "outside": "<SVG path d>" }`. Координаты — в базовом пространстве, округлены до сотых. Контуры упрощены с сохранением общих границ (Приложение A).

**`overrides.yaml`:**

```yaml
sea_margin: 30                 # ширина морской полосы вдоль игровой суши, ед. SVG (1 ед. ≈ 23 км); дальше — «неизведанное море»
sea_margin_shape: square       # square — квадратная граница (расстояние по большей из осей); round — круглая
sea_margin_smooth: 10          # сглаживание мелких выемок границы полосы, ед. SVG (0 — без сглаживания)
lake_max_area: 70              # водоёмы (целиком) меньшей площади, кв. ед., — внутренняя вода (озёра): не узлы, фон
drop_parts:                    # обособленные куски игровых провинций внутри исключённой зоны (удаляются из геометрии)
  - { key: kemi_lappmark, point: [x, y] }
sea_zones:                     # морские зоны; границы рассчитываются от «семян» (одна или несколько точек на зону)
  - { key: sea_north, name_ru: "Северное море", seeds: [[x, y], [x, y]] }
  - { key: sea_old, name_ru: "Выведенная зона", seeds: [[x, y]], retired: true }   # 1.9: зона выведена из игры (необязательный ключ, по умолчанию false)
water_outside:                 # крупные водоёмы, сознательно не ставшие зонами (за краем поля): Красное, Персидский залив, Аральское
  - { name: "Аральское море", point: [x, y] }
straits:                       # узкие проливы между провинциями суши
  - { a: dover_key, b: calais_key, name: "Дувр", multiplier: null }
edges_add:    [ { a: key, b: key, type: sea } ]    # ручные связи (например, Босфор между морями)
edges_remove: [ { a: key, b: key } ]               # ложные автосвязи
technical_exclude: [ danish_sea ]                  # мусорные контуры исходника
keep_parts: [ ]                                    # сознательно сохраняемые обособленные куски: { key, point }
names_ru: { moscow: "Москва" }                     # русские названия; необязательны
geometry_patches:                                  # ручные поправки границ (1.9)
  - { transfer: { from: key_a, to: key_b, polygon: [[x, y], [x, y], [x, y]] } }   # часть провинции from внутри многоугольника переходит к to
sea_like_water:  [ [x, y] ]                        # точки внутри малых водоёмов, которые красятся цветом моря (1.9)
lake_force:      [ [x, y] ]                        # точки внутри водоёмов, которые остаются озёрами несмотря на правило (1.9)
sea_link_gap: 0.6                                  # водоём не больше lake_max_area на расстоянии не более этого (ед. SVG) от морской воды красится цветом моря (1.9)
```

Утверждённое содержимое секций `sea_margin*`, `drop_parts`, `sea_zones` (37 зон), `straits` (16), `water_outside`, `lake_max_area` и четырёх ручных морских связей `edges_add` (Гибралтар, Босфор, Дарданеллы, Керченский пролив) — хранится в `data/map/overrides.yaml`.

Другие модули не читают файлы `data/map/` и таблицу `map_ownership_log` напрямую.

## ЧАСТЬ 2: ИНВАРИАНТЫ, FSM И МЕСТО В TICK DAG

### Место в Tick DAG

`01_map` **не регистрирует обработчиков в `TickPhase`**. Смена владельцев провинций происходит в обработчиках других модулей (в основном в `PHASE_4_RESOLVE`) и в операциях `00_core`; запись журнала выполняется в той же транзакции по событию изменения владельца (INV-M7). Собственных расчётов в тике у модуля нет.

### Инварианты

| №      | Инвариант                                                                                                                                                              |
| ------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| INV-M1 | Идентификатор узла неизменен и не переиспользуется: `ids.lock.json` только пополняется. Удаление узла невозможно; выведенный из игры узел помечается в `overrides.yaml`. |

### Порядок запуска (дополнение к `lifespan` в `main.py`)

1. Загрузка и проверка `configs/01_map.yaml` (`MapConfig`).
2. Загрузка `manifest.json` и `geometry.json`, проверка схем, INV-M1…M3, M6, M10, лимитов.
3. `ProvinceService.ensure_nodes(...)` из `00_core`: добавляет отсутствующие строки и не изменяет существующие. Затем `ProvinceService.remove_retired(ids)` удаляет лишние строки выведенных из игры узлов (`id` из `ids.lock.json`, которых нет в `manifest.json`), если ими не владеет ни одно государство; если владеет — ошибка запуска с перечнем провинций и государств и указанием сначала удалить эти государства. Затем проверка INV-M5 (любая оставшаяся лишняя строка — ошибка).
4. Регистрация хуков: слушатель смены владельца, проверка регистрации (стартовая группа), хук сброса мира для журнала.
5. Обработчиков тика не регистрируется.

### Изменения `00_core` (Приложение B), используемые модулем

- **Реестр слушателей смены владельца.** `NationService` при создании государства (закрепление провинций) и при его удалении (освобождение) вызывает слушателей в той же транзакции, передавая список `OwnershipChange(province_id, prev_nation_id, new_nation_id, new_name, new_color, turn)`. `01_map` регистрирует слушателя, пишущего журнал.
- **Реестр проверок регистрации.** `NationService.create` после проверки существования и свободы провинций вызывает зарегистрированные проверки; `01_map` регистрирует проверку «только суша» и «связная группа». Так ядро не зависит от сателлита.
- **Хук сброса мира.** Админский сброс мира очищает `map_ownership_log` через зарегистрированный хук (по образцу `admin_hooks.py`).

## ЧАСТЬ 3: МАТЕМАТИЧЕСКИЙ АППАРАТ

Все длины — в базовых единицах исходного SVG (1 единица ≈ 0,3° долготы).

### 3.1 Сухопутная связь (инструмент подготовки)

Для валидных многоугольников $A$ и $B$ и допуска $\varepsilon$:

$$L(A,B)=\max\Big(\operatorname{len}\big(\partial A\cap \mathrm{buf}(B,\varepsilon)\big),\ \operatorname{len}\big(\partial B\cap \mathrm{buf}(A,\varepsilon)\big)\Big)$$

Связь существует, если $L(A,B)\ge L_{\min}$. Максимум обеспечивает симметрию. Значения по умолчанию, проверенные на 1 315 провинциях региона: $\varepsilon = 0{,}04$, $L_{\min}=0{,}3$ (3 413 связей, 20 изолированных узлов). Касание в одной точке даёт $L\approx 0$ и связью не является.

Связи `coast` и `sea` формулой выше не считаются: границы морских зон существуют только на растре (3.2), и векторный допуск $\varepsilon$ меньше размера пикселя. Для них длина контакта измеряется на растре: $L = h \cdot N$, где $N$ — число пар четырёхсвязных соседних пикселей, один из которых принадлежит морской зоне, а другой — провинции суши (`coast`) либо другой морской зоне (`sea`); $h = 1/r$. Связь существует, если $L \ge L_{\min}$. Пикселю суши метка провинции ставится по тому, в контур какой игровой провинции он попал; пиксели исключённой суши и удалённых кусков меток не имеют и связей не образуют.

### 3.2 Построение морских зон (инструмент подготовки)

1. Растр с шагом $h = 1/r$ единиц ($r = 4$ пикселя на единицу) над рамкой игрового поля с запасом $\ge$ `sea_margin` со всех сторон.
2. Вода $W$ = рамка минус объединение всех контуров суши исходника (включая исключённые провинции и без удалённых `drop_parts`-кусков игровых провинций, которые считаются исключённой сушей).
3. Морская полоса. Пусть $I$ — игровая суша (провинции из `boundary.yaml` без `drop_parts`), $m$ = `sea_margin`. Расстояние пикселя $p$ до $I$: при `square` — $d_\infty(p, I)=\min_{q\in I}\max(|p_x-q_x|,|p_y-q_y|)$, при `round` — евклидово. Полоса $B=\{p:\ d(p,I)\le m\}$; при `sea_margin_smooth` $=s>0$ полоса замыкается квадратным элементом со стороной $2s$ (расширение, затем сжатие), не уменьшая исходную $B$. Рабочая вода $W' = W\cap B$; остальная вода — «неизведанное море» (узлов не образует).
4. Многоисточниковый поиск в ширину по четырёхсвязным пикселям $W'$ от всех опорных точек всех зон: пиксель получает метку зоны, чья точка достигла его первой; при равенстве — зоны с меньшим порядковым номером. (1.9) Зона с `retired: true` участвует в поиске наравне с остальными, чтобы воды соседних зон не менялись, но после него исключается: не узел, не входит в граф и в `paths`, её вода становится «неизведанным морем» (входит в `outside`); её `id` остаётся в `ids.lock.json` (INV-M1) и обслуживается удалением выведенных узлов при запуске (INV-M5). Полностью выведенная зона не требует достижимых точек. Опорная точка вне $W'$ смещается на ближайший пиксель $W'$ в пределах 1 единицы, иначе — ошибка. Зона без единой достижимой точки — ошибка.
5. Водоёмы, не достигнутые ни одной точкой. Водоём — связная компонента воды $W$ целиком (до обрезки полосой); $A$ — её площадь. Если $A <$ `lake_max_area` — внутренняя вода (озеро): не узел, не суша, не входит в граф, на карте показывается фоном цвета `colors.inland_water`. Иначе, если водоём содержит точку из `water_outside`, — вода за краем поля (часть фона «неизведанного»). Иначе — ошибка `UNSEEDED_WATER` с перечнем площадей и координат. Водоём, часть которого лежит в полосе и достигнута точкой зоны, обрабатывается как зона (его остаток вне полосы — «неизведанное море»). Уточнения (1.3): водоём, не затрагивающий полосу, в расчёт не берётся (не узел, не озеро, фон «неизведанного моря»); кусок полосы внутри засеянного водоёма, которого не достигла ни одна точка (полоса разрезала водоём), — «неизведанное море», а при площади не меньше `lake_max_area` — ошибка `UNSEEDED_WATER`; точка `water_outside` должна лежать в воде незасеянного водоёма площадью не меньше `lake_max_area`, иначе — ошибка `WATER_OUTSIDE_INVALID`.

5а. (1.9) Внутренняя вода делится на два класса. Малый водоём ($A <$ `lake_max_area`) — **морской залив**, если расстояние от него до воды, принадлежащей зоне либо «неизведанному морю», не больше `sea_link_gap`, или если в нём лежит точка из `sea_like_water`; точка из `lake_force` делает его озером в любом случае. Остальные малые водоёмы — озёра. Заливы не становятся узлами и в граф не входят, красятся цветом `colors.sea`; озёра — цветом `colors.inland_water`. Отчёт инструмента перечисляет все малые водоёмы с площадью, классом и расстоянием до моря.
6. Растр меток зон сохраняется как промежуточный результат инструмента (вместе с рамкой и шагом растра). Векторизация меток в многоугольники, упрощение и обрезка по рамке выполняются на этапе геометрии (Приложение A, шаги 7–9), вместе с контурами суши.

Узкие места, не соединённые на растре (Гибралтар, Босфор, Дарданеллы, Керченский пролив), соединяются ручными связями `edges_add` типа `sea`.

### 3.3 Связность группы провинций

Для множества $S$ выбранных провинций суши:

$$E_S=\{(u,v)\in E:\ u,v\in S,\ \mathrm{type}(u,v)\in\{\text{land},\text{strait}\}\}$$

Группа связна, если поиск в ширину из любого $s_0\in S$ по $E_S$ посещает ровно $|S|$ узлов. Для $|S|=1$ — связна. Морские зоны и связи `coast`/`sea` в проверке не участвуют.

### 3.4 Достижимость

Поиск в ширину по всем связям из любого узла посещает ровно $|V|$ узлов.

### 3.5 Владелец провинции на ход $T$

Пусть $R_p$ — записи журнала провинции $p$, $t_r$ — их ходы, $id_r$ — идентификаторы:

$$owner(p,T)=\begin{cases} new(r^\*), & r^\*=\operatorname*{arg\,max}_{r\in R_p,\ t_r\le T}(t_r,\ id_r)\\ \text{свободна}, & \text{если } \{r\in R_p: t_r\le T\}=\varnothing\end{cases}$$

Для текущего хода владелец и данные государства берутся из живых таблиц `provinces` и `nations`; для прошлых ходов — из журнала (название и цвет на момент события).

### 3.6 Версия геометрии

$$v=\mathrm{hex}\big(\mathrm{SHA256}(\mathrm{canon}(G))\big)[0{:}12]$$

где $\mathrm{canon}$ — JSON с отсортированными ключами, разделителями `,` и `:` без пробелов, кодировка UTF-8, а $G=\{\texttt{"outside"}: \dots,\ \texttt{"paths"}: \dots,\ \texttt{"sea\_water"}: \dots\}$ — содержимое `geometry.json` без поля `version`. Сервер при проверке INV-M6 пересчитывает хэш по тому же правилу.

### 3.7 Геопривязка (используется инструментом и расширением v2)

Проекция исходной карты — стереографическая Галла. Для долготы $\lambda$ (градусы) и широты $\varphi$ (радианы):

$$x=x_0+k\,\lambda,\qquad y=y_0-m\tan\frac{\varphi}{2}$$

$x_0 = 562{,}53$, $k = 3{,}339$ ед./градус, $y_0 = 353{,}34$, $m = 459{,}3$. Параметры подобраны по 18 опорным городам, среднеквадратичное отклонение около 1,1 единицы; уточняются при подготовке рельефа и записываются в `manifest.georef`.

### 3.8 Вид и жесты (клиент)

Пусть $F=(f_x,f_y,f_w,f_h)$ — рамка `view.frame`, окно просмотра имеет размер $W_v\times H_v$ (CSS-пиксели), а $z\in[1,\text{zoom\_max}]$ — масштаб пользователя. (1.9) Минимальный масштаб определяется **только высотой**: $s_{min}=H_v/f_h$, текущий масштаб $s=s_{min}\,z$. При $z=1$ по высоте видна ровно вся рамка; в полноэкранном режиме окно выше и шире, поэтому $s_{min}$ растёт пропорционально высоте окна, а по ширине видно больше, чем ширина рамки. Точка экрана $c$ при смене $z\to z'$ остаётся на месте под курсором:

$$t'=c-(c-t)\frac{z'}{z}$$

Смещение $t$ ограничивается отступом $\mu=\text{pan\_margin\_fraction}$ по каждой оси отдельно: если видимая длина оси больше длины рамки на этой оси (например, ширина в полноэкранном режиме), карта по этой оси центрируется и не смещается; иначе $t_x\in[W_v-s(f_x+f_w)-\mu W_v,\ -s f_x+\mu W_v]$, аналогично $t_y$. Начальный вид: $z=1$, рамка по центру окна. При изменении размера окна (вход и выход из полного экрана) масштаб $z$ сохраняется, $s_{min}$ пересчитывается, смещение ограничивается заново. Верхний предел `zoom_max` отсчитывается от $s_{min}$.

### 3.9 Подписи

Подпись узла $i$ показывается, если $s\cdot w_i\ge \text{label\_min\_width\_px}$, где $w_i$ — ширина `bbox` узла в единицах.

### 3.10 Расписание обновления

Клиент запрашивает состояние в момент $t_f=\text{next\_tick\_at}+\text{tick\_refresh\_delay\_seconds}+U(0,\ \text{tick\_refresh\_jitter\_seconds})$, а также при открытии и при возврате в окно. Неудача: повтор через `retry_delay_seconds`, не более `max_retries` раз подряд; если после этого возраст последних данных больше `stale_after_seconds`, показывается пометка «данные устарели».

### 3.11 Проходимость пролива

$$mult(\text{strait})=\begin{cases}\text{multiplier}, & \text{если задан}\\ \text{strait.default\_crossing\_multiplier}, & \text{иначе}\end{cases}\in[0{,}05;\ 1]$$

Модуль карты только отдаёт значение; применяют его модули движения.

### 3.12 Поиск по названию

Нормализация: `casefold`, замена `ё → е`, удаление лишних пробелов. Совпадение — подстрока; результаты: сначала названия, начинающиеся с запроса, затем остальные, внутри групп — по возрастанию длины названия; не более `search_max_results`. Запрос короче `search_min_chars` не обрабатывается. Поиск выполняется на клиенте по `manifest.nodes` (по `name_ru` и `name`).

`GET /map/manifest` отдаёт содержимое `manifest.json` плюс правила интерфейса; поддерживает `ETag` (значение — хэш от `geometry_version`, хэша `manifest.json` и канонического JSON блока `rules`) и условный запрос `If-None-Match`. `GET /map/geometry/{version}` отдаёт геометрию с заголовком `Cache-Control: public, max-age=31536000, immutable`; версия, отличная от текущей, даёт 404 `MAP_VERSION_UNKNOWN` (клиент перезапрашивает manifest). `GET /map/state` без `turn` — текущий ход; с `turn` — прошлый ход по журналу; вне диапазона `0…current_turn` — 422 `TURN_OUT_OF_RANGE`.

### Клиентские компоненты (desktop, VKUI; тексты на русском; раскладка до ширины 1000 px)

- **`PanelMap`** — основной экран карты. Верхняя строка: поле поиска (`Search`) и кнопка «Развернуть» (видна при `big_window_enabled = true` и если браузер разрешает полноэкранный режим). Центр: `MapView`. Справа поверх карты — `NodeCard` (около 280 px, закрывается крестиком и клавишей Esc). Внизу: строка состояния «Ход N · обновлено ЧЧ:ММ» с пометкой «данные устарели» при необходимости; легенда цветов; строка авторства из `attribution`.
- **`MapView`** — единый компонент с режимами `view` и `select`. SVG со слоями снизу вверх: фон (цвет `colors.inland_water`: он виден в промежутках между провинциями на месте озёр); слой `sea_water` (1.9: заливы цвета `colors.sea`, лежат в «окнах» контура `outside`); контур `outside` (всё остальное, включая «неизведанное море»); заливки узлов (одна `<g>`, одно делегированное событие, узел определяется по `data-id`); подписи (по правилу 3.9); подсветка наведения и выбора. Границы провинций — обводка тонкой линией с `vector-effect: non-scaling-stroke`. Перемещение — перетаскиванием, масштаб — колесом (3.8); смещение и масштаб применяются одним `transform` на контейнер, обновление через `requestAnimationFrame`.
- **`NodeCard`** — название, вид, владелец (имя и цвет) или «свободна», список связанных узлов (клик переходит к узлу), место для данных модулей-сателлитов.
- **`ProvincePicker`** — всплывающее окно (`ModalPage`) с `MapView` в режиме `select`: клик по свободной провинции суши добавляет или убирает её из выбора; морские зоны и занятые провинции не выбираются; счётчик «Выбрано N из M»; индикатор связности; кнопка «Готово». Заменяет ручной ввод ID в окне 1 регистрации государства: поле выбранных провинций показывает названия и позволяет убирать их по одной; ввод чисел вручную удаляется.
- **Хуки:** `useMapManifest` (условный запрос по `ETag`), `useMapGeometry(version)` (кэш браузера, при `MAP_VERSION_UNKNOWN` перезапрос manifest), `useMapState` (политика 3.10; хранит последнее успешное состояние), `useMapSearch` (3.12), `useBigWindow` (состояние полного экрана и команды входа и выхода).
- **`vk-bridge`:** для карты события не требуются. Режим большого окна использует только средства браузера.

### Режим большого окна

Способ один, проверенный в настоящем ВК (эксперимент E1): полноэкранный режим **всей страницы** через `document.documentElement.requestFullscreen()`. Режим для отдельного блока не используется: всплывающие окна VKUI (выбор провинций, подтверждения) рисуются вне блока карты и в таком режиме были бы невидимы.

- **Вход:** кнопка «Развернуть» вызывает `requestFullscreen()` и работает только по клику игрока (требование браузера).
- **Состояние:** `useBigWindow` определяет полноэкранный режим только по событию `fullscreenchange` и значению `document.fullscreenElement`, а не по таймеру и не по результату вызова. Событие `fullscreenerror` и отклонённый вызов оставляют игрока в обычном виде с коротким сообщением.
- **Выход:** клавиша Esc (поведение браузера) и кнопка «Свернуть» в той же строке, что и «Развернуть»; кнопка меняет подпись по состоянию и доступна всегда.
- **Недоступность:** если `document.fullscreenEnabled` ложно, кнопка скрыта.
- **Ширина:** в полноэкранном режиме карта занимает всю ширину окна; раскладка не должна предполагать 1000 px (в обычном виде остаётся до 1000 px).

## ПРИЛОЖЕНИЕ A: КОНТРАКТ ПОДГОТОВКИ ДАННЫХ (для трека `map_pipeline`)

Инструмент `tools/map_pipeline/` (Python) детерминированно выпускает `ids.lock.json` (дополнение), `manifest.json` и `geometry.json` из `source/map.svg`, `boundary.yaml` и `overrides.yaml`. Свои параметры (допуски, шаг растра, упрощение) он берёт из собственной конфигурации; значения по умолчанию из этой спецификации: $\varepsilon=0{,}04$; $L_{\min}=0{,}3$; $r=4$; допуск упрощения 0,03 единицы.

Шаги: (1) разбор путей исходника: отбросить вложенный `<svg>` и преобразования масштаба и сдвига, заливки и штриховки, служебные дубли `id`; (2) замкнуть открытые контуры, починить самопересечения, удалить вырожденные отрезки длиной порядка 0,01; (3) оставить провинции из `boundary.yaml`, за вычетом `technical_exclude`; удалить из геометрии куски, перечисленные в `drop_parts` (кусок определяется точкой внутри него; точка вне любого куска провинции — ошибка); затем автоматически найти все обособленные куски игровых провинций, у которых в окружении 0,3 единицы есть только исключённые провинции, и остановить сборку с ошибкой `ISOLATED_PART` для каждого, не внесённого в `drop_parts` или в `keep_parts` (список таких кусков с точками, принятых сознательно); (4) присвоить `key` (slug от исходного имени; коллизия — ошибка) и `id` (из `ids.lock.json`, новые — следующие по порядку, начиная с 1001; морские зоны получают ключи `sea_*`); (5) построить морские зоны (3.2); (6) вычислить связи (`land` по 3.1; `coast` и `sea` по контакту на растре, 3.1), применить `edges_add`, `edges_remove`, `straits` (пролив между провинциями, уже имеющими сухопутную связь, — ошибка `STRAIT_ALREADY_CONNECTED`; `edges_add` на уже существующую пару — не ошибка, пара остаётся одна); (7) построить и упростить контуры: суша — каждый узел отдельно (допуск `min(simplify.tolerance, simplify.small_part_factor·√A)`, где $A$ — площадь куска, без самопересечений; общие границы соседей не гарантируются, см. изменения 1.4); моря — растр меток зон, расширенный в сушу на 2 пикселя, векторизуется в грани по общим рёбрам и упрощается единым покрытием (допуск `simplify.sea_tolerance`), затем зоны вычитаются из точного объединения итоговых (упрощённых) контуров игровой суши и сухопутной маски исключённой суши, чтобы море не перекрывало береговые кромки и острова; остатки воды (фьорды, узкие заливы) площадью до `sea_cut.fill_max_area`, примыкающие к зоне, присоединяются к ней; координаты округляются до сотых; (8) вычислить `anchor` (центр наибольшей вписанной окружности наибольшей части контура), `bbox`, `area` по итоговым контурам; (9) собрать контур `outside` = окно просмотра минус (замкнутое объединение всех узлов) минус внутренняя вода (озёра): озёра в `outside` не входят и остаются прозрачными промежутками над фоном (только озёра, примыкающие к игровой суше; озёра в исключённой земле остаются частью `outside`); (10) проверить INV-M2 и INV-M3, вывести отчёт (число узлов и связей, изолированные острова, узлы с аномальным числом соседей, провинции меньше порога, неразмещённые водоёмы) и картинку предпросмотра.

**Дополнение 1.9 к шагам.** (3а) После разбора путей и до назначения `key`: применить `geometry_patches` по порядку записи. Правка `transfer` вырезает из провинции `from` её часть внутри `polygon` и присоединяет эту часть к провинции `to`; обе провинции должны существовать, часть должна касаться `to`, остаток `from` не должен стать пустым или распасться на куски, не внесённые в `drop_parts`/`keep_parts`; сумма площадей `from` и `to` до и после совпадает с точностью округления; иначе — ошибка `PATCH_INVALID`. Правки не меняют `source/map.svg`. (9) Контур `outside` строится как раньше; водоёмы-заливы (3.2, шаг 5а), касающиеся хотя бы одного узла, выводятся отдельным составным путём `sea_water` и остаются «окнами» в `outside`; (1.10) залив или озеро, не касающееся ни одного узла, в `outside` не вырезается и в `sea_water` не попадает. Предпросмотр помечает залив и озёра разными цветами.

Инструмент не меняет исходные файлы и не пишет в БД.
