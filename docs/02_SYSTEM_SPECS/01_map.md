# 02_SYSTEM_SPECS / 01_map

> Терминология: «узел» Bible ⇔ строка таблицы `provinces` (поле `kind`: `LAND` — провинция суши, `SEA` — морская зона). «Провинция» в коде `00_core` по-прежнему означает строку этой таблицы; для суши используется `kind = LAND`.
> Пакеты и пути: бэкенд `backend/src/modules/_01_map/`, фронтенд `frontend/src/modules/01_map/`, конфиг `configs/01_map.yaml`, данные карты `data/map/`, инструмент подготовки `tools/map_pipeline/`.

## ЧАСТЬ 1: ДОМЕННАЯ МОДЕЛЬ

### Таблицы БД

#### `provinces` (владелец `00_core`; расширение этой спецификацией)

| Поле        | Тип         | Ограничения                                                                     |
| ----------- | ----------- | ------------------------------------------------------------------------------- |
| `id`        | INTEGER     | PK, не UUID. Присваивается файлом `ids.lock.json`, не переиспользуется          |
| `nation_id` | UUID        | FK → `nations.id`, NULLABLE (`NULL` = свободна), без изменений                  |
| `kind`      | VARCHAR(4)  | NOT NULL, default `'LAND'`, `CHECK (kind IN ('LAND','SEA'))`                    |

Дополнительное ограничение `ck_provinces_sea_unowned`: `CHECK (kind = 'LAND' OR nation_id IS NULL)` — морская зона не может принадлежать государству (INV-M4). Изменение выполнено одной миграцией через `batch_alter_table` (чисто на SQLite и PostgreSQL).

Наполнение таблицы — не миграцией, а идемпотентной синхронизацией при старте (INV-M5, Часть 2). Идентификаторы узлов начинаются с `1001`; переименованные узлы хранят прежний ключ в `ids.lock.json.previous_keys` (идентификатор не меняется).

#### `map_ownership_log` (владелец `01_map`)

| Поле               | Тип           | Ограничения                                                            |
| ------------------ | ------------- | ---------------------------------------------------------------------- |
| `id`               | BIGINT        | PK, autoincrement (на SQLite — через `with_variant(Integer, "sqlite")`) |
| `province_id`      | INTEGER       | FK → `provinces.id`, NOT NULL                                          |
| `turn_number`      | BIGINT        | NOT NULL — `game_clock.current_turn` на момент смены                   |
| `prev_nation_id`   | UUID (String(36)) | NULLABLE, **без FK** (логическая ссылка; государство может быть удалено) |
| `new_nation_id`    | UUID (String(36)) | NULLABLE, без FK; `NULL` = провинция стала свободной               |
| `new_nation_name`  | VARCHAR(100)  | NULLABLE — название государства на момент события                      |
| `new_nation_color` | CHAR(7)       | NULLABLE — цвет государства на момент события                          |
| `created_at`       | TIMESTAMPTZ   | NOT NULL                                                               |

Ограничение `ck_log_new_nation_consistent`: три поля `new_nation_*` одновременно NULL или одновременно NOT NULL. Индексы: `(province_id, turn_number, id)`, `(turn_number)`. Таблица append-only: сервис не выполняет UPDATE и DELETE (исключение — хук сброса мира, Часть 2). Первичный ключ обязателен и проверяется защитным тестом расхождения моделей и миграций.

Это не баланс, а контент; они не лежат в `configs/`, но проходят такую же строгую проверку при старте (INV-M9). Размеры ограничены `limits.*` в конфиге.

| ------------------------ | -------------------- | ------------------------------------------------------------------------------------------------------------- |

| `manifest.json`          | инструмент генерирует | узлы, связи, версии геометрии и границ, геопривязка, хэши входных файлов, опоры подписей                        |

| `preview/*.png`          | инструмент генерирует | картинки предпросмотра для глаз Project Owner                                                                  |

Файлы рельефа живут отдельно от `data/map/`: две WebP-картинки `frontend/public/assets/map/relief.{playable,inactive}.<hash>.webp` печёт `tools/map_pipeline/build_relief.py`, а указатель с прямоугольниками в базовых единицах лежит в `frontend/src/modules/01_map/relief/manifest.json` (коммитится вместе с картинками, имя файла содержит хэш содержимого).

**`manifest.json`** (фактические значения на момент версии 2.0: 1 067 узлов — 1 032 `LAND` и 35 `SEA`; 3 091 связь — 2 621 `land`, 382 `coast`, 43 `sea`, 45 `strait`):

```jsonc
  "geometry_version": "2c9fddf246c5",          // первые 12 hex SHA-256 канонического geometry.json (3.6)
  "borders_version": "c490386a482e",           // первые 12 hex SHA-256 канонического borders.json + geometry_version (3.6)
  "view_box": [0, 0, 1200, 680],               // базовое пространство исходного SVG
  "playable_bbox": [497.87, 0.21, 768.59, 263.97],  // рамка игрового поля в базовых единицах
  "georef": { "projection": "gall_stereographic", "x0": 562.53, "k": 3.339, "y0": 353.34, "m": 459.3 },
  "inputs_sha256": { "source": "…", "boundary": "…", "overrides": "…", "ids_lock": "…" },
  "nodes": [
    { "id": 1001, "key": "aargau", "kind": "LAND", "name": "Aargau", "name_ru": "Ааргау",
      "source_name": "Aargau", "anchor": [590.06, 152.55], "bbox": [588.66, 150.46, 591.29, 154.43], "area": 5.41,
      "label": { "x": 590.06, "y": 152.55, "w": 1.76, "h": 2.37,
                 "spine": [589.29, 154.23, 590.89, 151.45, 0.0], "len": 3.21, "thick": 0.42 } }
  ],
  "edges": [
    { "a": 1001, "b": 1002, "type": "land", "len": 3.4 },
    { "a": 1003, "b": 2001, "type": "coast", "len": 2.1 },
    { "a": 2001, "b": 2002, "type": "sea",  "len": 5.0 },

```

Правила: `a < b` в каждой связи; пара `(a, b)` встречается один раз; типы связей — `land` (суша—суша), `coast` (суша—море), `sea` (море—море), `strait` (суша—суша через узкий пролив); `multiplier = null` означает `strait.default_crossing_multiplier` из конфига (в файле ни у одного пролива явного множителя нет). `key` — латинский slug (`[a-z0-9_]+`), уникальный и неизменный; у морской зоны начинается с `sea_`. Отображаемое имя узла — `name_ru`, если задано, иначе `name` (название из источника с пробелами вместо подчёркиваний); все 1 067 узлов имеют `name_ru`. Поле `label` — опора подписи (3.9): `x`, `y` — опорная точка (полюс недоступности доминантной части или взвешенный центр островной группы), `w`, `h` — свободный бокс вокруг неё, `spine` — вписанная базовая линия `[x0, y0, x1, y1, s]` (концы и знаковая стрелка дуги), `len` — её длина, `thick` — локальная толщина территории поперёк неё.

**`geometry.json`:** `{ "version": "<geometry_version>", "paths": { "<id>": "<SVG path d>" }, "outside": "<SVG path d>", "sea_water": "<SVG path d>" }` (~2,7 МБ). Координаты — в базовом пространстве, на сетке 0,01 единицы. Контуры сглажены (Приложение A, шаг `smooth`), общие границы соседей совпадают вершина в вершину. `outside` — земли и «неизведанное море» за краем поля с окнами-озёрами и заливами; `sea_water` — составной путь малых водоёмов-заливов, красящихся цветом моря (может быть пустой строкой).

**`borders.json`:** `{ "version": "<borders_version>", "pairs": { "<a>-<b>": "<SVG path d>" }, "coasts": { "<id>": "<SVG path d>" } }` (~1,3 МБ; 2 621 пара и 1 032 береговые линии — только сухопутные: пар и берегов морских узлов в файле нет). `pairs` — каноническая линия общей границы для каждой связи `land` (включая пары `land_links`), `coasts` — береговая линия каждой провинции суши (пустая строка у полностью сухопутной). Клиент рисует по ним тонкие внутренние границы, границы государств и линии берега, не вычисляя общие границы сам.

**`ids.lock.json`:** `{ "version": 1, "ids": { "<key>": <id> }, "previous_keys": { "<key>": ["<old_key>"] } }`. Только пополняется (INV-M1): на момент версии 2.0 — 1 125 записей, из них 58 — выведенные из игры `id` (исключённые провинции и две морские зоны), старший номер 2125. `previous_keys` фиксирует переименования ключей (`renames` в `overrides.yaml`): `balearic_islands ← mallorca`, `cyclades ← naxos`, `dodecanese ← rodos`, `shetland_islands ← northern_isles`.

### Объект времени выполнения

`MapData` — неизменяемый объект в памяти сервера, строится при старте из `manifest.json`, `geometry.json` и `borders.json`: словарь узлов по `id`, словарь связей и списки смежности, отсортированные по `id`. Публичный сервис `modules/_01_map/service.py` — единственный интерфейс для других модулей:

| Метод                                       | Назначение                                                                          |
| ------------------------------------------- | ----------------------------------------------------------------------------------- |
| `neighbors(node_id, types=None)`            | соседи узла, при необходимости только заданных типов связей                         |
| `edge(a, b)`                                | связь между двумя узлами или `None`                                                 |
| `strait_multiplier(a, b)`                   | итоговый множитель проходимости пролива (явный или `strait.default_crossing_multiplier`) |
| `group_components(node_ids)`                | компоненты связности группы по правилу 3.3                                          |
| `is_group_connected(node_ids)`              | связность группы по правилу Bible §3                                                |
| `shortest_path(a, b, cost_fn)`              | алгоритм Дейкстры; стоимость ребра задаёт вызывающий модуль                         |
| `get_node(node_id)`, `get_node_by_key(key)` | данные узла                                                                         |
| `all_nodes(kind=None)`                      | все узлы, при необходимости одного вида                                             |
| `geometry_version`, `borders_version`       | версии загруженных файлов                                                           |

Другие модули не читают файлы `data/map/` и таблицу `map_ownership_log` напрямую.

## ЧАСТЬ 2: ИНВАРИАНТЫ, FSM И МЕСТО В TICK DAG

### Место в Tick DAG

`01_map` **не регистрирует обработчиков в `TickPhase`**. Смена владельцев провинций происходит в обработчиках других модулей (в основном в `PHASE_4_RESOLVE`) и в операциях `00_core`; запись журнала выполняется в той же транзакции по событию изменения владельца (INV-M7). Собственных расчётов в тике у модуля нет.

### Инварианты

| №      | Инвариант                                                                                                                                                              |
| ------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| INV-M1 | Идентификатор узла неизменен и не переиспользуется: `ids.lock.json` только пополняется, переименование ключа сохраняет `id` и оставляет след в `previous_keys`. Удаление узла невозможно; выведенный из игры узел помечается в `overrides.yaml` (провинция — переносом в `exclude_explicit`, морская зона — `retired: true`). |
| INV-M2 | Граф симметричен и без петель: пара `(a, b)` с `a < b` встречается ровно один раз; оба конца существуют; типы допустимы для видов концов (`land`: LAND–LAND, `coast`: LAND–SEA, `sea`: SEA–SEA, `strait`: LAND–LAND). |
| INV-M3 | Достижимость: из любого узла по всем связям достижим любой другой.                                                                                                      |
| INV-M4 | Морская зона не принадлежит государству: ограничение БД `ck_provinces_sea_unowned` и проверка в `00_core`.                                                              |
| INV-M5 | Соответствие БД и карты: после синхронизации множество `id` таблицы `provinces` равно множеству `id` в `manifest.json`; `kind` совпадает. Лишняя строка в БД — ошибка запуска, кроме строки выведенного из игры узла: её `id` есть в `ids.lock.json`, но нет в `manifest.json`, и ею не владеет государство — такая строка удаляется при синхронизации (`ProvinceService.remove_retired`). |
| INV-M6 | Согласованность версий: `manifest.geometry_version` равен хэшу `geometry.json`, `manifest.borders_version` — хэшу `borders.json` вместе с версией геометрии (3.6), а ответ `/map/state` содержит обе версии. |
| INV-M7 | Запись журнала и смена владельца провинции происходят в одной транзакции; запись добавляется для каждой смены. Журнал не изменяется задним числом.                      |
| INV-M8 | При `starting_group.require_connected = true` регистрация государства отклоняется, если группа выбранных провинций не связна (сервер — единственный источник истины).    |
| INV-M9 | Отказ при старте: нарушение любого из INV-M1…M6, превышение `limits.*`, отсутствие файла — сервер не запускается и сообщает причину.                                    |
| INV-M10 | Хэши входов в `manifest.inputs_sha256` совпадают с фактическими хэшами файлов `source`, `boundary`, `overrides`, `ids.lock`. Расхождение — признак, что инструмент подготовки не перезапущен после правки входных данных. |

### Порядок запуска (дополнение к `lifespan` в `main.py`)

1. Загрузка и проверка `configs/01_map.yaml` (`MapConfig`).
2. Загрузка `manifest.json`, `geometry.json`, `borders.json` и `ids.lock.json`, проверка схем, размеров `limits.*` (включая `max_borders_bytes`), рамки `view.frame` внутри `view_box`, INV-M1…M3, M6, M10, лимитов графа.
3. `ProvinceService.ensure_nodes(...)` из `00_core`: добавляет отсутствующие строки и не изменяет существующие. Затем `ProvinceService.remove_retired(ids)` удаляет лишние строки выведенных из игры узлов (`id` из `ids.lock.json`, которых нет в `manifest.json`), если ими не владеет ни одно государство; если владеет — ошибка запуска с перечнем провинций и государств и указанием сначала удалить эти государства. Затем проверка INV-M5 (любая оставшаяся лишняя строка — ошибка).
4. Регистрация хуков: слушатель смены владельца, проверка регистрации (стартовая группа), хук сброса мира для журнала. Сборка готовых ответов API (тело manifest, геометрии и границ, `ETag`) — до первого запроса.
5. Обработчиков тика не регистрируется.

### Изменения `00_core` (Приложение B), используемые модулем

- **Реестр слушателей смены владельца.** `NationService` при создании государства (закрепление провинций) и при его удалении (освобождение) вызывает слушателей в той же транзакции, передавая список `OwnershipChange(province_id, prev_nation_id, new_nation_id, new_name, new_color, turn)`. `01_map` регистрирует слушателя, пишущего журнал.
- **Реестр проверок регистрации.** `NationService.create` после проверки существования и свободы провинций вызывает зарегистрированные проверки; `01_map` регистрирует проверку «только суша» и «связная группа». Так ядро не зависит от сателлита.
- **Хук сброса мира.** Админский сброс мира очищает `map_ownership_log` через зарегистрированный хук (по образцу `admin_hooks.py`).

## ЧАСТЬ 3: МАТЕМАТИЧЕСКИЙ АППАРАТ

Все длины — в базовых единицах исходного SVG (1 единица ≈ 0,3° долготы).

### 3.1 Сухопутная связь (инструмент подготовки)

Для валидных многоугольников $A$ и $B$ и допуска $\varepsilon$:

$$L(A,B)=\max\Big(\operatorname{len}\big(\partial A\cap \mathrm{buf}(B,\varepsilon)\big),\ \operatorname{len}\big(\partial B\cap \mathrm{buf}(A,\varepsilon)\big)\Big)$$

Связь существует, если $L(A,B)\ge L_{\min}$. Максимум обеспечивает симметрию. Значения, проверенные на реальных данных: $\varepsilon = 0{,}04$, $L_{\min}=0{,}3$. Касание в одной точке даёт $L\approx 0$ и связью не является. Три пары, которым автоматика связи не нашла, добавлены принудительно списком `land_links` (Дехейбарт—Поуис, Понтье—Западная Фландрия, Данциг—Нижняя Пруссия); такие пары получают и каноническую линию в `borders.json`.

Связи `coast` и `sea` формулой выше не считаются: границы морских зон существуют только на растре (3.2), и векторный допуск $\varepsilon$ меньше размера пикселя. Для них длина контакта измеряется на растре: $L = h \cdot N$, где $N$ — число пар четырёхсвязных соседних пикселей, один из которых принадлежит морской зоне, а другой — провинции суши (`coast`) либо другой морской зоне (`sea`); $h = 1/r$. Связь существует, если $L \ge L_{\min}$. Пикселю суши метка провинции ставится по тому, в контур какой игровой провинции он попал; пиксели исключённой суши и удалённых кусков меток не имеют и связей не образуют.

### 3.2 Построение морских зон (инструмент подготовки)

1. Растр с шагом $h = 1/r$ единиц ($r = 4$ пикселя на единицу) над рамкой игрового поля с запасом $\ge$ `sea_margin` со всех сторон.
2. Вода $W$ = рамка минус объединение всех контуров суши исходника (включая исключённые провинции и без удалённых `drop_parts`-кусков игровых провинций, которые считаются исключённой сушей).
3. Морская полоса. Пусть $I$ — игровая суша (провинции из `boundary.yaml` без `drop_parts`), $m$ = `sea_margin`. Расстояние пикселя $p$ до $I$: при `square` — $d_\infty(p, I)=\min_{q\in I}\max(|p_x-q_x|,|p_y-q_y|)$, при `round` — евклидово. Полоса $B=\{p:\ d(p,I)\le m\}$; при `sea_margin_smooth` $=s>0$ полоса замыкается квадратным элементом со стороной $2s$ (расширение, затем сжатие), не уменьшая исходную $B$. Рабочая вода $W' = W\cap B$; остальная вода — «неизведанное море» (узлов не образует).
4. Многоисточниковый поиск в ширину по четырёхсвязным пикселям $W'$ от всех опорных точек всех зон: пиксель получает метку зоны, чья точка достигла его первой; при равенстве — зоны с меньшим порядковым номером. Зона с `retired: true` участвует в поиске наравне с остальными, чтобы воды соседних зон не менялись, но после него исключается: не узел, не входит в граф и в `paths`, её вода становится «неизведанным морем» (входит в `outside`); её `id` остаётся в `ids.lock.json` (INV-M1) и обслуживается удалением выведенных узлов при запуске (INV-M5). Полностью выведенная зона не требует достижимых точек. Опорная точка вне $W'$ смещается на ближайший пиксель $W'$ в пределах `sea.seed_snap_radius` единицы, иначе — ошибка. Зона без единой достижимой точки — ошибка.
5. Водоёмы, не достигнутые ни одной точкой. Водоём — связная компонента воды $W$ целиком (до обрезки полосой); $A$ — её площадь. Если $A <$ `lake_max_area` — внутренняя вода (озеро): не узел, не суша, не входит в граф, на карте показывается фоном. Иначе, если водоём содержит точку из `water_outside`, — вода за краем поля (часть фона «неизведанного»). Иначе — ошибка `UNSEEDED_WATER` с перечнем площадей и координат. Водоём, часть которого лежит в полосе и достигнута точкой зоны, обрабатывается как зона (его остаток вне полосы — «неизведанное море»). Уточнения: водоём, не затрагивающий полосу, в расчёт не берётся (не узел, не озеро, фон «неизведанного моря»); кусок полосы внутри засеянного водоёма, которого не достигла ни одна точка (полоса разрезала водоём), — «неизведанное море», а при площади не меньше `lake_max_area` — ошибка `UNSEEDED_WATER`; точка `water_outside` должна лежать в воде незасеянного водоёма площадью не меньше `lake_max_area`, иначе — ошибка `WATER_OUTSIDE_INVALID`.
5а. Внутренняя вода делится на два класса. Малый водоём ($A <$ `lake_max_area`) — **морской залив**, если расстояние от него до воды, принадлежащей зоне либо «неизведанному морю», не больше `sea_link_gap`, или если в нём лежит точка из `sea_like_water`; точка из `lake_force` делает его озером в любом случае. Остальные малые водоёмы — озёра. Заливы не становятся узлами и в граф не входят, красятся цветом `colors.sea`; озёра — цветом `colors.inland_water` (в текущей палитре эти два цвета совпадают — вся вода одинакова). Отчёт инструмента перечисляет все малые водоёмы с площадью, классом и расстоянием до моря.
6. Растр меток зон сохраняется как промежуточный результат инструмента (вместе с рамкой и шагом растра). Векторизация меток в многоугольники, упрощение и обрезка по рамке выполняются на этапе геометрии (Приложение A, шаги 8–10), вместе с контурами суши.

Узкие места, не соединённые на растре (Гибралтар, Босфор, Дарданеллы, Керченский пролив), соединяются четырьмя ручными связями `edges_add` типа `sea`.

### 3.3 Связность группы провинций

Для множества $S$ выбранных провинций суши:

$$E_S=\{(u,v)\in E:\ u,v\in S,\ \mathrm{type}(u,v)\in\{\text{land},\text{strait}\}\}$$

Группа связна, если поиск в ширину из любого $s_0\in S$ по $E_S$ посещает ровно $|S|$ узлов. Для $|S|=1$ — связна. Морские зоны и связи `coast`/`sea` в проверке не участвуют.

### 3.4 Достижимость

Поиск в ширину по всем связям из любого узла посещает ровно $|V|$ узлов.

### 3.5 Владелец провинции на ход $T$

Пусть $R_p$ — записи журнала провинции $p$, $t_r$ — их ходы, $id_r$ — идентификаторы:

$$owner(p,T)=\begin{cases} new(r^\*), & r^\*=\operatorname*{arg\,max}_{r\in R_p,\ t_r\le T}(t_r,\ id_r)\\ \text{свободна}, & \text{если } \{r\in R_p: t_r\le T\}=\varnothing\end{cases}$$

Для текущего хода владелец и данные государства берутся из живых таблиц `provinces` и `nations`; для прошлых ходов — из журнала (название и цвет на момент события).

### 3.6 Версии геометрии и границ

$$v_{geom}=\mathrm{hex}\big(\mathrm{SHA256}(\mathrm{canon}(G))\big)[0{:}12]$$

где $\mathrm{canon}$ — JSON с отсортированными ключами, разделителями `,` и `:` без пробелов, кодировка UTF-8, а $G=\{\texttt{"outside"}: \dots,\ \texttt{"paths"}: \dots,\ \texttt{"sea\_water"}: \dots\}$ — содержимое `geometry.json` без поля `version`. Аналогично версия границ считается по `borders.json` (без поля `version`) плюс `geometry_version` — границы переиздаются всякий раз, когда меняется геометрия. Сервер при проверке INV-M6 пересчитывает оба хэша по тому же правилу.

### 3.7 Геопривязка (используется инструментом и слоем рельефа)

Проекция исходной карты — стереографическая Галла. Для долготы $\lambda$ (градусы) и широты $\varphi$ (радианы):

$$x=x_0+k\,\lambda,\qquad y=y_0-m\tan\frac{\varphi}{2}$$

$x_0 = 562{,}53$, $k = 3{,}339$ ед./градус, $y_0 = 353{,}34$, $m = 459{,}3$. Параметры подобраны по опорным городам; записываются в `manifest.georef`. По ним же регистрируются картинки рельефа: весь земной шар в проекции Галла покрывается конечным прямоугольником базовых единиц.

### 3.8 Вид и жесты (клиент)

Пусть $F=(f_x,f_y,f_w,f_h)$ — рамка `view.frame`, окно просмотра имеет размер $W_v\times H_v$ (CSS-пиксели), а $z\in[1,\text{zoom\_max}]$ — масштаб пользователя. Минимальный масштаб определяется **только высотой**: $s_{min}=H_v/f_h$, текущий масштаб $s=s_{min}\,z$. При $z=1$ по высоте видна ровно вся рамка; в полноэкранном режиме окно выше и шире, поэтому $s_{min}$ растёт пропорционально высоте окна, а по ширине видно больше, чем ширина рамки. Точка экрана $c$ при смене $z\to z'$ остаётся на месте под курсором:

$$t'=c-(c-t)\frac{z'}{z}$$

Смещение $t$ ограничивается отступом $\mu=\text{pan\_margin\_fraction}$ по каждой оси отдельно: если видимая длина оси больше длины рамки на этой оси (например, ширина в полноэкранном режиме), карта по этой оси центрируется и не смещается; иначе $t_x\in[W_v-s(f_x+f_w)-\mu W_v,\ -s f_x+\mu W_v]$, аналогично $t_y$. При `pan_margin_fraction = 0` (текущее значение) карту нельзя вытянуть за рамку поля. Начальный вид: $z=1$, рамка по центру окна. При изменении размера окна (вход и выход из полного экрана) масштаб $z$ сохраняется, $s_{min}$ пересчитывается, смещение ограничивается заново. Верхний предел `zoom_max` отсчитывается от $s_{min}$.

**Живое перетаскивание.** Масштаб и смещение хранятся вне состояния React. Каждый кадр жеста пишет текущий `transform` в атрибут единственного мирового `<g>` через `requestAnimationFrame`: карта перерисовывается по-настоящему на каждом кадре — без растрового снимка, без скрытия слоёв и без коммитов React во время жеста. Зависящие от масштаба наборы (подписи, уровень детализации границ, режим штриха закрытия швов) переключаются императивными записями атрибутов, а набор подписей пересчитывается только после остановки жеста (3.9). Клик отличается от перетаскивания порогом 4 px.

### 3.9 Подписи узлов и названия государств

**Подписи узлов.** У каждого узла есть опора `label` из манифеста (Часть 1). Название рисуется вдоль «спины» `spine` — вписанной прямой или пологой дуги: размер шрифта не выше `labels.thickness_ratio × thick` и в пределах `labels.land_min_px…land_max_px` (морские зоны — `sea_min_px…sea_max_px`); разрежение букв в `labels.letter_spacing_min_em…letter_spacing_max_em` подгоняет длину к `labels.length_ratio × len`; изгиб уже учтён дугой (не больше `labels.max_bend` от хорды). Если по спине ничего не помещается — запасной вариант: горизонтальная подпись в одну-две строки (разрыв по пробелу или дефису), вписанная в `labels.fit_ratio` бокса `w × h`. Столкновения разрешаются по приоритету площади узла (при равной — суша раньше моря) пространственной сеткой на экране с отступом `labels.collision_padding_px`; проигравший скрыт. Раскладка зависит только от узлов и масштаба, поэтому перетаскивание её не пересчитывает.

**Правило зума.** Имена провинций существуют только на максимальном зуме ($s \ge \text{labels.province\_zoom\_ratio}\times s_{max}$), имена морских зон — только ниже порога; при пересечении порога группы кроссфейдятся за `labels.fade_ms` (0 — без перехода; `prefers-reduced-motion` тоже 0). Отрисованный набор держится «окном»: элементы `<text>` создаются для подписей, чей бокс пересекает вьюпорт, расширенный на полэкрана (не более 600 за раз, пересборка не чаще 100 мс); на максимальном зуме подпись видна, если не меньше половины рамки провинции в вьюпорте или её опорная точка внутри вьюпорта, сжатого на 10 % с каждой стороны. Подписи суши имеют прозрачность `labels.land_opacity`, морские — `labels.sea_opacity` (на весь элемент вместе с обводом); обвод `labels.halo_width_px` цветом `labels.halo_color` по правилу `paint-order: stroke`. Шрифты — из встроенного реестра (`labels.font`, `labels.sea_font`, Часть 5).

**Названия государств.** Для каждого государства по растровой маске его территории (256 ячеек по длинной стороне) ищется строка наибольшей «свободная длина × локальная толщина»: угол в пределах ±`states.max_angle_deg` (грубый шаг 10°, уточнение 3°), смещения по сетке; каждая хорда дополнительно пробуется как дуга с сагиттой до `states.max_bend` от длины хорды. Высота надписи не больше `states.thickness_ratio` толщины, длина — `states.length_ratio` свободной длины; разрежение букв добирает до `states.max_letter_spacing_em`, длинное имя уменьшает шрифт; бокс обязан лежать внутри территории не менее чем на 97 %. Экранный размер зажат в `states.min_px…states.max_px`, ниже порога надпись скрыта. Государство из нескольких связных частей получает надпись для каждой части площадью не меньше `states.min_group_share` общей (наибольшая — всегда). Цвет — `states.color_mode`: `auto` выбирает светлый или тёмный по контрасту с цветом государства. Надпись рисуется по `<textPath>` повёрнутой или слегка изогнутой, ЗАГЛАВНЫМИ при `states.uppercase`, с прозрачностью `states.opacity`; на максимальном зуме весь слой кроссфейдится с именами провинций (тот же порог и `labels.fade_ms`). Позиции кэшируются по сигнатуре государства — смена владельца пересчитывает только затронутое государство.

### 3.10 Расписание обновления

Клиент запрашивает состояние в момент $t_f=\text{next\_tick\_at}+\text{tick\_refresh\_delay\_seconds}+U(0,\ \text{tick\_refresh\_jitter\_seconds})$, а также при открытии и при возврате в окно. Неудача: повтор через `retry_delay_seconds`, не более `max_retries` раз подряд; если после этого возраст последних данных больше `stale_after_seconds`, показывается пометка «данные устарели».

### 3.11 Проходимость пролива

$$mult(\text{strait})=\begin{cases}\text{multiplier}, & \text{если задан}\\ \text{strait.default\_crossing\_multiplier}, & \text{иначе}\end{cases}\in[0{,}05;\ 1]$$

Модуль карты только отдаёт значение; применяют его модули движения.

### 3.12 Поиск по названию

Нормализация: `casefold`, замена `ё → е`, удаление лишних пробелов. Совпадение — подстрока; результаты: сначала названия, начинающиеся с запроса, затем остальные, внутри групп — по возрастанию длины названия; не более `search_max_results`. Запрос короче `search_min_chars` не обрабатывается. Поиск выполняется на клиенте по `manifest.nodes` (по `name_ru` и `name`).

### FastAPI эндпоинты

Все эндпоинты требуют Bearer. Префикс `/api/v1`.

| Метод | Путь | Request | Response | Код |
| --- | --- | --- | --- | --- |
| GET | `/map/manifest` | — | `MapManifestDTO` | 200 / 304 |
| GET | `/map/geometry/{version}` | — | `MapGeometryDTO` | 200 / 404 |
| GET | `/map/borders/{version}` | — | `MapBordersDTO` | 200 / 404 |
| GET | `/map/state` | `?turn=` | `MapStateDTO` | 200 / 422 |
| POST | `/map/starting-group/check` | `StartingGroupCheckRequest` | `StartingGroupCheckResponse` | 200 / 404 |

`GET /map/manifest` отдаёт содержимое `manifest.json` плюс правила интерфейса; поддерживает `ETag` (значение — хэш от `geometry_version`, хэша `manifest.json` и канонического JSON блока `rules`, поэтому правка конфига меняет `ETag`) и условный запрос `If-None-Match` (слабое сравнение RFC 9110); заголовок `Cache-Control: no-cache`. `GET /map/geometry/{version}` и `GET /map/borders/{version}` отдают геометрию и границы с заголовком `Cache-Control: public, max-age=31536000, immutable` и `ETag`, равным версии; версия, отличная от текущей, даёт 404 `MAP_VERSION_UNKNOWN` (клиент перезапрашивает manifest). Тела manifest, геометрии и границ собираются один раз при старте и отдаются готовыми байтами. `GET /map/state` без `turn` — текущий ход; с `turn` — прошлый ход по журналу; вне диапазона `0…current_turn` — 422 `TURN_OUT_OF_RANGE`. Выведенные из игры узлы в ответе `state` не появляются.

### Клиентские компоненты (desktop, VKUI; тексты на русском; раскладка до ширины 1000 px)

- **`PanelMap`** — основной экран карты; занимает всю область приложения (`position: fixed`), в полноэкранном режиме — весь монитор. Верхняя строка: поле поиска (`Search` с выпадающим списком и клавиатурной навигацией), кнопка «Развернуть на весь экран» / «Свернуть» (видна при `big_window_enabled = true` и если браузер разрешает полноэкранный режим), кнопка «Назад» (скрыта в полном экране). Центр: `MapView`. Справа поверх карты — `NodeCard` (около 280 px, закрывается крестиком и клавишей Esc — список поиска закрывается Esc первым). Внизу: строка состояния «Ход N · обновлено ЧЧ:ММ» (время московское) с пометкой «данные устарели» при необходимости; легенда цветов (пункт «Озёра» скрывается, когда `inland_water` совпадает с `sea`); строка авторства из `attribution`.
- **`MapView`** — единый компонент с режимами `view` и `select`. Слои снизу вверх: фоновый прямоугольник `colors.inland_water` (цвет воды виден в окнах-озёрах контура `outside`); составной путь `sea_water` (заливы цвета `colors.sea`); контур `outside` (`colors.outside`, при включённом рельефе — `colors.sea`: неигровую сушу рисует картинка мира); картинка `relief.inactive` (тёмный рельеф всего мира, лениво загружается); картинка `relief.playable` (игровой рельеф); заливки узлов (сначала SEA, затем LAND одной группой `<g>` с одним делегированным событием, узел определяется по `data-id`; группа суши несёт штрих `colors.land_underlay` закрытия швов); копия `relief.playable` в режиме `mix-blend-mode: multiply` с прозрачностью `relief.strength_playable` над заливками; слой границ из `borders.json`; надписи государств; подписи узлов; оверлеи выбора и наведения (копии контура узла, а не перестилизация заливок).
  - **Слой границ:** три класса из `borders.json` — `internal` (сплошная тонкая линия внутри одного владельца или между свободными), `state` (сплошная линия границы государства, только по суше), `coast` (тонкая линия берега у каждой провинции суши); ширины — экранные px (`non-scaling`). Пар и берегов морских узлов нет: море остаётся ровным. Слой разбит на пространственную сетку 8×8 ячеек (браузер отбрасывает ячейки вне экрана) и хранит три уровня детализации (упрощения Douglas–Peucker с ошибкой меньше полупикселя на пороге переключения); смена владения пересобирает только ячейки с изменившимися парами. Запасной вариант при неудачной загрузке `borders.json` — прежняя обводка каждого узла цветом `colors.province_border`.
  - **Закрытие швов:** волосяные зазоры между заливками соседей перекрываются унаследованным штрихом `colors.land_underlay` на группе заливок суши — мировой ширины 0,05 ед. на большом зуме, экранный тонкий штрих на среднем, выключен на малом (зазор не достигает пикселя).
  - **Живое перетаскивание** по 3.8: жест пишет `transform` в мировой `<g>` каждый кадр анимации; подписи, границы, выбор и наведение видны всегда; пульсация выбора приостанавливается на время жеста; набор подписей пересчитывается на остановке.
  - **Наведение и выбор:** заливка `colors.hover` копией контура — при наведении с прозрачностью `hover.fill_opacity` (обводка при `hover.stroke_enabled`), у осматриваемой провинции — пульсация `selection.pulse_*` (при `prefers-reduced-motion` зафиксирована посередине), у отобранных в пикере — постоянная `selection.picked_opacity`. Перемещение — перетаскиванием, масштаб — колесом (обработчик непассивный, единственный источник зума).
- **`NodeCard`** — название, вид, владелец (имя и цвет) или «свободна», список связанных узлов (клик переходит к узлу), место для данных модулей-сателлитов.

### Режим большого окна

Способ один, проверенный в настоящем ВК (эксперимент E1): полноэкранный режим **всей страницы** через `document.documentElement.requestFullscreen()`. Режим для отдельного блока не используется: всплывающие окна VKUI (выбор провинций, подтверждения) рисуются вне блока карты и в таком режиме были бы невидимы.

- **Вход:** кнопка «Развернуть» вызывает `requestFullscreen()` и работает только по клику игрока (требование браузера).
- **Состояние:** `useBigWindow` определяет полноэкранный режим только по событию `fullscreenchange` и значению `document.fullscreenElement`, а не по таймеру и не по результату вызова. Событие `fullscreenerror` и отклонённый вызов оставляют игрока в обычном виде с коротким сообщением.
- **Выход:** клавиша Esc (поведение браузера) и кнопка «Свернуть» в той же строке, что и «Развернуть»; кнопка меняет подпись по состоянию и доступна всегда.
- **Недоступность:** если `document.fullscreenEnabled` ложно, кнопка скрыта.
- **Ширина:** в полноэкранном режиме карта занимает всю ширину окна; раскладка не должна предполагать 1000 px (в обычном виде остаётся до 1000 px).

## ПРИЛОЖЕНИЕ A: КОНТРАКТ ПОДГОТОВКИ ДАННЫХ (для трека `map_pipeline`)

Инструмент `tools/map_pipeline/` (Python) детерминированно выпускает `ids.lock.json` (дополнение), `manifest.json`, `geometry.json` и `borders.json` из `source/map.svg`, `boundary.yaml` и `overrides.yaml`; отдельная команда `build_relief.py` печёт картинки рельефа. Свои параметры (допуски, шаг растра, упрощение, сглаживание, спины, границы) он берёт из собственной конфигурации `pipeline_config.yaml`; значения по умолчанию из этой спецификации: $\varepsilon=0{,}04$; $L_{\min}=0{,}3$; $r=4$; допуск упрощения 0,03 единицы.

Шаги `run_build` (порядок фактический): (1) разбор путей исходника: отбросить вложенный `<svg>` и преобразования масштаба и сдвига, заливки и штриховки, служебные дубли `id`; проверка корневого viewBox (`VIEWBOX_MISMATCH`); (2) замкнуть открытые контуры, починить самопересечения, удалить вырожденные отрезки и осколки мельче `clean.min_part_area`; (3) оставить провинции из `boundary.yaml`, за вычетом `technical_exclude`; (3а) применить `geometry_patches` по порядку записи — до проверки обособленных кусков: `transfer` (часть `from` внутри `polygon` переходит к `to`), `split` (провинция режется ломаной `line` на два узла, часть с `keep_point` сохраняет ключ и `id`, вторая получает `new_key`/`new_name`), `transfer_part` (кластер кусков `from`, выбранный `cluster_point`, переходит к существующей `to`), `detach` (кластеры по `cluster_points` выделяются из `from` в новый узел `new_key`); правки не меняют `source/map.svg`, суммы площадей консервируются, любое нарушение — `PATCH_INVALID`; применить `renames` (узел сохраняет `id`, старый ключ — в `previous_keys`); (4) удалить куски `drop_parts` и остановить сборку с `ISOLATED_PART` для каждого обособленного куска, не внесённого в `drop_parts`/`keep_parts`; присвоить `key` (коллизия — ошибка) и `id` из `ids.lock.json` (только добавление, начиная с 1001; исчезнувший из входа ключ — ошибка; исключённые в `boundary.exclude_explicit` ключи и выведенные зоны законно остаются без узла); (5) построить морские зоны (3.2); (6) вычислить связи (`land` по 3.1; `coast` и `sea` по контакту на растре, 3.1), применить `edges_add`, `edges_remove`, `land_links`, `straits` (пролив между уже связанными по суше провинциями — ошибка `STRAIT_ALREADY_CONNECTED`), проверить INV-M2 и INV-M3; (7) построить контуры суши по узлам: упрощение с допуском `tol = min(simplify.tolerance, simplify.small_part_factor·√A)` у мелких частей, ремонт швов провинций из `seam_repair`; (8) сгладить кольца (`smooth.*`): разбивка на цепи в якорях (стыки трёх и более регионов, концы общих границ, точки рамки, вершины патчей и `land_links`), гауссиан `smooth.sigma` по длине дуги с закреплёнными концами, общая граница пары сглаживается один раз по срединной линии и вставляется одинаково в обе стороны; лестница отката σ→σ/2→σ/4→исход под охранами валидности, числа частей и дыр, сдвига площади `max_area_change` и смещения `max_displacement`; (9) векторизовать морские зоны единым покрытием, обрезать по точному объединению итоговых контуров суши (плюс маска исключённой суши) с заходом `sea_cut.dilate_pixels` пикселей и присоединением водных остатков не больше `sea_cut.fill_max_area` к примыкающей зоне; (10) посчитать метрики узлов — `anchor` (центр наибольшей вписанной окружности), `bbox`, `area`, опору `label` (полюс недоступности доминантной части либо взвешенный центр островной группы, бокс `w`/`h`, спину `spine`/`len`/`thick` по правилу `spine.*`: перебор направлений шагом `angle_step_deg` в ±`max_angle_deg`, смещения `offset_step`, пять сагитт до `max_bend`); построить `outside` (замыкание `outside.closing`, подлезание `underlap`, окна-озёра только в пределах `lake_near_land` от игровой суши; водоём, не касающийся ни одного узла, не вырезается и остаётся тёмным) и составной путь `sea_water` заливов, касающихся хотя бы одного узла; (11) записать `geometry.json` с канонической сериализацией и версией 3.6, построить `borders.json` (канонические общие границы: линия пары — контур узла с меньшим `id` в полосе `borders.eps` вокруг соседа; концы дуг одного стыка подтягиваются к центру не дальше `junction_snap`; покрытие периметра каждого узла не ниже `1 − coverage_fail`, отклонения выше `coverage_warn` — в `reference/borders_coverage.tsv`) и `manifest.json` (узлы, связи, `borders_version`, геопривязка, `playable_bbox`, `inputs_sha256` по четырём входным файлам); проверить размеры по `limits.*`; (12) отчёт и картинки предпросмотра `preview/*.png`. Флаг `--check` завершает сборку ошибкой, если любой из `ids.lock.json`, `manifest.json`, `geometry.json`, `borders.json` изменился бы.

Отдельный шаг `build_relief.py` (выполняется вручную, растры Natural Earth в репозиторий не коммитятся): печёт две WebP-картинки с альфой и указатель `frontend/src/modules/01_map/relief/manifest.json` — игровую `relief.playable.<hash>.webp` (альфа — только полигоны LAND-узлов с дырами озёр, ~18 px/ед., двукратный суперсэмплинг) и мировую `relief.inactive.<hash>.webp` (весь глобус в той же регистрации Галла, ~5 px/ед.; яркость запечена по `relief.inactive_brightness`; альфа — суша `ne_10m_land` минус `ne_10m_lakes` минус «игровая рамка» объединения всех узлов, выращенная на 0,15 ед., кроме полигонов `outside`). Проверка регистрации — по контрольным точкам берега.
