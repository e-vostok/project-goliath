### `nations`

| Поле                  | Тип           | Ограничения                                                                  |

| `created_at`          | TIMESTAMPTZ   | NOT NULL                                                                     |

`owner_player_id UNIQUE` — единственный способ жёстко гарантировать инвариант «1 игрок = 0 или 1 государство» на уровне БД, а не только в сервисном слое.

**Описательные сведения** — все поля после `color_hex` кроме `created_turn` и `created_at` (Bible §8). Уникальность на них не накладывается, кроме `short_name`; индексы на них не нужны. NULL допустим на уровне БД только ради государств, созданных до миграции и для необязательных полей; сервис при создании всегда записывает обязательные поля (INV-7, INV-12). Длины колонок равны верхним границам схемы конфига, поэтому любое валидное значение конфига помещается в колонку без новой миграции:

- `name`, `short_name`, `leader_name`, `leader_title`, `motto`, `capital_name` — 100 (`le=100`);
- `description` — 200 (`le=200`);
- `leader_bio`, `history_url`, `anthem_url` — 2000 (`le=2000`);
- `gender` и `succession_type` — набор значений фиксирован кодом (не баланс), в конфиг не выносится.

**Миграция 0017** (версия 0.12.0, единица 4; номер — следующий свободный на момент ТЗ) удаляет колонки `nations.flag_id`, `nations.portrait_id` и `orders.nation_flag_id` (`04_orders`); тестовых государств и приказов на боевом сервере нет (подтверждено Project Owner 27.10.2026), переноса данных не требуется. Описание в этой Части 1 — состояние после миграции.

**Миграция** (следующая после head `0010`, имя `0011_00_core_registration_2.py`) добавляет одиннадцать колонок (в SQLite — через `batch_alter_table`), уникальный индекс на `short_name` и внешний ключ `capital_province_id`; существующие данные не меняет. Между `nations` и `provinces` возникает циклическая ссылка (`provinces.nation_id` → `nations.id` и `nations.capital_province_id` → `provinces.id`): внешнему ключу столицы задаётся имя и `use_alter=True`; обе стороны NULLABLE. Порядок удаления государства не меняется: провинции освобождаются (INV-6), затем строка государства удаляется.

**Миграция 0012** (версия 0.10.0, единица 4a) делает `short_name` NOT NULL: перед ALTER пустые значения заполняются полным названием (`UPDATE nations SET short_name = name WHERE short_name IS NULL`), и если это нарушает уникальность, миграция падает. Пустых кратких названий в игре больше не существует.

### `admin_grants` и `admin_audit_log` (версия 0.11.0, единица 3 — основа панели администратора)

`admin_grants` — выданные в базе права администратора, дополнение к `ADMIN_VK_USER_IDS`: `id` UUID PK; `player_id` UNIQUE, FK → `players.id`; `granted_by_vk_user_id` BIGINT NULL (снимок, без FK — запись переживает удаление выдавшего); `granted_at` TIMESTAMPTZ, серверный default `now()`.

`admin_audit_log` — ограниченный по числу записей журнал действий администратора (старые записи удаляются автоматически, см. `admin_panel.audit_log_max_rows`): `id` INTEGER PK; `created_at` TIMESTAMPTZ, серверный default `now()`, индекс; `actor_vk_user_id` BIGINT NOT NULL, индекс (снимок, без FK — история переживает удаление игрока); `action` VARCHAR(64) — машинный код (`tick.run`, `world.reset`, `player.delete`); `target_type`/`target_id` NULL; `summary` VARCHAR(300) — одна русская фраза для будущего просмотра; `details` JSON NULL — только идентификаторы и значения «было/стало», никогда не токены и не сырые параметры запуска.

Сервисы `modules/_00_core/admin_service.py` (оба работают в транзакции вызывающего, не коммитят): `AdminAuditService.record(...)` пишет строку журнала и в той же транзакции удаляет самые старые записи сверх `admin_panel.audit_log_max_rows`, `list_recent(limit, before_id)` отдаёт новейшие первыми с курсором `before_id`; `AdminGrantService.is_granted/grant/revoke` — `grant` идемпотентен, `revoke` отказывает администратору из `.env` (`ROOT_ADMIN_PROTECTED`) и последнему оставшемуся администратору — `.env` плюс таблица (`LAST_ADMIN`). `require_admin` (`core/admin/security.py`) принимает `.env` ИЛИ строку гранта, проверку по базе выполняет при каждом запросе — снятый администратор теряет доступ сразу. Сброс мира обе таблицы не трогает.

### `nation_images` (версия 0.12.0, единица 5)

Картинки государства: по одной строке на вид. Хранятся в PostgreSQL (решение исследования: попадают в `pg_dump`, удаляются вместе со строкой, не бывают «сиротами»).

| Поле | Тип | Ограничения |
| --- | --- | --- |
| `id` | INTEGER | PK |
| `nation_id` | UUID | FK → `nations.id`, `ON DELETE CASCADE` (страховка), NOT NULL |
| `kind` | VARCHAR(10) | `flag` или `portrait` (CHECK), NOT NULL |
| `sha256` | CHAR(64) | хэш полной картинки после пережатия; индекс, не уникальный; NOT NULL |
| `full_bytes` | BYTEA | WebP полного размера, NOT NULL |
| `thumb_bytes` | BYTEA | WebP миниатюры, NOT NULL |
| `byte_size` | INTEGER | размер `full_bytes`, NOT NULL |
| `uploaded_by_player_id` | UUID | FK → `players.id`, `ON DELETE SET NULL`, NULLABLE |
| `uploaded_at` | TIMESTAMPTZ | NOT NULL; обновляется при замене |

`UNIQUE (nation_id, kind)`: одна загрузка каждого вида; замена обновляет строку в той же транзакции, прежнее содержимое исчезает сразу, адрес прежней картинки начинает отвечать 404. Два государства с одинаковым файлом — две строки с одним `sha256`; удаление у одного не затрагивает другое. Классификация в `TABLE_COVERAGE`: `reset` (удаляется явно в `admin_reset` до `nations` и в `NationService.delete`; удаление игрока идёт через удаление государства). Миграция 0018 (следующая свободная) создаёт таблицу `nation_images`. Счётчика загрузок нет: игрок может заменять картинки сколько угодно, прежняя каждый раз удаляется.

### Картинки государства

Файл `backend/src/modules/_00_core/images.py` — единственное место, которое знает, как картинка превращается в адрес и как она обрабатывается. `image_url(sha256, variant) -> str` возвращает `/api/v1/images/<sha256>/full` или `/api/v1/images/<sha256>/thumb`; для отсутствующей картинки функции представлений возвращают `None`. Приём и пережатие (проверка настоящего типа, ориентации и размера до распаковки, автоматическая обрезка по центру до пропорции, WebP, миниатюра, хэш) — функция этого же файла, она выполняется в пуле потоков под семафором на одну картинку. Файла `catalog.py` и каталога статических картинок `frontend/public/assets/nations/` больше нет (единица 4).

## ЧАСТЬ 2: ИНВАРИАНТЫ, FSM И МЕСТО В TICK DAG

### Инварианты

- **INV-1:** `nations.owner_player_id` уникален — игрок не может владеть двумя государствами одновременно.
- **INV-2:** `nations.name` и `nations.color_hex` уникальны глобально (UNIQUE-констрейнты БД, а не только проверка в сервисе).
- **INV-3:** Создание государства и закрепление провинций — одна атомарная транзакция; частичное закрепление недопустимо (нарушение любого условия откатывает всю операцию).
- **INV-4:** `scheduled_actions` неизменяемы после создания игроком; единственный разрешённый переход статуса — `PENDING → APPLIED`, и выполняет его только тик-оркестратор.
- **INV-5:** `game_clock.current_turn` мутируется исключительно оркестратором тика, монотонно, на `+1`.
- **INV-6:** Удаление государства не удаляет провинции — обнуляет их `nation_id` (провинции переходят в статус свободных).
- **INV-7:** При создании государства `leader_name`, `leader_title`, `history_url` обязательны и проходят проверки Части 3 (нормализация, длины, формат). Ни одно из трёх значений не может быть NULL у государства, созданного после миграции профиля.
- **INV-8:** При изменении `null` или отсутствие поля означает «не менять»; пустая строка (после нормализации) у **обязательного** поля — ошибка, а не очистка. Очистить можно только необязательные поля (INV-12).
- **INV-9:** Проверки профильных полей выполняются в `service.py` (единый источник; коды ошибок — Часть 5). DTO только типизирует поля.
- **INV-10:** На описательные сведения (кроме `short_name`) не накладывается уникальность; они не участвуют в расчётах Tick.
- **INV-11:** `nations.short_name` уникален глобально (UNIQUE-констрейнт БД) и не может быть NULL (NOT NULL с миграции 0012). Сравнение — точное, после нормализации; различие регистра пока считается различием (бэклог). При создании краткое название обязательно.
- **INV-12:** При создании обязательны: `short_name`, `gender`, `succession_type`, `capital_province_id`, `capital_name` — вместе с полями INV-7. Необязательные поля (`motto`, `description`, `leader_bio`, `anthem_url`) пустыми не хранятся: пустое значение после нормализации записывается как NULL.
- **INV-13 (различимость цветов):** Цвет государства при создании и при смене проходит проверку Части 3 (расстояние OKLab до цветов других государств и до цветов карты) под транзакционной блокировкой, так что два одновременных похожих цвета не проходят оба. Цвет нормализуется к верхнему регистру до всех проверок. Государства, существовавшие до 0.8.0, задним числом не проверяются.
- **INV-14 (столица):** `capital_province_id` при создании — одна из провинций, закрепляемых за этим государством; если не передан, равен первому элементу `province_ids` в том порядке, в котором список передан. Через PATCH не меняется; `capital_name` меняется. Состав провинций через PATCH не меняется. Модули, которые меняют владельца провинции, решают судьбу столицы по правилу админ-передачи (см. «Передача и вывод провинций администратором» ниже): переход столичной провинции требует обязательного выбора новой столицы из оставшихся провинций донора.
- **INV-15 (картинки):** у государства не больше одной картинки каждого вида (`UNIQUE (nation_id, kind)`); картинки необязательны. Сервер не хранит выбор из каталога и не отдаёт каталога; отсутствие картинки означает «клиент показывает заглушку». Создание государства картинок не принимает: игрок загружает их после создания (отдельный запрос), поэтому сбой загрузки не отменяет регистрацию.
- **INV-16:** адреса картинок строятся только функцией `images.image_url`; ни сервисы, ни сателлиты не склеивают путь сами. Сателлиты получают картинки государств только через публичное представление `NationService.image_refs`.
- **INV-17 (одиночные тексты):** однострочные тексты не содержат символов категорий Unicode `Cc`/`Cf`; многострочная биография допускает единственный управляющий символ — перевод строки `\n`.
- **INV-18 (обработка):** сервер доверяет только содержимому файла: тип определяется по содержимому (разрешены JPEG, PNG, WebP), всё перекодируется в WebP стандартного размера, метаданные не переносятся, прозрачность сводится на белый фон; размер файла, число пикселей и сторона проверяются до распаковки. Окно может обрезать картинку заранее, но сервер этому не доверяет и всегда приводит к размеру сам.
- **INV-19 (удаление):** картинку государства удаляет только заменяющая загрузка владельца или администратор через панель (журнал администратора обязателен); игрок удалить картинку без замены не может. Удаление государства, игрока и сброс мира удаляют картинки явным `delete`, не только каскадом.
- **Порядок проверок при создании:** INV-1 → поля сведений в фиксированном порядке (имя лидера, должность, пол, способ смены, ссылка на историю, ссылка на гимн, краткое название, девиз, описание, биография, название столицы; возвращается первая ошибка) → блокировка (PostgreSQL: `pg_advisory_xact_lock`, SQLite: не требуется) → INV-2 для названия → INV-11 для краткого названия → цвет (совпадение → `COLOR_TAKEN`; близость к цвету карты → `COLOR_TOO_CLOSE`; близость к цвету другого государства → `COLOR_TOO_CLOSE`) → существование провинций → свобода провинций → проверки сателлитов стадии `after_free` → количество провинций → проверки сателлитов стадии `after_count` → столица принадлежит выбранным провинциям (`CAPITAL_NOT_IN_PROVINCES`) → создание (точки расширения — §3.8).
- **Порядок проверок при изменении:** профильные поля (только переданные, в том же порядке) → блокировка → название → краткое название → цвет (только если новый цвет отличается от текущего; сравнение с остальными государствами, своё исключается) → запись.
- **INV-TICK-ATOMICITY:** Весь тик — одна транзакция БД. Необработанное исключение в любом обработчике любой фазы → откат целиком; `current_turn` не увеличивается; все `scheduled_actions` хода остаются `PENDING` и обрабатываются повторно на следующей попытке. Запись в `tick_log` выполняется отдельным соединением/autocommit — вне транзакции тика, — иначе при откате пропадёт и диагностика сбоя.
- **INV-FREQUENCY:** Проверка частоты акта — обязанность `00_core` (реализация), правило частоты — обязанность модуля-владельца (конфигурация). См. алгоритм в Части 3.

**Ключ блокировки.** `NATIONS_ADVISORY_LOCK_KEY = 0x4E4154494F4E53` («NATIONS» в ASCII; помещается в bigint, не совпадает с `ORDERS_ADVISORY_LOCK_KEY` модуля `04_orders`). Блокировка берётся вызовом `SELECT pg_advisory_xact_lock(:key)` только на диалекте `postgresql` — по образцу `04_orders/service.py`; на SQLite единственный писатель делает её лишней. Блокировка держится до конца транзакции; сервис не коммитит.

### Регистрация в Tick DAG

```python
class TickPhase(IntEnum):
    PHASE_1_ENVIRONMENT = 100
    PHASE_2_PRODUCTION  = 200
    PHASE_3_CONSUMPTION = 300
    PHASE_4_RESOLVE     = 400
    PHASE_5_EXPIRATION  = 500
```

`00_core` **не регистрирует ни одного обработчика** ни в одной из 5 фаз — ни одна игровая механика ядру не принадлежит. Единственная процедура ядра — `finalize_tick()`: инкремент `current_turn`, запись `last_tick_at`/`next_tick_at`, закрытие `tick_log`. Она вызывается оркестратором как финальный шаг **вне** цикла по `TickPhase`, строго после завершения обработчиков `PHASE_5_EXPIRATION`.

Описательные сведения государства (символика, руководство, ссылки, столица) в Tick не участвуют: нового шага расчёта и новой регистрации в `TickPhase` они не создают.

**Фазовые зависимости:**

- *Входящие:* отсутствуют — никакой модуль не мутирует таблицы `00_core` напрямую (только через `service.py` ядра).
- *Исходящие:* структурная (не фазовая) зависимость всех модулей-сателлитов от `00_core` — регистрация обработчика в реестре фаз обязана произойти до старта тика, иначе оркестратор модуль не вызовет.

### 3.8 Точки расширения для модулей-сателлитов (extension points)

Ядро никогда не импортирует модули-сателлиты: зависимость односторонняя. Чтобы сателлит мог встроиться в операции ядра, `00_core` владеет именованными реестрами (реализация — `modules/_00_core/hooks.py`), которые сателлиты заполняют при старте приложения.

**Реестр слушателей смены владельца провинции.**

- Контракт события — `OwnershipChange(province_id, prev_nation_id, new_nation_id, new_name, new_short_name, new_color, turn)`: замороженный dataclass; `turn` = `game_clock.current_turn` транзакции, выполняющей смену. У захвата `prev_nation_id = NULL` и все `new_*` заполнены (включая `new_short_name` — краткое название на момент события, версия 0.10.0, единица 4b); у освобождения `prev_nation_id` = id удалённого государства, а все `new_*` = `NULL` — личность исчезнувшего государства доезжает до журнала через событие.
- Вызов: `NationService.create` (закрепление провинций) и `NationService.delete` (освобождение) вызывают `notify_ownership_changed(session, changes)` в **той же транзакции**, что и мутация `provinces.nation_id`, до commit (INV-M7 spec 01_map). Слушатели не коммитят сами. Ошибка любого слушателя откатывает всю операцию: государства нет, провинции свободны, записей журнала нет.
- Это единственная точка, через которую смена владельца становится видимой сателлитам: любая будущая операция, пишущая `provinces.nation_id` (завоевание, передача, освобождение), обязана идти через `notify_ownership_changed`. Админский сброс мира — осознанное исключение: он стирает мир целиком, а журнал очищает зарегистрированный хук сброса (см. ниже).

**Реестр проверок регистрации государства.**

- `NationService.create` выполняет проверки сателлитов на двух стадиях полного порядка Части 2/Части 5: `after_free` — сразу после проверки существования и свободы провинций, до проверки количества; `after_count` — сразу после проверки количества, до проверки столицы и записи строки государства.
- Проверка получает `AsyncSession` и загруженные строки `provinces`; отказ — доменное исключение со стабильным `code` и русским `message` (HTTP-статус — таблица соответствия в `main.py`, отсутствующий код → 500). Порядок вызова внутри стадии — порядок регистрации.

**Реестр хуков удаления игрока.**

- `register_player_delete_hook(name, fn)` — хук получает `(session, player_id)` и удаляет только строки собственного модуля этого игрока (инвариант суверенности данных); коммитить нельзя.
- `PlayerService.delete_player(session, player_id)` — админский инструмент для удаления тестовых игроков, необратимо. Всё выполняется в **одной транзакции** вызывающего кода (сервис не коммитит): (1) `NationService.delete` для государства игрока, если оно есть — провинции освобождаются, `scheduled_actions` сиротеют, записи об освобождении пишутся в журнал через `notify_ownership_changed` той же транзакцией; (2) все зарегистрированные хуки удаления в порядке регистрации — в отличие от хуков `nation_created`, SAVEPOINT на хук **нет**: ошибка любого хука откатывает удаление целиком (все-или-ничего); (3) строка `players`. Явные DELETE хуков — не запасной вариант: SQLite-тесты могут работать без включённых внешних ключей, поэтому каскады FK остаются лишь страховкой для PostgreSQL. Игрок не найден → `PLAYER_NOT_FOUND`. Удалённый пользователь ВК, снова открывший приложение, получает нового игрока через `get_or_create` — удаление не является баном.

**Общие правила реестров.**

- Записи именованные; повторная регистрация под тем же именем заменяет запись (идемпотентность: приложение может стартовать несколько раз в одном процессе тестов).
- Реестры предоставляют снимок/восстановление (`snapshot_extension_points`/`restore_extension_points`) для изоляции тестов — по образцу `AdminRegistry`.
- Сателлит `01_map` использует оба реестра при старте (spec 01_map, Часть 2): слушатель пишет `map_ownership_log`, проверки — «только суша» (`after_free`, `PROVINCE_NOT_LAND`) и «связная группа» (`after_count`, `STARTING_GROUP_NOT_CONNECTED`).
- Ядро работает с пустыми реестрами без деградации поведения — покрыто тестами.

**Хук сброса мира.** `admin_reset` в `00_core` выполняется в транзакции сброса через `AdminRegistry` (существующий механизм): хуки сателлитов вызываются в порядке, обратном регистрации, до модуля `00_core`. Сброс освобождает провинции массовым UPDATE без событий владельца — журнал владения зачищает собственный хук сателлита (для `01_map` — `DELETE FROM map_ownership_log`), поэтому после сброса журнал пуст, `current_turn = 0`, провинции свободны. Строки государств удаляются вместе со всеми сведениями (включая столицу): внешний ключ `capital_province_id` не мешает, потому что государства удаляются раньше любого удаления провинций (если провинции удаляются, `ON DELETE SET NULL` страхует).

**Реестр плиток «Состояние мира» (версия 0.11.0, единица 6a).** `AdminRegistry.register_overview(module_slug, fn)` — хук `fn(session)` возвращает список плиток `{"key", "label", "value", "sort"}` уже отформатированными для экрана; `GET /api/v1/admin/overview` (`require_admin`) склеивает плитки всех модулей и сортирует по `sort`, а падающий хук логируется, его сессия откатывается и плитки пропускаются — ответ не ломается. `00_core` отдаёт «Ход», «Следующий ход», «Часовой пояс», «Игроки», «Государства», «Провинций занято» и «Администраторы» (env-allowlist + гранты через `AdminGrantService`, уникальные игроки, последней); `04_orders` — «Приказы без вердикта» и «Ожидают распределения». `GET /api/v1/admin/me` дополнительно возвращает `reset_allowed` — снимок `ADMIN_ALLOW_RESET` на момент запроса.

**Реестр данных игрока (версия 0.11.0, единица 6b).** `AdminRegistry.register_player_info(module_slug, info_fn, search_fn=None)` — хук `info_fn(session, player_ids)` возвращает `{player_id: {field: value}}` для колонок, которыми владеет модуль, а необязательный `search_fn(session, text)` возвращает множество id игроков, подходящих под свободный запрос; падающий хук логируется, его сессия откатывается и хук пропускается. `03_registry` регистрирует `display_name` из кэша профиля ВК (статус OK) и поиск по имени-фамилии. `GET /api/v1/admin/players` (`require_admin`; `search`, `limit` 1..100 по умолчанию 50, `offset`) отвечает `{items, total}`: строки по дате регистрации и id, в каждой `vk_user_id`, `display_name` (или `null`), `nation_short_name` (или `null`), `created_at` в часовом поясе тика и `is_admin` (env-allowlist или активный грант, считается один раз на страницу); поиск идёт по точному VK id, названию государства и хукам — в питоновском сравнении, без регистрозависимости SQL. Тест `test_admin_table_coverage.py` держит словарь «таблица → reset | player_delete | kept» по всем таблицам `Base.metadata` и падает на новой неизвестной таблице.

**Журнал и права администратора (версия 0.11.0, единица 7).** `AdminRegistry.register_audit_actions(module_slug, {action_code: русская_метка})` — модуль владеет подписями своих действий журнала; неизвестный код показывается как есть. `GET /api/v1/admin/audit-log` (`require_admin`; `actor_vk_user_id`, `action`, `date_from`/`date_to` — даты в часовом поясе тика, `limit` 1..100 по умолчанию 50, курсор `before_id`) отвечает `{items, next_before_id}` новейшими первыми; `actor_name` — через хуки данных игрока (`null`, если игрок уже удалён). `GET /api/v1/admin/audit-log/filters` отдаёт разные значения актёров и действий для двух фильтров-выпадаек. `GET /api/v1/admin/admins` перечисляет env-администраторов и гранты (`source`, `granted_by_*`, `is_self`); `POST /api/v1/admin/admins` выдаёт права существующему игроку (404 неизвестному, идемпотентно), `POST /api/v1/admin/admins/{vk}/revoke` снимает — отказы 409 `CANNOT_REVOKE_SELF` (проверяется до сервиса), `ROOT_ADMIN_PROTECTED`, `LAST_ADMIN`. Каждая выдача и каждое снятие пишут по одной строке `admin.grant`/`admin.revoke` в транзакции запроса.

**Государства в панели (версия 0.11.0, единица 8a).** `AdminRegistry.register_province_info(module_slug, info_fn, search_fn=None)` — хук `info_fn(session, province_ids)` возвращает `{province_id: {"name": str}}` именами хозяина данных, необязательный `search_fn(session, text)` — подходящие id провинций; падающий хук логируется, его сессия откатывается и хук пропускается. `01_map` регистрирует показные имена сухопутных провинций. `GET /api/v1/admin/provinces` (`require_admin`; `search` через хук, `free_only`, `limit` 1..100 по умолчанию 50, `offset`) отвечает `{items: [{id, name, nation_id, nation_short_name}], total}` — только LAND, сортировка в питоновском сравнении по имени и id. `GET /api/v1/admin/nations` (`require_admin`; `search` по полному и краткому названию, `limit`, `offset`) отвечает `{items, total}`: `id`, `short_name`, `name`, `flag_thumb_url`, `owner_vk_user_id`, `owner_name` (хуки данных игрока), `provinces_count`, `capital_name`; порядок по дате создания и id. `POST /api/v1/admin/nations` (`require_admin`) принимает `owner_vk_user_id`, поля государства и упорядоченные `province_ids` (первая — столица, если не пришёл `capital_province_id`) и вызывает неизменённый `NationService.create`: картинок нет (создание государства в панели картинок не принимает), `capital_name` — имя столицы из хука провинций; неизвестному владельцу — 404 `PLAYER_NOT_FOUND`, отказы сервиса сохраняют свой HTTP-код. Одна строка `nation.create` пишется в той же транзакции до коммита; отказ откатывает всё вместе с ней.

**Правка государства в панели (версия 0.11.0, единица 8b).** `GET /api/v1/admin/nations/{nation_id}` (`require_admin`) отдаёт двенадцать правочных полей (`name`, `short_name`, `color_hex`, `motto`, `description`, `leader_name`, `leader_title`, `gender`, `succession_type`, `leader_bio`, `history_url`, `capital_name`) плюс `id`, `owner_vk_user_id`, `owner_name`, `capital_province_id`, `provinces_count`; неизвестному id — 404 `NATION_NOT_FOUND`. `PATCH /api/v1/admin/nations/{nation_id}` (`require_admin`; только те же двенадцать полей, все необязательные, `extra="forbid"`; пустое тело — 400 `NOTHING_TO_CHANGE`) вызывает неизменённый `NationService.update` — флаг, портрет, провинции и столичная провинция не меняются; отказы сервиса сохраняют свой HTTP-код, откатывают транзакцию и не пишут журнала. Одна строка `nation.update` («Правка государства») пишется в той же транзакции до коммита: сводка с русскими именами полей, `details` — только коды полей и идентификаторы, без текстов. `POST /api/v1/admin/nations/color-check` (`require_admin`; `color_hex`, необязательный `nation_id`) отвечает `{status}` из `NationService.color_status`, исключая переданное государство из сравнения; панель больше не вызывает игровой эндпоинт проверки цвета.

**Удаление государства из панели (версия 0.11.0, единица 8c).** `AdminRegistry.register_nation_preview(module_slug, preview_fn)` — хук `preview_fn(session, nation_id)` возвращает список `{"code", "text"}` — по одной готовой русской фразе на последствие в таблицах самого модуля; хук только читает и не коммитит, падающий хук не пропускается — его ошибка поднимается, потому что неверный прогноз не должен разрешать настоящее удаление. `00_core` регистрирует две строки: осиротевшие `scheduled_actions` государства и число освобождений, которые лягут в журнал владения карты. `GET /api/v1/admin/nations/{nation_id}/delete-preview` (`require_admin`) отвечает `{nation_id, short_name, name, owner_vk_user_id, owner_name, provinces: [{id, name}] (по имени), consequences: [{code, text}]}`; неизвестному id — 404 `NATION_NOT_FOUND`. `POST /api/v1/admin/nations/{nation_id}/delete` (`require_admin`; тело `{"confirm_short_name"}`) требует повторного ввода краткого названия посимвольно после обрезки пробелов (422 `CONFIRMATION_MISMATCH`), затем вызывает неизменённый `NationService.delete` в транзакции запроса: провинции освобождаются, запланированные действия теряют `nation_id`, в журнал владения пишутся освобождения; сбой откатывает всё (500 `NATION_DELETE_FAILED`). Игрок-владелец остаётся и может зарегистрировать новое государство. Одна строка `nation.delete` («Удаление государства») пишется до коммита — сводка с именем игрока и числом освобождённых провинций, `details` — только идентификаторы; ответ возвращает прогноз, истинный на момент удаления.

**Передача и вывод провинций администратором (версия 0.11.0, единица 9a).** `ProvinceService.transfer(session, province_id, to_nation_id, *, new_capital_province_id=None, new_capital_name=None, confirm_seize=False, config)` — единая доменная операция «передать сухопутную провинцию государству или освободить её» (`to_nation_id=None`): работает в транзакции вызывающего под блокировкой nations, не коммитит и объявляет ровно один `OwnershipChange` через `notify_ownership_changed` (запись в журнал владения делает собственный слушатель `01_map`, INV-M7). Ограничения `min/max_provinces_per_nation` к администратору не применяются; порядок отказов: провинция существует и LAND (422 `PROVINCE_NOT_LAND` для морских узлов) → целевое государство существует (404 `NATION_NOT_FOUND`) → `ALREADY_OWNER` (уже у цели либо уже свободна при выводе) → `SEIZE_NOT_CONFIRMED` (занята чужим государством, `confirm_seize` не передан) → `LAST_PROVINCE` (у донора только эта провинция — государство удаляется вместо передачи) → столица донора: обязательный выбор новой из оставшихся провинций (`CAPITAL_REQUIRED`, `CAPITAL_NOT_IN_PROVINCES`, `CAPITAL_NAME_INVALID`); у донора без столицы (государство до 0.8.0) ничего не требуется. `GET /api/v1/admin/provinces/{id}/transfer-preview` (`require_admin`, только чтение; без `to_nation_id` — предпросмотр вывода) отвечает `{province {id, name}, from_nation {id, short_name, provinces_count, capital_province_id, capital_name} | null, to_nation {id, short_name, provinces_count} | null, seizes, capital_choice_needed, capital_candidates [{id, name}] (оставшиеся провинции донора по имени), donor_after, receiver_after, blocker (null | LAST_PROVINCE | ALREADY_OWNER)}`; имена — через хуки провинций, неизвестной провинции — 404 `PROVINCE_NOT_FOUND`. `POST /api/v1/admin/provinces/{id}/transfer` (`require_admin`; `{to_nation_id, confirm_seize=false, new_capital_province_id}`; название новой столицы берётся у выбранной провинции из хуков, иначе 422 `PROVINCE_NAME_UNKNOWN`) вызывает сервис и пишет одну строку `province.transfer` («Передача провинции») в той же транзакции до коммита: сводка — одна русская фраза, `details` — только идентификаторы и флаг `seized`; отказ откатывает всё и строки не пишет. Ответ: `province_id`, `previous_nation_id`, `new_nation_id`, `new_capital_province_id`.

**Публичные представления для сателлитов.** Чтение чужих данных идёт только через открытые представления `service.py` — сателлит не обращается к таблицам `00_core` напрямую. `PlayerNationSummary` (`NationService.player_nation_summary`) несёт `short_name: str` и `flag_sha256: str | None` рядом с полным названием и цветом — этого достаточно, чтобы `04_orders` снимал свой снимок, не касаясь таблицы `nations`. `OwnedProvinceInfo` (`ProvinceService.list_current_owners`) несёт `nation_short_name: str` — живую строку владельца для текущего хода `GET /map/state` (версия 0.10.0, единица 4b).

Адрес строится `images.image_url`.

## ЧАСТЬ 3: МАТЕМАТИЧЕСКИЙ АППАРАТ

Формульный аппарат `00_core` минимален по конструкции: ядро не считает игровые показатели (это зона модулей-сателлитов), поэтому формул с делением здесь нет и защита от деления на ноль не применима к текущей части — общий паттерн для будущих модулей: `x / max(y, ε)`.

**Момент следующего тика:**
$$
t_{next} = \min\{\, t \in T_{tick} \mid t > t_{now} \,\}
$$
где $T_{tick}$ — множество локальных календарных моментов `tick.tick_time` (строгий формат `HH:MM`) в зоне `tick.tick_timezone`. `next_tick_at` — ближайшее наступление этого времени суток строго после `t_{now}`, вычисленное по локальной календарной дате (никогда не «+24h»): переходы на летнее/зимнее время сдвигают UTC-момент тика, а локальное время остаётся фиксированным. Следствие: ручной запуск тика не сдвигает суточное расписание.

**Игровая дата:**
$$
M_{total} = Y_{epoch} \times 12 + (m_{epoch} - 1) + N_{turn} \times R_{months}
$$
$$
D_{game} = \mathrm{date}\bigl(\lfloor M_{total} / 12 \rfloor,\; M_{total} \bmod 12 + 1,\; 1\bigr)
$$
где $D_{epoch}$ = `calendar.epoch_start_date` (схема требует первое число месяца, поэтому день результата всегда 1), $N_{turn}$ = `game_clock.current_turn`, $R_{months}$ = `calendar.months_per_turn`. Округление не нужно — все операнды целые; отрицательный $N_{turn}$ — `ValueError`, а итог за пределами `date.max` прижимается к `9999-12-01` вместо ошибки. Первый ход ($N_{turn} = 0$, в том числе сразу после сброса мира) — январь 2040 года.

Игроку дата показывается как «Месяц Год»: `format_game_date` берёт название из `calendar.month_names` (ровно 12 имён, январь первым, без дублей), делает первую букву заглавной и добавляет год без ведущих нулей — `Январь 2040`, `Февраль 2040`, `Январь 2041` (ход 12). День не показывается (он всегда 1). В JSON дата остаётся ISO в `game_date`, текстовая форма приезжает отдельным полем `game_date_text`.

**Свежесть `vk_ts` (Session Auth):**
$$
|\,t_{now} - t_{vk\_ts}\,| \le W_{freshness}
$$
где $W_{freshness}$ = `vk_ts_freshness_window_minutes × 60` (секунды). Модуль абсолютного значения закрывает сразу два случая: устаревший запрос (replay-атака) и запрос с меткой из будущего (рассинхрон часов/подделка).

**Проверка частоты механического акта (INV-FREQUENCY):**
$$
\text{Allow} \iff N_{used}(P, M, A, T) < N_{max}(F)
$$
где $N_{used}$ — число уже существующих `scheduled_actions` для государства $P$, модуля $M$, типа акта $A$ на ходу $T$ (для правила `ONCE_PER_GAME` фильтр по ходу $T$ снимается — считается за всю историю); $N_{max}(F)$ определяется правилом частоты: `ONCE_PER_TURN → 1`, `ONCE_PER_GAME → 1` (без фильтра по ходу), `MULTIPLE_PER_TURN → cap` (числовой лимит модуля-владельца), `UNLIMITED → ∞`.

### Профильные поля государства

Формул с делением здесь нет, защита от деления на ноль не применима. Округления нет.

**Нормализация:** $t = s.\mathrm{strip}()$ (Unicode-пробелы). Длина считается в кодовых точках Unicode ($\lvert t \rvert$ = `len(t)`).

**Однострочное текстовое поле** (полное название, краткое название, имя лидера, должность лидера, девиз, описание, название столицы):
$$
\text{valid}(s) \iff L_{\min} \le \lvert t \rvert \le L_{\max} \;\wedge\; \forall c \in t:\ \mathrm{cat}(c) \notin \{\mathrm{Cc}, \mathrm{Cf}\}
$$
Поле однострочное: управляющие символы (включая перевод строки) и невидимые символы форматирования (категории Unicode `Cc`, `Cf`) недопустимы. Пределы берутся из конфига: `nation.nation_name_*`, `nation.short_name_*`, `nation.leader_name_*`, `nation.leader_title_*`, `nation.capital_name_*`; у девиза и описания нижней границы нет ($L_{\min} = 0$ после нормализации: пустое значение — «нет значения», хранится как NULL), верхние — `nation.motto_max_length`, `nation.description_max_length`. Значение хранится в нормализованном виде (после `strip`).

**Многострочное текстовое поле** (биография лидера): сначала `\r\n` и одиночный `\r` заменяются на `\n`, подряд идущие три и более `\n` сворачиваются в два (между абзацами — не больше одной пустой строки), затем `strip`; допустимы символы, кроме категорий `Cc`/`Cf`, за исключением перевода строки `\n`; длина — в кодовых точках, `\n` считается за один; верхняя граница — `nation.leader_bio_max_length`, применяется к тексту после нормализации; пустое значение — NULL.

**Ссылка на историю:** $u = \mathrm{trim}(s)$, разбор — `urllib.parse.urlsplit`:
$$
\text{valid\_url}(u) \iff \lvert u \rvert \le L_{url} \;\wedge\; \text{scheme}=\texttt{https} \;\wedge\; \text{host}\in H \;\wedge\; \text{port},\ \text{userinfo},\ \text{query},\ \text{fragment}=\varnothing \;\wedge\; \text{path} = \texttt{/@}\,\text{slug}
$$
где $H$ — `nation.history_url_allowed_hosts` (в 0.8.0: `vk.com`, `vk.ru`, `m.vk.com`), хост сравнивается в нижнем регистре, $L_{url}$ — `nation.history_url_max_length`. Путь ($\text{slug}$ — название статьи) должен соответствовать регулярному выражению `^/@[^/\s]+$` (адрес статьи ВКонтакте: знак `@`, затем название без слэшей и пробелов). Пробелы и управляющие символы внутри адреса недопустимы. Ошибка разбора (`ValueError`, например некорректный порт) считается невалидной ссылкой. Значение хранится в том виде, в котором принято после удаления внешних пробелов.

**Ссылка на гимн** (поле не используется с 0.9.0 — интерфейс его не предлагает; колонка, поле DTO и проверка временно сохраняются): $u = \mathrm{trim}(s)$; пустое значение — «нет ссылки» (NULL). Иначе:
$$
\text{valid\_anthem}(u) \iff \lvert u \rvert \le L_{anthem} \;\wedge\; \text{scheme}=\texttt{https} \;\wedge\; \text{host}\in H_{a} \;\wedge\; \text{port},\ \text{userinfo}=\varnothing \;\wedge\; u\ \text{не содержит пробелов и символов категорий Cc/Cf}
$$
где $H_a$ — `nation.anthem_url_allowed_hosts`, $L_{anthem}$ — `nation.anthem_url_max_length`. Путь, параметры и фрагмент не проверяются: формат ссылок ВКонтакте на музыку не подтверждён (NAT-0, N4). Это сознательно мягкая проверка; ужесточение — после исследования формата.

**Известное ограничение:** формат ссылок проверяется, содержимое — нет. Ссылка на чужую статью или на страницу автора `vk.com/@имя` формат проходит (Bible §8, `out_of_scope`).

**Частичное изменение (PATCH):** обязательные поля: не-`null` проходит те же проверки, `null` или отсутствие — «не менять», пустая строка — ошибка; необязательные поля: не-`null` проходит проверки, `null` или отсутствие — «не менять», пустая строка (после нормализации) — «очистить» (запись NULL).

### Различимость цветов (INV-13)

**Перевод цвета в OKLab.** Вход — `#RRGGBB` (регистр любой). Каналы $c \in \{R, G, B\}$ переводятся в линейный sRGB:
$$
c' = c/255,\qquad c_{lin} = \begin{cases} c'/12.92, & c' \le 0.04045 \\ \bigl((c'+0.055)/1.055\bigr)^{2.4}, & c' > 0.04045 \end{cases}
$$
Затем в конусный отклик и кубический корень:
$$
\begin{aligned}
l &= 0.4122214708\,R + 0.5363325363\,G + 0.0514459929\,B\\
m &= 0.2119034982\,R + 0.6806995451\,G + 0.1073969566\,B\\
s &= 0.0883024619\,R + 0.2817188376\,G + 0.6299787005\,B
\end{aligned}
\qquad l_c=\sqrt[3]{l},\; m_c=\sqrt[3]{m},\; s_c=\sqrt[3]{s}
$$
(здесь $R, G, B$ — линейные значения). Координаты OKLab:
$$
\begin{aligned}
L &= 0.2104542553\,l_c + 0.7936177850\,m_c - 0.0040720468\,s_c\\
a &= 1.9779984951\,l_c - 2.4285922050\,m_c + 0.4505937099\,s_c\\
b &= 0.0259040371\,l_c + 0.7827717662\,m_c - 0.8086757660\,s_c
\end{aligned}
$$

**Расстояние:**
$$
d(c_1, c_2) = \sqrt{(L_1-L_2)^2 + (a_1-a_2)^2 + (b_1-b_2)^2}
$$
Чёрный и белый находятся на расстоянии 1.0. Деления нет, защита от деления на ноль не применима; округления нет (сравнение с порогом — на полной точности `float`).

**Решение.** Для нового цвета $c$ (в верхнем регистре) и множеств $O$ — цвета других государств, $R$ — цвета карты из `color.reserved`:
$$
\text{status}(c) = \begin{cases}
\texttt{TAKEN}, & \exists\, o \in O:\ o = c\\
\texttt{TOO\_CLOSE}, & \exists\, r \in R:\ d(c, r) < D_{res}\\
\texttt{TOO\_CLOSE}, & \exists\, o \in O:\ d(c, o) < D_{nat}\\
\texttt{OK}, & \text{иначе}
\end{cases}
$$
где $D_{nat}$ = `color.min_distance_nations`, $D_{res}$ = `color.min_distance_reserved`. Равенство порогу — допустимо (строгое «меньше»). Реализация — чистые функции в `backend/src/modules/_00_core/color_policy.py` (`hex_to_oklab`, `oklab_distance`; схема конфига импортирует их же). Цвета государств читаются из БД в той же транзакции, что и запись, после взятия блокировки (INV-13).

**Тестовые векторы** (допуск по каждому значению $10^{-5}$):

- `#000000` → (0.0, 0.0, 0.0); `#FFFFFF` → (1.0, 0.0, 0.0); `#8C8C8C` → (0.640087, 0.0, 0.0); `#FF0000` → (0.627955, 0.224863, 0.125846); `#00FF00` → (0.866440, −0.233888, 0.179498); `#141E26` → (0.229243, −0.009648, −0.018895).
- $d$(`#000000`, `#FFFFFF`) = 1.000000; $d$(`#FF0000`, `#00FF00`) = 0.519813; $d$(`#0C7CF4`, `#2B2DB0`) = 0.207907.
- $d$(`#8C8C8C`, `#8F8F8F`) = 0.009954; $d$(`#BE1253`, `#C01355`) = 0.005012 — оба меньше любого порога конфига (отказ).
- $d$(`#8C8C8C`, `#9A9A9A`) = 0.046136; $d$(`#8C8C8C`, `#A0A0A0`) = 0.065670 — при порогах 0.08 оба отказ.
- $d$(`#ff0000`, `#FF0000`) = 0 (регистр не влияет).

**Палитра.** Палитра из 36 цветов в `color.palette` подобрана заранее жадным алгоритмом «максимальный минимум» (не вычисляется при работе сервера). Схема конфига проверяет, что любые два цвета палитры различимы не хуже $D_{nat}$, а любой цвет палитры — не хуже $D_{res}$ до каждого цвета карты; в поставляемом конфиге минимальное расстояние в палитре 0.1015, до цветов карты 0.1002. Пороги и палитру можно менять правкой конфига (быстрый трек «А»), CI не пропустит палитру, нарушающую собственные пороги.

Число стартовых провинций задано двумя ключами `min`/`max`, оба равны 5 (решение Project Owner 17.10.2026): ключи остаются раздельными, чтобы число могло позже зависеть от бонусов.

**Перекрёстные правила схемы:**

- `*_min_length ≤ *_max_length` для названия, краткого названия, лидера, должности, столицы; `short_name_max_length ≤ nation_name_max_length`; `min_provinces_per_nation ≤ max_provinces_per_nation`.
- Хосты в `history_url_allowed_hosts` и `anthem_url_allowed_hosts` — в нижнем регистре, без схемы, порта и пути, валидные имена хостов, без дублей.
- Верхние границы `le` текстовых лимитов не больше длин колонок в БД (100 / 100 / 100 / 100 / 200 / 2000 / 2000 / 2000, см. Часть 1); это проверяет тест `test_configs_validity.py`.
- `color.reserved[].hex` и `color.palette[]` — формата `#RRGGBB`; палитра без дублей (регистр не учитывается); любые два цвета палитры различимы не хуже `min_distance_nations`; любой цвет палитры различим с каждым цветом `color.reserved` не хуже `min_distance_reserved`.
- `images`: флаг строго шире, чем выше (`flag_width > flag_height`), портрет строго выше, чем шире (`portrait_height > portrait_width`); миниатюра имеет ту же пропорцию, что полный размер (`flag_width × flag_thumb_height == flag_height × flag_thumb_width`, так же для портрета) и не больше полного размера; `max_pixels ≤ max_side × max_side`.
- `tick.health_max_heartbeat_age_seconds > tick.retry_delay_seconds + tick.heartbeat_interval_seconds`.
- Все ключи, кроме двух ключей `tick.heartbeat_*`, обязательны (значений по умолчанию в схеме нет): пропущенный ключ ломает запуск.

**Сверка с картой (тест CI, не схема).** Тест `test_configs_validity.py` проверяет, что цвета `colors.neutral_province`, `colors.sea`, `colors.outside`, `colors.hover` из `configs/01_map.yaml` присутствуют среди `color.reserved[].hex` (регистр не учитывается). Так правка цвета карты без правки резерва ломает сборку, а не молча открывает цвет государствам.

`DELETE /api/v1/nations/me` отменён (Изменения 1.4) и снят в единице 8 версии 0.9.0 вместе с тестами и клиентским вызовом: игрок государство не удаляет; `NationService.delete` остаётся внутренней операцией сервиса (хук удаления игрока, сброс мира).

`POST /api/v1/nations/color-check` — подсказка для интерфейса при вводе HEX: проверяет цвет теми же функциями Части 3, но без блокировки и без записи, поэтому ответ `OK` не гарантирует успех создания (окончательное решение принимает `POST /api/v1/nations` под блокировкой). Свой собственный цвет (если у игрока уже есть государство) из сравнения исключается. Неверный формат `color_hex` — стандартный 422.

`kind` ∈ {`flag`, `portrait`}, `variant` ∈ {`full`, `thumb`}.

**Загрузка (`PUT /api/v1/nations/me/images/{kind}`).** Тело запроса — сам файл (не multipart); `Content-Type` и расширение не учитываются. Порядок проверок: вход → у игрока есть государство (иначе 404 `NATION_NOT_FOUND`) → чтение тела с отсечкой по `images.max_upload_bytes` (иначе 413 `IMAGE_TOO_LARGE`) → тип по содержимому (не JPEG, PNG или WebP либо файл повреждён — 415 `IMAGE_UNSUPPORTED`) → число пикселей и сторона по заголовку, до распаковки (больше `images.max_pixels` или `images.max_side` — 413 `IMAGE_TOO_LARGE`) → ориентация по размеру после поворота по EXIF (флаг не шире, чем выше, либо портрет не выше, чем шире — 422 `IMAGE_ORIENTATION_INVALID`) → разбор в пуле потоков под семафором: обрезка по центру до пропорции, уменьшение до точного размера, WebP, миниатюра, `sha256` → одна транзакция: замена строки `nation_images` (прежнее содержимое исчезает сразу). Сервер число загрузок игрока не считает. Ответ `NationImageDTO = { kind: str, url: str, thumb_url: str }`. Квадратная картинка для флага не проходит (длина должна быть строго больше высоты). Для JPEG при разборе используется режим уменьшенной распаковки (`draft`), чтобы пик памяти не зависел от размера источника.

**Раздача (`GET /api/v1/images/{sha256}/{variant}`).** Без входа (тег `<img>` не передаёт заголовок `Authorization`; содержимое видно всем игрокам). Ответ 200: `Content-Type: image/webp`, `Cache-Control: public, max-age=86400`, `ETag` = `sha256`, `X-Content-Type-Options: nosniff`. Если строки с таким хэшем нет — 404 с `Cache-Control: no-store`. Адрес по содержимому: замена или удаление картинки делает прежний адрес мёртвым, у зрителя картинка может оставаться в кэше не дольше суток.

**Порядок в окне регистрации.** Окно сначала создаёт государство обычным `POST /api/v1/nations` (без картинок), затем отправляет выбранные картинки; сбой загрузки не отменяет регистрацию, игрок видит сообщение и может загрузить картинку позже в «Штабе» (щелчком по флагу или портрету). Картинки, выбранные при регистрации, хранятся в окне до создания государства и после него отправляются по одной; в форме правки текстовых данных блоков флага и портрета нет.

### Вход в панель администратора (версия 0.11.0, единица 4)

| POST   | `/api/v1/admin/panel-link` | Bearer + admin        | —          | `{token, expires_in_seconds}`           | 200 / 401 / 403     |
| POST   | `/api/v1/admin/session`    | нет                   | `{token}`  | `{access_token, expires_in_seconds}`    | 200 / 401 / 403     |

- `panel-link` выдаёт одноразовую метку `secrets.token_urlsafe(32)`; хранится только её SHA-256 вместе с id игрока и сроком годности — сама метка не хранится и не пишется в логи. Строки журнала при выдаче нет (это только билет).


`color_hex` валидируется regex-паттерном `^#[0-9A-Fa-f]{6}$` на уровне DTO — это не балансовое число, поэтому в YAML не выносится. Длина названия также проверяется на уровне DTO по конфигу. Ошибки типов и формата DTO (`color_hex`, длина названия, тело запроса) FastAPI возвращает в стандартном формате 422; описательные поля государства проверяет сервис, и их ошибки приходят в формате `ErrorResponse`. Ответы всегда содержат `color_hex` в верхнем регистре для новых и изменённых цветов; у старых записей возвращается как хранится.

## ПРИЛОЖЕНИЕ A: Изменения за пределами `00_core`

- **A1. `03_registry`.** `NationRegistryRow` (результат `NationService.list_for_registry`) получает поля `short_name: str` (NOT NULL с миграции 0012) и `flag_sha256: str | None` (хэш загруженного флага, `None` — флага нет). Источники `players` и `nations` строят ячейку `nation` как `cell_nation(name=short_name, color, flag_url=images.image_url(flag_sha256, "thumb"))`. Spec `03_registry` (описание ячейки `nation`, строка про `flag_url = null`) обновляется Lead AI в Issue 16 отдельным файлом.
- **A2. `01_map`.** `ProvincePicker` принимает и возвращает упорядоченный список (порядок выбора важен для столицы по умолчанию), поддерживает отметку столицы правой кнопкой и видимой кнопкой; исправляется дёрганье карты в окне выбора (бэклог `01_map`) — Issue 15.
- **A3.** Статических картинок государств нет: загруженные картинки отдаёт приложение (`/api/v1/images/...`, Caddy проксирует `/api/*`); заглушки рисует клиент.
- **A4. Тесты и фабрики.** Фабрика государства создаёт ровно `max_provinces_per_nation` (5) провинций и заполняет новые обязательные поля; тесты, предполагавшие меньшее число провинций, обновляются; добавляются тесты порядка проверок, гонки цветов (две одновременные регистрации близких цветов — принята одна), миграции вверх/вниз на SQLite и PostgreSQL, сверки конфига с `01_map.yaml`, раздела `images` и перекрёстных правил схемы (Часть 4), векторов OKLab из Части 3.
- **A5. `main.py`.** Таблица соответствия кодов ошибок и статусов расширяется кодами Части 5.
- **A6. Эксплуатация.** `m.vk.com` добавлен в допустимые хосты ссылки на историю по итогам NAT-0 (N7); формат ссылок ВК на музыку не подтверждён (N4), поэтому ссылка на гимн проверяется мягко.
