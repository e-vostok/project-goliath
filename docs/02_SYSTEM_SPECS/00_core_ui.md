# 02_SYSTEM_SPECS / 00_core — Единый интерфейс (UI Spec)

> Этот файл — единственный источник правил вида и поведения окон приложения PAX ATOMICA. Каждый модуль и расширение строит свой интерфейс по нему; отдельным Issue «Интерфейс» в Roadmap модуля (см. `docs/development_workflow.md`, п. 4). Правила утверждены Project Owner 19–20.10.2026 по макетам версии 0.9.0 (артефакт «PAX ATOMICA — макеты окон»; в репозиторий макеты не вносятся, на них ссылаются Issues «Интерфейс» в Roadmap). Раздел «Панели VKUI» Части 5 Spec `00_core` описывает содержимое панелей `00_core`; вид и поведение окон определяет этот файл, а при расхождении побеждает он.
> Что в этом файле: 1. Принципы. 2. Окно приложения во ВК. 3. Четыре типа окон. 4. Каркас и навигация. 5. Дизайн-токены. 6. Собственные элементы. 7. Состояния и сообщения. 8. Правила текстов. 9. Окна приложения (образцы). 10. Чек-лист Issue «Интерфейс».

## 1. Принципы

1. **Один язык интерфейса.** Основа — VKUI платформы VKCOM; поверх него — небольшой набор собственных оформленных элементов (п. 6). Любой элемент, который есть в п. 5–6, выглядит одинаково везде; копировать вид по файлам запрещено — только общие компоненты из `frontend/src/shared/ui/`.
2. **Компактно и информативно.** Главное видно сразу, остальное сгруппировано блоками; пустых полей «для красоты» нет; строка списка и таблицы — `row-compact`.
3. **Игроку — игровое, а не служебное.** Не показываются: номера и идентификаторы провинций и игроков, пол лидера, настройки уведомлений, технические статусы, англоязычные коды. Вместо номера провинции — её название.
4. **Только десктоп.** Мышь, колесо, ПКМ/ЛКМ, клавиатура, монитор 1920 × 1080. Мобильной раскладки нет.
5. **Две темы.** Тёмная — основная, светлая — вторая; игрок выбирает тему маленькой кнопкой в верхней полосе (п. 5.4); каждый цвет интерфейса — токен с двумя значениями (п. 5). Значения цветов «из головы» в коде запрещены.
6. **Всё, чего нельзя проверить, помечено.** Что не проверено в настоящем ВК, в Spec так и названо («не проверено»), а проверка закладывается в приёмку.

## 2. Окно приложения во ВК

Замер 19.10.2026 (версия 0.8.1) и проба 0.8.2:

- **Ширина — ровно 910 px.** Любое окно приложения, кроме карты, умещается в 910 px: без горизонтальной прокрутки, ничего не выступает. Колонки и поля сжимаются и переносятся, а не уезжают вбок.
- **Высота** задаётся приложением. Метод `VKWebAppResizeWindow` из приложения работает (проверено до 4050 px). Правило: **высота окна = высота содержимого корневого контейнера приложения** (не всей страницы: страница не бывает ниже окна). Один компонент каркаса следит за размером корневого контейнера (`ResizeObserver`), после изменения с задержкой 200 мс вызывает `VKWebAppResizeWindow` с шириной 910 и высотой, округлённой вверх, в пределах 600–4050 px. Меняется при каждом переходе между окнами и при изменении содержимого. Больше нигде в коде высота не задаётся.
- **Начальная высота** в кабинете dev.vk.com понижается при выкладке каркаса до значения короткого экрана (предложение: 1000 px), чтобы при открытии не было большой пустоты.
- **Окно прокручивается страницей ВК, а не приложением.** Внутри окна `scrollY` всегда 0; какую часть окна видит игрок, приложению неизвестно. Следствия: верхняя полоса не «липкая» (прокручивается вместе со страницей); всплывающее окно не может рассчитывать на положение прокрутки (п. 3.3).
- **Не проверено в настоящем ВК:** мерцание при частой смене высоты, поведение всплывающих окон на высокой странице при прокрутке страницы вниз, закрытие окон по Esc и по клику на затемнение внутри окна ВК, наведение с удержанием (подсказка) в окне ВК. Проверяются в приёмке единиц 4, 6 и 11 версии 0.9.0.
- **Карта** — исключение из ширины: она занимает всю область окна; её высота задаётся отдельно (п. 9.5). Панели Реестра и карты не используют `position: fixed` относительно окна: они лежат в обычном потоке страницы, иначе при автоматической высоте они схлопываются.

## 3. Четыре типа окон

У каждого типа свои правила размера, открытия, закрытия, вложенности и графики. Тип окна виден игроку по поведению.

### 3.1 Экран

- Основное окно приложения: Штаб (карточка государства), Реестр, Карта, Регистрация государства. Один экран в каждый момент.
- Ширина — 910 px (карта — вся область). Фон — `ground`; содержимое — блоки на `surface` со скруглением `radius-lg` и отступами `space-4`.
- Заголовок экрана — стиль `title`-uppercase (п. 5.3) со значком блока (п. 6, элемент 2) и линией справа; у карточки государства — название государства (стиль `display-lg`).
- Переход между экранами — только через верхнюю полосу (п. 4); адрес экрана — хеш (`#map`, `#registry`, `#register`, главная — пустой хеш).
- Закрыть экран нельзя; «Назад» не нужен: у каждого экрана есть своя вкладка в верхней полосе.

### 3.2 Подэкран

- Заменяет содержимое экрана (не лежит поверх него), **ширина та же, 910 px**: со стороны выглядит как обычное переключение окон.
- Всегда виден как подэкран: под верхней полосой стоит **полоса возврата** высотой 48 px — слева синяя отметка 4 px (`action`), кнопка «← Название родителя» (всегда на одном месте, вторичная кнопка), цепочка пути («Реестр / Игроки / …»). Надписи «Подэкран» нет: тип окна виден по полосе возврата. Возврат ведёт в окно, из которого игрок пришёл, с сохранением его состояния (фильтры, поиск, положение в списке).
- Имеет собственный адрес (например, `#registry/order-N`, `#registry/nation-N`); при открытии по ссылке возврат ведёт в родительский экран в состоянии по умолчанию.
- Подэкран не открывает подэкран: предел вложенности — один уровень.
- Верхняя полоса остаётся: вкладка родителя подсвечена.
- Образец — «Реестр → Государство» (единица 14); компонент `shared/ui/Subscreen`.

### 3.3 Всплывающее окно

- Лежит поверх затемнения (`rgba(0,0,0,0.6)`), открывается из любого места, формально привязано к одному окну-родителю (карточке государства, строке Реестра и т. п.). Фон — `surface-raised`, скругление `radius-lg`, тень `shadow-popup`.
- **Размеры (ширина):** S = 480 px (подтверждение, простой вопрос), M = 640 px (форма: подача приказа, вердикт), L = 880 px (просмотр: приказ целиком). Окно «Выбор провинций» (регистрация) — размера L (880 px) с картой фиксированной высоты 520 px; привязано к регистрации.
- **Расположение.** Положение прокрутки страницы ВК приложению неизвестно (п. 2), поэтому окно прижимается к **верху окна приложения** с отступом 64 px (не по центру высокого окна). Метод `VKWebAppScroll` в версии 0.9.0 не применяется (не проверен): сначала Project Owner смотрит, как окно ложится на высокой странице в настоящем ВК; при необходимости решение добавляется отдельной правкой. Корневой контейнер приложения не ниже самого нижнего всплывающего окна, поэтому окно ВК растёт вместе с окном.
- **Состав:** заголовок (стиль `title-uppercase`, значок окна — п. 6, элемент 2) слева; крестик «Закрыть» справа **внутри рамки**; разделитель `line`; тело с отступом `space-4`; нижняя полоса действий.
- **Кнопки действий:** справа, главное действие самое правое (заливка `action`), отмена слева от него (вторичная). Одно главное действие на окно. Опасное действие — кнопка цвета `danger` и обязательно малое подтверждение.
- **Закрытие:** крестиком, кнопкой «Отмена»/«Вернуться…», клавишей Esc, кликом по затемнению (если в форме есть несохранённый ввод — Esc и клик по затемнению окно не закрывают, остаются крестик и «Отмена»; введённое сохраняется как черновик). Все окна закрываются одинаково.
- **Вложенность:** поверх всплывающего окна допускается только малое подтверждение (S); окно любого другого типа поверх всплывающего запрещено. Подтверждение лежит над затемнением, затемнение второго уровня темнее первого.
- Всплывающее окно не меняет адрес страницы (не подэкран); состояние формы хранится, пока открыто родительское окно.

### 3.4 Подсказка

- Только чтение: без кнопок и полей. Появляется у курсора при наведении с удержанием около 0,5 с, исчезает при уходе курсора; не перехватывает клики.
- Ширина до 320 px, фон `surface-raised`, граница `line`, скругление 8 px, тень `shadow-tip`. Не выходит за границы окна приложения: у правого края прижимается к краю.
- В подсказке — только сокращённые сведения (название, лидер, число провинций, столица) и строка «Нажмите на название, чтобы открыть …». Подсказка **не единственное место** важной информации: всё, что в ней, есть на экране или подэкране.
- Не проверено в настоящем ВК (наведение в окне ВК); проверка — единица 11 версии 0.9.0.
- Построена в единице 11: компонент `shared/ui/Tooltip`; открывается через 500 мс после наведения у места курсора и затем следует за курсором, пока тот не уйдёт с элемента; закрывается при уходе курсора, щелчке, прокрутке, Esc; рисуется внутри корневого контейнера (не `position: fixed`), у правого края прижимается к нему, у нижнего открывается над курсором; только наведение, на фокус с клавиатуры не реагирует.

## 4. Каркас и навигация

- **Верхняя полоса** — высота 48 px, фон `surface`, нижняя линия `line`. Слева логотип проекта (38 px) и надпись «PAX ATOMICA» (плакатный шрифт, п. 5.3), затем вкладки «Штаб · Реестр · Карта»; активная вкладка — цвет `ink` и линия `action` 2 px снизу, остальные — `ink-muted`. Справа метка текущего хода «ХОД N · Месяц Год» (заливка `signal`, текст `on-signal`, шрифт `figure`), за ней — маленькая кнопка темы (п. 5.4).
- Заменяет плавающие кнопки «Карта» и «Реестр». Регистрация (`#register`) открывается вместо Штаба, пока у игрока нет государства; в этом режиме вкладки «Реестр» и «Карта» остаются.
- **Ссылки бота и меню сообщества не меняются:** `#map`, `#registry`, `#registry/order-N`, `#register` открывают те же окна, что раньше; на каждую ссылку есть тест.
- Одно общее место показывает состояние загрузки, ошибки и пустоты (п. 7); экран не рисует их сам.
- Высота окна приложения управляется только из каркаса (п. 2).
- **Страница панели администратора (`/admin.html`, версия 0.11.0).** Панель открывается в отдельной вкладке браузера, вне окна ВК, поэтому правила п. 2 (ширина 910 px, высота по содержимому) на неё не действуют: страница занимает обычное окно браузера, ориентир макета — 1280 px, аккуратная раскладка — от 1024 px. Токены, шрифты, темы и переключатель темы — общие (п. 5). Каркас свой: верхняя полоса с логотипом 32 px, надписью «Пульт · панель администратора», счётчиком сеанса, меткой хода и кнопкой «Выйти»; левое меню разделов 232 px; адреса разделов — хеш-маршруты `#/turn` и далее; меню собирается из реестра `sections.ts`, а не зашито в каркас. Карточки состояний («Ссылка устарела», «Нет доступа», «Сеанс закончился», «Вы вышли из панели», «Нет связи с сервером») показываются по одной под минимальной верхней полосой. Макеты — `docs/06_DESIGN/0.11.0/` (экраны 02 и 09, обе темы).

## 5. Дизайн-токены

Источник — дизайн-система PAX ATOMICA (`tokens.json` в её артефакте). Реализация в коде — единственный файл токенов `frontend/src/shared/ui/tokens` (единица 5 версии 0.9.0); значения ниже — исходные. Цвета основаны на значениях VKUI (платформа VKCOM). Тёмная тема — основная.

### 5.1 Цвета (тёмная / светлая)

| Токен | Тёмная | Светлая | Где |
|:--|:--|:--|:--|
| `ground` | #141414 | #edeef0 | фон приложения за окнами |
| `surface` | #222222 | #ffffff | фон блоков, карточек, верхней полосы |
| `surface-raised` | #292929 | #ffffff | фон всплывающих окон, подсказок, плиток показателей |
| `surface-inset` | #333333 | #f0f2f5 | поля ввода, вторичные кнопки, чипы |
| `line` | #363738 | #dce1e6 | разделители (не рамка элемента управления) |
| `ink` | #e1e3e6 | #000000 | основной текст |
| `ink-muted` | #939393 | #626d7a | подписи (не на `surface-inset` в тёмной теме) |
| `ink-faint` | #828282 | #818c99 | значки, рамки полей, недоступное; не для текста |
| `action` | #71aaeb | #447bba | заливки и значки интерактивного |
| `link` | #71aaeb | #2a5885 | текст ссылок и текстовых кнопок |
| `signal` («латунь») | #e3b04b | #e3b04b | игровые состояния и фирменный знак; только заливка |
| `on-signal` | #241a06 | #241a06 | текст на заливке `signal` |
| `signal-ink` | #e3b04b | #7a5200 | текст и тонкие линии цвета латуни |
| `danger` | #ff5c5c | #b83232 | ошибки и опасные действия (всегда со словом) |
| `positive` | #4bb34b | #2a7230 | успех (всегда со словом) |
| `warning-bg` | #473315 | #fff2d6 | фон предупреждающей плашки |

Правила: цвета государств — самые яркие элементы экрана; рядом с образцом государства не ставится крупная заливка `signal` или `action`. `signal` не обозначает ошибку или предупреждение. Контраст текста ≥ 4,5 : 1 в каждой теме (проверено при подборе токенов); `ink-muted` не ставится на `surface-inset` в тёмной теме.

### 5.2 Отступы, скругления, тени, размеры

- Отступы: `space-1` 4, `space-2` 8, `space-3` 12, `space-4` 16, `space-5` 24, `space-6` 32 px.
- Скругления: `radius-sm` 4 (образцы цвета, метки), `radius-md` 8 (кнопки, поля, строки), `radius-lg` 12 (блоки, окна), `radius-pill` 999.
- Тени: `shadow-popup` (0 8px 24px, чёрный 50 % / 18 %), `shadow-tip` (0 4px 12px, 45 % / 16 %).
- Размеры: `win-screen` 910, `win-popup-s` 480, `win-popup-m` 640, `win-popup-l` 880, `win-tooltip-max` 320, `topbar-h` 48, `row-compact` 36 px; высота кнопки 36 px (малая — 32 px).

### 5.3 Шрифты и стили текста

- **Заголовки:** Fira Sans Condensed (400, 500; файлы в `frontend/public/assets/fonts/`). **Числа, даты, номер хода:** JetBrains Mono. **Основной текст:** системный стек VKUI (`-apple-system, BlinkMacSystemFont, Roboto, Helvetica Neue, arial`).
- **Надпись PAX ATOMICA:** плакатный шрифт Big Shoulders Display 800, разрядка 0,1 em, 24 px в верхней полосе (из Google Fonts; поставка и хостинг шрифта — решение единицы 5, предпочтительно файл в `frontend/public/assets/fonts/`, лицензия OFL). Пробный выбор, может быть заменён по решению Project Owner.
- Стили: `title-uppercase` 18–24 px, 500, верхний регистр, разрядка 0,06 em; `display-lg` 26/30 (название государства); `heading` 16/20; `body` 14/20; `caption` 12/16; `label` 11/14 верхний регистр с разрядкой 0,06 em; `figure` 14/20 моноширинный; `figure-lg` 22/28.
- Заголовок блока окна: значок блока (`signal`), текст `title-uppercase`, тонкая линия `line` справа на всю оставшуюся ширину.

### 5.4 Переключатель темы

- Тема приложения не обязана совпадать с темой ВК: следует ли приложение за переключением темы во ВК, не проверено (сейчас приложение не передаёт VKUI параметр `appearance`). Поэтому в верхней полосе правее метки хода стоит маленькая ненавязчивая кнопка темы: значок 18 px цвета `ink-muted`, область нажатия 32 × 32 px, `radius-md`.
- Три режима: «Авто» (приложение следует теме ВК, если ВК её сообщает; иначе — тёмная), «Светлая», «Тёмная». Нажатие переключает режимы по кругу; значок показывает действующую тему (луна или солнце; в режиме «Авто» рядом точка), всплывающая подпись (атрибут `title`) называет режим: «Тема: авто / светлая / тёмная». Меню и всплывающих окон для этого нет.
- Выбор запоминается в браузере (`localStorage`, ключ `pax.theme`, чтение и запись в `try/catch`); если хранилище недоступно, выбор действует до закрытия окна. Без выбора — «Авто».
- Тема включается в одном месте: атрибутом на корневом элементе приложения и параметром `appearance` у `ConfigProvider` VKUI; все цвета — токены п. 5.1.
- Не проверено в настоящем ВК: сообщает ли ВК приложению свою тему (событие `VKWebAppUpdateConfig`, поле `scheme`) и меняет ли её при переключении во ВК; проверяется в приёмке единицы 5 версии 0.9.0.

## 6. Собственные элементы

Единицы 5–11 версии 0.9.0 собирают их в `frontend/src/shared/ui/`; прочие элементы — VKUI.

1. **Верхняя полоса** (п. 4).
2. **Заголовок блока** (п. 5.3): значок + текст + линия. Значок — простой линейный (18 px, штрих 1,6 px, цвет `signal`, в светлой теме `signal-ink`) по смыслу блока: «Глава государства» — силуэт человека, «Территория» — сложенная карта, «Описание» — строки текста, «Приказы» и окна приказов — лист документа, «Вердикт» и окна вердиктов — весы (вердикт), «Реестр» — список. Новый блок получает значок того же вида; значки лежат в `frontend/src/shared/ui/icons` (единица 5).
3. **Плитка показателя:** `surface-raised`, граница `line` 1 px, `radius-lg`; подпись `label` сверху, значение `figure-lg` снизу; ключевое число (например, судейский рейтинг) цвета `signal`.
4. **Метка хода:** заливка `signal`, текст `on-signal`, шрифт `figure` 12 px, `radius-sm`.
5. **Полоса возврата подэкрана** (п. 3.2).
6. **Чип провинции:** `surface-inset`, `radius-sm`, отступы 2 × 8; чип столицы — звёздочка «★» и цвет `signal-ink`, всегда первый. Пояснительной подписи «★ — столица» нет: звёздочка понятна без неё.
7. **Образец цвета государства:** квадрат 16 px, `radius-sm`, граница `swatch-edge`; рядом HEX шрифтом `figure`.
8. **Портрет и флаг:** флаг 96 × 64 (на карточке) или 32 × 22 (в строке), портрет 72 × 88 (блок главы) или 22 × 22 круг (в строке таблицы); до появления настоящих картинок — заглушки в цвете `surface-inset`.
9. **Всплывающее окно** трёх размеров (п. 3.3), **Подсказка** (п. 3.4), **Подтверждение** (малое всплывающее окно с кратким перечнем).
10. **Загрузка, ошибка с «Повторить», пустое состояние, всплывающее сообщение об успехе** (п. 7).
11. **Поле ввода** (`TextField`/`TextArea`, единица 8 версии 0.9.0): строка подписи стилем `label` (верхний регистр, `ink-muted`); «*» после названия — единственный знак обязательного, слово «необязательно» не пишется; справа счётчик «N / M», когда лимит известен. Поле: `surface-inset`, `radius-md`, высота 36 px (однострочное), многострочное — по числу строк. Ошибка под полем текстом `danger` со значком и рамкой поля `danger`; подсказка — мелким текстом `ink-muted`. Вторая строка «до N символов» под полем не ставится — счётчик сверху уже назвал лимит. Флаг 22 × 14 в ячейке и метке (`cell`), 28 × 19 в заголовке подсказки (`tip`), 48 × 32 в строке подэкрана «Игрок» (`sub`), скругление 2 px (4 px у `sub`), `object-fit: cover`; нет флага или ошибка загрузки — блок того же размера в цвете государства (не точка), нет и цвета — заглушка флага. Единый вид везде, где показывается государство; на карте — только краткие названия без флагов.

## 7. Состояния и сообщения

- **Загрузка.** Один компонент-индикатор для всех мест; блок на время загрузки сохраняет свою высоту, чтобы окно не «прыгало».
- **Ошибка сети и сервера.** Один компонент: слово «Ошибка» в `danger`, текст причины по-русски, кнопка «Повторить». Фраза по умолчанию: «Ошибка сети — попробуйте ещё раз.» Живёт в одном месте; повторять её текст по файлам запрещено. Тексты ошибок по кодам сервера — единый словарь на клиенте (единица 9 версии 0.9.0), структура рассчитана на будущие файлы локализации. Английский текст сервера игроку не показывается никогда: все тексты — в одном словаре `frontend/src/shared/texts/errors.ru.ts`.
- **Пустое состояние.** Короткая фраза и, если есть, действие («Приказов на рассмотрении нет»). Пустая таблица выглядит так же во всех таблицах.
- **Успех.** Одно общее всплывающее сообщение у верха окна приложения, под верхней полосой (внизу высокого окна его не увидеть), с галочкой и текстом цвета `positive`, исчезает через 4 секунды или по клику: «Государство создано», «Изменения сохранены», «Приказ №N подан», «Вердикт по приказу №N записан».
- **Ошибка поля** — у поля, текстом `danger` и значком; в форме с вкладками — отметка на вкладке, где ошибка.
- **Блокировка.** Недоступное действие — кнопка в состоянии «неактивна» с причиной в подсказке или подписи рядом.

## 8. Правила текстов

- По-русски, коротко, без жаргона программистов. Кнопка называется действием («Подать приказ»), не «ОК».
- Порядок кнопок в окнах один: главное действие справа, отмена слева. Опасное действие — `danger`.
- Согласованные подписи: «Глава государства» (блок лидера), «Территория» (блок провинций), «Описание», «Приказы», «Мои приказы» и «Приказы других игроков» (значки «Штаба»), «Назначены мне» (фильтр Реестра), «Дата регистрации» (столбец Реестра), «Подать приказ», «Отправить приказ?», «Вернуться к правке».
- Лидер показывается без подписей строк: имя крупно, должность заглавными под ним цветом `signal-ink`, биография текстом ниже.
- Провинции — только названиями; столица всегда первой, со звёздочкой, в любом списке провинций государства (карточка, подсказка, Реестр, регистрация). Если название столицы отличается от названия её провинции, чип показывает «★ Название столицы (Название провинции)».
- Игровая дата — «Месяц Год»; номер хода — шрифтом `figure`.
- Служебные сведения не показываются игроку: идентификаторы и номера провинций, пол лидера, состояние уведомлений, коды ошибок.

## 9. Окна приложения (образцы)

Макеты: артефакт «PAX ATOMICA — макеты окон» (утверждены 20.10.2026). Ниже — состав; точный вид — по макету.

### 9.1 Штаб (экран «Карточка государства»)
Верхняя полоса. Шапка: флаг 96 × 64, над названием (`display-lg`) мелкая строка с кратким названием — без слов «Кратко:» —, девиз курсивом, образец цвета и HEX; справа кнопка «Изменить». Ряда плиток нет (версия 0.10.0): уровень и судейский рейтинг — показатели игрока — ушли на подэкран «Игрок» (п. 9.7), а числа приказов — в значки блока «Приказы». Два блока в ряд (3 : 2): «Глава государства» (портрет 72 × 88, имя, должность, биография) и «Территория» (чипы провинций, столица первой). Блок «Описание». Блок «Приказы»: заголовок с кнопкой «Подать приказ» справа; ниже две карточки в ряд (доска 08) — «Мои приказы» (число моих поданных приказов без вердикта, подпись «Ждут вердикта») и «Приказы других игроков» (число назначенных мне на суд, подпись «Нужно написать вердикт»): `surface-raised` карточка с рамкой `line`, слева плитка-иконка 44 px `surface-inset`, латунный кружок числа в её правом верхнем углу (ноль — без кружка, 100 и больше — «99+», неудачная загрузка — без числа и без окна ошибки), название и серая строка-подпись, справа шеврон `ink-faint`. Щелчок по карточке открывает Реестр на вкладке «Приказы» с предустановкой фильтра («Мои приказы» — список «Государство» = краткое название моего государства; «Приказы других игроков» — «Назначены мне» = «Да»; Spec `03_registry`, вход с предустановкой). Списка «Ожидают вердикт» в «Штабе» нет: путь судьи — карточка → вкладка «Приказы» → строка → окно приказа. Игрок без государства карточек не видит. Кнопки «Удалить государство» у игрока нет. Названия провинций берутся из `GET /api/v1/map/province-names` (`useProvinceNames`; версия 0.10.0, единица 11 — лёгкий ответ названий вместо полного манифеста карты); если данных нет — нейтральная заглушка. Пол, уведомления, способ смены лидера и гимн на карточке не показываются. Ссылка на историю — в блоке «Описание».

### 9.2 Реестр (экран)
Верхняя полоса (вкладка «Реестр»). Заголовок «РЕЕСТР» (Fira Sans Condensed 24/28, верхний регистр, иконка списка `signal-ink`) и рядом сегмент-вкладки «Игроки / Государства / Приказы» — пилюли `surface`, активная `surface-inset` (доски 09–10б). Строка инструментов: поиск 240 px, «Показано N из M» (`ink-muted`), «Фильтры», «Обновить», «Сбросить». Таблица: «№, Игрок, Регистрация, Уровень, Рейтинг, Государство» (заголовки стилем `label`, числа и даты — JetBrains Mono, рейтинг — `signal-ink`; строка при наведении — `surface-raised`). Названия государств — кнопки-ссылки обычного цвета `ink` во всех таблицах и на подэкране «Игрок» (решение Project Owner 24.10.2026; цветной остаётся только ссылка-название приказа в таблице «Приказы»). Рейтинг показан числом со знаком; шкала видна в подсказке к числу («<число> · шкала −100…+100») и в полях фильтра («от −100» / «до +100»). Панель «Фильтры» — строгая сетка из трёх равных колонок: одна группа = одна ячейка = подпись + один ряд полей высотой 36 px; фильтр «наличие» — своя ячейка «<столбец>: наличие» сразу после ячейки столбца (макет 09c). Наведение на государство или игрока — подсказка (п. 3.4). Высота таблицы — не более 720 px, дальше прокрутка внутри таблицы (заголовок остаётся на месте). Щелчок по государству открывает подэкран «Государство» (единица 14), щелчок по игроку — подэкран «Игрок» (п. 9.7, версия 0.10.0).

### 9.3 Подэкран «Государство» (из Реестра)
Построен в единице 14, вид по макетам доски 11 (утверждены 23.10.2026). Адрес — `#registry/nation-<id>` (`<id>` — идентификатор государства). Полоса возврата: кнопка «← Реестр» и цепочка «Реестр / Государства / Название» (при переходе из таблицы — вкладка той таблицы; имя игрока в цепочку не входит). Состав: шапка с флагом, кратким названием над полным, девизом, образцом цвета и HEX, справа кнопка «Показать на карте»; два блока в ряд — «Глава государства» (портрет, имя, должность, биография) и «Территория» (чипы провинций, столица первой, справа число провинций); блок «Описание» со ссылкой на историю. Плиток показателей, блока «Приказы» и кнопки «Изменить» нет (с единицы 13 ряд плиток убран по макетам). Названия провинций — тем же хуком `useProvinceNames` (`GET /api/v1/map/province-names`), столица первой. Образец — макеты доски 11.

### 9.4 Всплывающие окна приказов
«Подать приказ» (M, 640): строка «Неразрешённых приказов: N из 5», поля «Название» (счётчик «0 из 100»), «Краткая суть приказа» (0 из 500), «Ссылка на статью ВК» (0 из 200); действия: «Отмена» слева, «Отправить приказ» справа (неактивна, пока обязательные поля пусты). «Отправить приказ?» (S, 480): предупреждение «Проверьте приказ: изменить его после подачи нельзя», перечень значений, «Вернуться к правке» слева, «Да, отправить» справа. Вердикт и просмотр приказа — M и L по этим же правилам.

### 9.5 Карта
Экран без ограничения ширины. Внутренности карты не меняются (вне версии 0.9.0). Панель карты в окне высотой 780 px (сама карта около 640 px); полноэкранный режим карты («Развернуть на весь экран») во ВК работает (проверено 19.10.2026). В каркасе карта получает обычную рамку экрана и общую верхнюю полосу; собственные кнопки «Назад» и плавающие кнопки убираются.

### 9.6 Регистрация государства (экран)
Четыре вкладки: «Основные данные и символика», «Глава государства», «История» (одно поле — ссылка на историю государства), «Территории»; вид — по правилам этого файла: заголовки блоков, поля одной ширины, ошибка у поля, отметка на вкладке. Окно «Выбор провинций» — особое всплывающее окно.

Правила полей: название до 50, краткое до 16, девиз до 60, описание до 100 (поле описания выше поля девиза), имя и должность лидера до 60, биография до 500, столица 2–40; значок «обязательное» — только звёздочка у названия поля, слов «необязательно» нет; счётчик «0 из N» только над полем; флаг и портрет обязательны, первый из каталога выбран заранее; пол — два значка (копьё Марса, зеркало Венеры); Enter в любом поле не отправляет форму, в многострочных полях делает перенос строки; гимна нет.

Вкладка «Территории»: названия провинций; столица первой, «Сделать столицей»; в правке — только чтение. Эти же компоненты — форма правки государства.

### 9.7 Подэкран «Игрок» (из Реестра)

Построен в версии 0.10.0 (единица 8, доски 12 и 12б). Адрес — `#registry/player-<N>` (`<N>` — публичный номер игрока в Реестре, 1–9 цифр: ключ строки `p<N>` таблицы «Игроки» без `p`); голый хэш `#registry/player-<N>` нормализуется так же, как адрес государства, испорченный номер ведёт на обычный Реестр без ошибки. Полоса возврата: кнопка «← Реестр» и цепочка «Реестр / Игроки / имя» (вкладка приезжает состоянием маршрута при переходе из таблицы, по голой ссылке — «Игроки»). Один запрос — `GET /registry/players/{number}` (Spec `03_registry` 5.6) — и три блока (доска 12): карточка-шапка `surface`/`radius-lg` (круглая аватарка ВК 96 px либо нейтральный силуэт при `avatar_url = null`, `is_fallback` или ошибке загрузки; надпись «ИГРОК» стилем `label` над именем в `display-lg` — запасное при `is_fallback`), ряд из трёх плиток — «РЕГИСТРАЦИЯ» (`joined.text`, моноширинная), «УРОВЕНЬ», «РЕЙТИНГ» (число `signal-ink`, без шкалы) — и карточка «ГОСУДАРСТВО»: флаг 48 × 32 и краткое название строкой-ссылкой с шевроном на подэкран «Государство» `#registry/nation-<id>` при `id`; при `id = null` — обычный текст без шеврона. Игрок без государства: строка «Государства нет», без флага и ссылки (доска 12б). Идентификаторы `player_id` и `vk_user_id` не показываются нигде. Состояния: загрузка — общий `LoadingState`; `404` — «Игрок не найден» со своей кнопкой «← Реестр»; прочие ошибки — общий `ErrorState` с «Повторить», сырые коды не показываются. Вход: щелчок по ячейке `person` в любой таблице Реестра (кликабельна только при ключе строки `p<N>`, номер не угадывается), подсказка игрока (п. 3.4, доска 9б: те же сведения, что в шапке подэкрана, и строка «Нажмите на имя, чтобы открыть игрока»), прямая ссылка. Образец — макеты досок 12 и 12б.

## 10. Чек-лист Issue «Интерфейс» (для любого модуля и расширения)

Issue «Интерфейс» входит в Roadmap каждого модуля и расширения, идёт **после** Spec и Roadmap и **до** кода экрана. Определение готовности:

1. **Состав окон** модуля: какие экраны, подэкраны, всплывающие окна и подсказки получает игрок; тип каждого определён по п. 3.
2. **Макет** каждого нового окна (Lead AI делает в инструменте Design на дизайн-системе PAX ATOMICA); Project Owner утверждает вид; утверждённые макеты ссылаются из Roadmap.
3. **Тексты:** подписи по п. 8; нет служебных сведений; ошибки — через общий словарь.
4. **Размеры:** экран ≤ 910 px, всплывающее окно — S/M/L, подсказка ≤ 320 px; горизонтальной прокрутки нет.
5. **Общие элементы:** используются компоненты `frontend/src/shared/ui/`; новый собственный элемент сначала вносится в п. 6 этого файла и в дизайн-систему, потом в код.
6. **Состояния:** загрузка, ошибка с «Повторить», пустое состояние, успех — через общие компоненты.
7. **Темы:** оба состояния ВК (тёмная, светлая) — только через токены.
8. **Навигация и ссылки:** адрес нового окна, возврат, предел вложенности; ссылки бота не сломаны.
9. **Проверка в настоящем ВК:** Project Owner смотрит окно по чек-листу ручных действий, приёмка фиксируется в файле версии.
