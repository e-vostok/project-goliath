## F1 — Передаёт ли ссылка `vk.com/app{APP_ID}#<fragment>` фрагмент в мини-приложение; канонический домен

- Status: VERIFIED (с оговорками UNVERIFIED)
- Fact: На странице «Параметры запуска» (раздел мини-приложений, раздел «Передача произвольных параметров → Запуск по прямой ссылке») документировано: «вы можете передавать произвольные параметры в игру или мини-приложение… укажите параметры после символа `#` в адресной строке, например `https://vk.com/app1234567#param1=12345`. Символы после `#` будут переданы игре в URL-параметре `hash`. Этот параметр всегда идёт последним среди остальных передаваемых параметров». Чтение — «с помощью свойства `hash` объекта `window.location`»; отслеживание изменений — события `VKWebAppLocationChanged` и `VKWebAppChangeFragment`. Знак `?` в прямой ссылке для передачи параметров «не работает» — только `#`. Тот же механизм у кнопки клавиатуры `open_app`: её параметр `hash` «будет передан в строке параметров запуска после символа `#`» (см. факт V9 в `02_bot_vk_facts.md`). Документация не ставит передачу `hash` в зависимость от источника перехода (сообщение, адресная строка, закладка) — фрагмент является частью самой ссылки. Отдельного описания именно клика по такой ссылке из текста сообщения сообщества нет — UNVERIFIED-фрагмент (переход может сопровождаться сниппетом/обёрткой, см. F2).
- Fact (домен): Канонический домен платформы — `vk.ru`: официальная документация VK ID предписывает с 30.09.2025 замену `vk.com` → `vk.ru` во всех адресах (`id.vk.ru`, `oauth.vk.ru`, `api.vk.ru`); событие `VKWebAppGetConfig` возвращает `api_host: api.vk.ru`; правила платформы и панель управления используют адреса `vk.ru/...` и `dev.vk.ru`. При этом формат ссылки на приложение задокументирован на обоих доменах: примеры `vk.com/app{id}` — на страницах «Размещение», «Параметры запуска», «Первые шаги», а `vk.ru/app{APP_ID}_-{VK_GROUP_ID}` — на странице плагинов для сообществ. Передача `#`-фрагмента конкретно по ссылке `vk.ru/app{id}#...` отдельно не описана — UNVERIFIED-фрагмент.
- Source: https://dev.vk.com/ru/mini-apps/development/launch-params («Передача произвольных параметров», «Запуск по прямой ссылке»), https://dev.vk.com/ru/api/bots/development/keyboard/key-types (`open_app`, параметр `hash`), https://id.vk.ru/about/business/go/docs/ru/vkid/latest/vk-id/connection/migration/migration-to-vkru, https://dev.vk.com/ru/bridge/VKWebAppGetConfig (`api_host`), https://dev.vk.com/ru/plugins/creating-and-settings (ссылка `vk.ru/app{APP_ID}_-{VK_GROUP_ID}`), https://dev.vk.com/ru/mini-apps/settings/general/placement (`vk.com/app{id}`)
- Spec impact: запланированный дизайн держится: ссылка вида `https://vk.ru/app{APP_ID}#registry/order-12` опирается на документированный механизм `hash`; клиент читает `window.location.hash` (или `VKWebAppGetLaunchParams`) и роутит на приказ. Домен в ссылке — `vk.ru` (канонический); `vk.com`-вариант оставить запасным в коде формирования URL. Оговорки: доставку фрагмента при клике именно из сообщения и по `vk.ru`-ссылке закрепить ручной проверкой в чек-листе Project Owner. Запасной вариант из TZ (номер приказа + подсказка «Реестр → Приказы», ссылка просто открывает приложение) сохранить в тексте независимо от результата — он же нужен пользователям без доступа (F3).

## F2 — Кликабельность и обработка ссылки `vk.com`/`vk.ru` в тексте сообщения `messages.send`

- Status: VERIFIED (с оговорками UNVERIFIED)
- Fact: Ссылки в тексте сообщения — штатная механика: параметр `dont_parse_links` существует именно для управления «сниппетом ссылки из сообщения» (`0` — создать сниппет, `1` — не создавать); официальная справка подтверждает дословно: «чтобы отправить сообщение со сниппетом ссылки, передайте `dont_parse_links=0`, а саму ссылку — в `message`». В объекте личного сообщения есть `format_data.items[]` с типом `url` (диапазон текста + адрес ссылки) — ВК распознаёт и хранит ссылки внутри текста. Правила для ботов (п. 4.1) исходят из того, что бот может предлагать пользователю ссылки; запрет касается только ссылок на «другие сообщества или сайты, не имеющие прямого отношения к боту» — ссылка на собственное мини-приложение под запрет не подпадает. Дословного утверждения «URL в тексте кликабелен» нет, но механика сниппета и `format_data.url` подтверждают, что ссылки в `message` парсятся и отображаются как ссылки.
- Fact (блокировки и предупреждения): ВК документированно проверяет переходы по внешним ссылкам: официальная справка «Why does VK block links to external websites?» — «мы закрываем переходы на сайты, которые не советуем посещать», пользователь видит заглушку, снятие блока — через Поддержку; сама dev.vk.com оформляет внешние ссылки обёрткой `https://vk.ru/away.php?to=...`. Освобождение внутренних ссылок `vk.com`/`vk.ru` (на `app{id}`) от проверки `away.php`/предупреждений документацией прямо не описано — UNVERIFIED-фрагмент; переписывание текста ссылки в сообщении также не описано.
- Source: https://dev.vk.com/ru/method/messages.send (`dont_parse_links`), https://vk.com/faq11772 (сниппет ссылки через API), https://dev.vk.com/ru/reference/objects/message (`format_data`, тип `url`), https://dev.vk.com/ru/bots-rules (п. 4.1), https://vk.com/faq18504 (блокировка внешних ссылок), https://dev.vk.com/ru/mini-apps/settings/managers (внешняя ссылка обёрнута в `vk.ru/away.php?to=...`)
- Spec impact: дизайн держится — ссылка на `vk.ru/app{id}` является внутренней ссылкой платформы и относится к боту прямо (п. 4.1 не нарушается). Гарантированного отсутствия предупреждения/обёртки для неё документация не обещает, поэтому текст уведомления обязан быть самодостаточным (номер приказа + «Реестр → Приказы») — это совпадает с запланированным фолбэком. Рекомендация для Spec: отправлять с `dont_parse_links=1`, чтобы ссылка не разворачивалась в карточку-сниппет (см. F4).

## F3 — Что видит пользователь без доступа по ссылке на отключённое приложение; официальный доступ для тестировщиков

- Status: VERIFIED (с оговорками UNVERIFIED)
- Fact: Состояние «Отключено» — статус мини-приложения сразу после создания: «приложение с таким состоянием доступно только администраторам. Они могут запускать мини-приложение по прямой ссылке `https://vk.com/app{id}`»; архивная справка старой панели формулирует так же: «приложение отключено — не видно никому, кроме администратора мини-приложения». Официальных способа дать доступ конкретным пользователям до публикации два, оба документированы: (1) **Настройки → Администраторы** — добавить пользователя администратором с частичным доступом и правом «Тестирование»; это право «даёт возможность запускать на всех подключённых площадках мини-приложение, у которого состояние для пользователей установлено в Отключено», а из настроек ему доступен только раздел «Доступ к приложению»; (2) **Настройки → Тестовые группы** — создать группу и включить в неё пользователя (ограничения: до 25 групп, добавлять можно только пользователей ВКонтакте; группе можно назначить свой URL загрузки, который имеет наивысший приоритет). Управлять списками могут создатель и администраторы с полным доступом. Страница «Первые шаги» называет второй раздел «Тестирование» — расхождение имён зафиксировать в чек-листе как «Настройки → Тестовые группы / Тестирование».
- Fact (экран без доступа): Что именно увидит пользователь без доступа после клика по `vk.com/app{id}` (страница-заглушка «приложение отключено», пустой экран, ошибка) — ни dev.vk.com, ни справки `vk.com/faq*` прямо не описывают. UNVERIFIED-фрагмент: задокументировано только следствие — приложение ему недоступно.
- Source: https://dev.vk.com/ru/mini-apps/settings/general/placement («Состояние для пользователей»), https://dev.vk.com/ru/mini-apps/getting-started («По умолчанию мини-приложение отключено для пользователей…»), https://dev.vk.com/ru/mini-apps/settings/managers (право «Тестирование», раздел «Администраторы»), https://dev.vk.com/ru/mini-apps/settings/test-groups (создание, ограничения), https://dev.vk.ru/ru/mini-apps/management/settings (архив: «не видно никому, кроме администратора»)
- Spec impact: дизайн держится: до включения приложения ссылкой могут воспользоваться только администраторы и тестировщики — это штатный контур разработки. Для Spec оформить чек-лист Project Owner: добавить тестировщиков через Настройки → Администраторы (право «Тестирование») И/ИЛИ Настройки → Тестовые группы. Так как экран для пользователя без доступа недокументирован, текст уведомления обязан быть понятным без перехода по ссылке — запланированный фолбэк обязателен, а не опционален.

## F4 — Лимиты `messages.send`: длина текста, ссылки в сообщении, показ ссылки без превью

- Status: VERIFIED (с оговорками UNVERIFIED)
- Fact: Максимальная длина параметра `message` — **9000 символов** («Макс. длина = 9000» на странице метода; при превышении — ошибка 914 «Message is too long»). Документированного лимита на количество ссылок в одном сообщении нет: ни в параметрах, ни в списке кодов ошибок (911–1021) такого ограничения не зафиксировано — UNVERIFIED-фрагмент (фактическим потолком остаётся длина текста). Показ без превью: параметр `dont_parse_links` — `1` «не создавать сниппет ссылки из сообщения», `0` «создать сниппет»; официальная справка faq11772 подтверждает семантику. Ранее подтверждённые пределы того же метода остаются в силе: до 20 запросов/с на ключ сообщества и до 100 получателей в `peer_ids`/`user_ids` (факты V5/V14 в `02_bot_vk_facts.md`).
- Source: https://dev.vk.com/ru/method/messages.send (`message` — «Макс. длина = 9000», `dont_parse_links`, «Коды ошибок»), https://vk.com/faq11772 (сниппет через `dont_parse_links`), https://dev.vk.com/ru/api/bots/development/messages (20 запросов/с, до 100 получателей)
- Spec impact: дизайн держится: текст уведомления (номер приказа + подсказка + ссылка) на порядки короче 9000 символов; ссылку отправлять с `dont_parse_links=1`, чтобы она не разворачивалась в сниппет-карточку (если превью понадобится — `0`, механизм документирован в обе стороны). Лимита «число ссылок в сообщении» нет — одна ссылка на приложение заведомо безопасна.
