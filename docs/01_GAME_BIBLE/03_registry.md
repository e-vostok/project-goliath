# 03_registry.md

## ОБЩАЯ ЧАСТЬ

### 0. Назначение и принципы

Реестр — справочник мира: игрок видит, кто в игре, какие государства существуют и чем они различаются. Это окно только для чтения: оно ничего не решает и ничего не меняет в игре.

Принципы:

- **Реестр только читает.** Данные принадлежат другим модулям; Реестр получает их через их публичные функции и никогда не изменяет. Единственные собственные данные Реестра — сохранённые имена и аватарки профилей ВК.
- **Сервер — источник истины.** Содержимое таблиц, порядковые номера и числа считает сервер. Клиент только упорядочивает и отбирает уже полученные строки.
- **Таблицы описываются, а не рисуются.** Состав таблиц и столбцов задаётся конфигом. Добавление столбца с уже существующими данными не требует правки интерфейса. Новые данные подключает модуль-владелец, не меняя интерфейс Реестра.
- **Сбой ВК не ломает окно.** Имена и аватарки приходят от ВК отдельно от открытия таблицы. Если ВК недоступен, таблица открывается с запасным видом профиля.
- **Заглушка — штатное состояние.** Где механики ещё нет, столбец существует и показывает одинаковое значение у всех. В конфиге такой столбец помечен как заглушка; когда механика появится, меняется источник значения, а не вид таблицы.
- **Реестр отражает состояние на момент загрузки.** Он не обновляется сам; актуальность — в момент открытия вкладки и по кнопке «Обновить».

### 1. Окно, вкладки и вход

**Окно.** «Реестр» — отдельный экран приложения. В самом верху окна расположен ряд иконок-вкладок; одна вкладка соответствует одной таблице. Ниже ряда — блок активной таблицы. Расположение ряда вкладок — решение интерфейса, которое Project Owner может изменить позднее (раздел «Принятые решения»).

**Вкладки.**
- Триггер: игрок нажимает иконку вкладки.
- Условие: вкладка существует в описании таблиц.
- Эффект: активная вкладка выделяется, блок ниже показывает соответствующую таблицу. При наведении на иконку показывается название таблицы.

При каждом открытии окна активна первая вкладка — «Игроки».

**Вход.**
- Триггер: игрок нажимает временную кнопку «Реестр» на главном экране.
- Условие: игрок вошёл в приложение. Наличие государства не требуется: окно доступно и игроку без государства, в том числе на экране регистрации.
- Эффект: открывается окно «Реестр». Кнопка «Назад» возвращает на экран, с которого окно открыто.

Кнопка входа временная и убирается вместе с настоящей навигацией приложения.

### 2. Общие правила таблиц

**2.1. Открытие таблицы.**
- Триггер: игрок открывает вкладку.
- Условие: связь с сервером есть.
- Эффект: клиент получает описание таблицы и все её строки и показывает их в порядке по умолчанию (для обеих таблиц — по порядковому номеру по возрастанию).

**2.2. Прокрутка.** Таблица прокручивается вверх и вниз внутри собственного блока. Высота окна приложения от числа строк не зависит: блок занимает отведённое ему место, а не растягивает окно. Шапка таблицы остаётся на месте при прокрутке.

**2.3. Сортировка.**
- Триггер: игрок нажимает на заголовок столбца.
- Условие: столбец помечен в описании как сортируемый.
- Эффект: первое нажатие — по возрастанию, второе — по убыванию, третье снимает сортировку и возвращает порядок по умолчанию. Одновременно действует сортировка одного столбца. Направление показано значком в заголовке. Пустые значения всегда стоят в конце списка при любом направлении. Текст сортируется по правилам русского алфавита без учёта регистра.

**2.4. Фильтры.**
- Триггер: игрок открывает фильтр столбца и задаёт условие.
- Условие: столбец помечен в описании как фильтруемый; вид фильтра зависит от типа данных столбца: для текста — «содержит», для чисел и дат — диапазон «от и до», для признака «есть / нет» — выбор значения.
- Эффект: в таблице остаются строки, подходящие под условия всех заданных фильтров одновременно. Столбец с действующим фильтром отмечен в шапке. Над таблицей показано «Показано N из M».

**Общий поиск.** Поле над таблицей отбирает строки по вхождению введённого текста в любой из текстовых столбцов, помеченных как поисковые (для «Игроков» — имя игрока и государство, для «Государств» — название). Поиск действует совместно с фильтрами. Кнопка «Сбросить» снимает поиск и все фильтры.

**2.5. Порядковый номер.** Номер принадлежит строке, а не позиции в текущей сортировке: при любой сортировке или фильтре номер строки не меняется. Сортировка по номеру возвращает порядок по умолчанию. Правила нумерации — у каждой таблицы свои (разделы 3 и 4).

**2.6. Актуальность.**
- Триггер: игрок открывает вкладку или нажимает «Обновить».
- Эффект: данные запрашиваются заново; сортировка и фильтры сохраняются.
- Во время открытого окна данные сами не меняются, в том числе при наступлении времени смены хода.

**2.7. Сохранение вида в сеансе.** Сортировка, фильтры и поиск каждой вкладки сохраняются при переключении между вкладками, пока окно «Реестр» открыто. При закрытии окна они сбрасываются.

**2.8. Расширяемость.** Состав вкладок и столбцов задаётся описанием таблиц в конфиге. Администратор может без правки интерфейса: добавить столбец, данные которого уже есть в системе; убрать столбец; изменить порядок, заголовок и ширину столбцов; включить или выключить сортировку, фильтр и поиск столбца. Изменение вступает в силу при следующем запуске сервера. Новый вид данных появляется в таблице, когда модуль-владелец этих данных подключает источник значения; таблица и интерфейс при этом не переписываются. Новая таблица добавляется описанием и источником строк.

### 3. Таблица «Игроки»

**Состав.** Все, кто хотя бы раз входил в приложение: учётная запись создаётся при первом входе. В таблице есть игроки с государством и без государства. Люди ВК, ни разу не открывавшие приложение, системе неизвестны и в таблице отсутствуют.

**Столбцы:**

- **№** — постоянный порядковый номер по порядку присоединения: первый вошедший в приложение получает номер один. Номер не меняется и не переиспользуется, так как игроки не удаляются.
- **Игрок** — малая аватарка и имя профиля ВК (имя и фамилия). Правила получения и запасной вид — раздел 5. Поиск включён, сортировка по имени.
- **Дата регистрации** — календарная дата первого входа в приложение (реальная дата, не игровая); отражает стаж игрока в проекте. Сортировка и фильтр по периоду.
- **Уровень** — целое число, начиная с первого. Заглушка: у всех игроков значение «1». Сортировка и фильтр по диапазону.
- **Судейский рейтинг** — шкала от −100 до +100 с нулевой точкой по умолчанию. Заглушка: у всех игроков значение «0». Рейтинг показан числом со знаком; границы шкалы показаны в подсказке к числу и в полях фильтра; полоса-шкала убрана по макетам 09/12 (утверждены 23.10.2026). Сортировка и фильтр по диапазону.
- **Государство** — название государства игрока с цветовой меткой его цвета; у игрока без государства — прочерк. Поиск включён; фильтр по тексту и по признаку «есть / нет государства».

**Порядок по умолчанию:** по номеру, по возрастанию.

---

### 4. Таблица «Государства»

**Состав.** Все существующие государства. Удалённое государство из таблицы исчезает при следующей загрузке.

**Столбцы:**

- **№** — порядковый номер по порядку формирования среди существующих государств (раньше сформированное — меньше номер; при равенстве — по времени создания). Если государство удалено, номера сформированных позже сдвигаются вверх.
- **Название** — название государства. Поиск включён, сортировка по алфавиту.
- **Флаг** — малое изображение флага. Заглушка: однотонный квадрат цвета государства. Когда появится загрузка флагов, на этом месте показывается загруженный флаг; у государства без флага остаётся цветной квадрат.
- **Дата формирования** — игровая дата хода, на котором государство было создано, записанная словами по-русски. Сортировка и фильтр — по моменту формирования (ход создания). Государства, созданные до появления Реестра, получают приблизительную дату по журналу ходов (ход, ближайший к времени их создания).
- **Провинции** — число провинций суши, которыми государство владеет в момент загрузки. Морские зоны не считаются: они не могут принадлежать государству. Сортировка и фильтр по диапазону.

**Порядок по умолчанию:** по номеру, по возрастанию.

---

### 5. Имя и аватарка профиля ВК

Мини-приложение получает данные только о текущем игроке. Имена и аватарки остальных игроков Реестр получает с серверов ВК на стороне сервера и хранит у себя.

**Получение.**
- Триггер: игрок появился в системе, либо сохранённый профиль устарел по сроку, заданному в конфиге.
- Условие: ВК доступен и отвечает.
- Эффект: имя, фамилия и малая аватарка запрашиваются у ВК, сохраняются и показываются при следующих открытиях таблицы без задержки. Смена имени или фото в ВК отражается в Реестре не позже срока обновления.

**Игрок не ждёт ВК.** Таблица всегда открывается сразу, значения берутся из сохранённых данных. Получение профиля идёт в фоне и не участвует в расчёте хода: сбой ВК не может помешать смене хода.

**Запасной вид.**
- Профиль ещё не получен: подпись «Игрок №N» (N — порядковый номер) и нейтральная аватарка-заглушка.
- ВК недоступен, а ранее профиль был получен: показывается последнее известное имя и аватарка.
- Страница игрока удалена или заблокирована: показывается последнее известное имя; если его нет — «Игрок №N»; аватарка нейтральная.

Имя и аватарка видны всем, кто вошёл в приложение, независимо от того, есть ли у них государство (решение Project Owner).

---

### 6. Уровень и судейский рейтинг

На старте механики начисления нет. Оба значения — свойства игрока и хранятся вместе с данными игрока в `00_core`, а не внутри Реестра. Реестр их только показывает.

- Уровень у всех равен единице, судейский рейтинг у всех равен нулю.
- Игрок изменить эти значения не может; возможности правки администратором в первой версии нет (решение Project Owner).
- Допустимые значения ограничены самой шкалой: уровень не ниже первого, рейтинг в пределах от −100 до +100.
- Когда появится механика, меняющая эти значения, она делает это через публичные функции `00_core`; таблица «Игроки» при этом не меняется.

---

### 7. Дата формирования государства

Игровая дата вычисляется календарём `00_core` из номера хода. Чтобы показать, когда государство сформировано, фиксируется ход, на котором оно было создано, как постоянное свойство государства.

- Триггер: создание государства.
- Условие: государство создано успешно.
- Эффект: у государства записан номер текущего хода. Он не меняется при переименовании, смене владельца провинций и других правках.

Игровая дата показывается словами по-русски (число, месяц, год). Текущая настройка календаря определяет, как выглядят даты; её изменение не требует правок Реестра.

## ИНТЕРФЕЙС (VK Mini App)

Реестр рассчитан на экран монитора, управление мышью и колесом прокрутки. Окно приложения в обычном виде — до тысячи точек по ширине; в полноэкранном режиме страницы окно шире, и таблица занимает всю доступную ширину.

**Структура экрана:**
1. Верхняя строка: заголовок «Реестр» и кнопка «Назад».
2. Ряд иконок-вкладок в самом верху окна под заголовком: одна иконка — одна таблица, активная выделена, у каждой при наведении название.
3. Строка управления таблицей: общее поле поиска, счётчик «Показано N из M», кнопки «Обновить» и «Сбросить».
4. Блок таблицы: закреплённая шапка с заголовками, значками сортировки и фильтров, ниже — строки с внутренней прокруткой.

**Что получает игрок:** для «Игроков» — № / аватарка и имя / дата присоединения / уровень / шкала рейтинга / государство; для «Государств» — № / название / флаг / дата формирования / число провинций.

**Осознанное бездействие.** Реестр не требует действий от игрока: непосещение окна и пропуск хода ни к чему не приводят.

## ВЗАИМОДЕЙСТВИЕ С ДРУГИМИ МОДУЛЯМИ

- **`00_core`** (обязательно): источник игроков, государств, числа провинций, уровня, рейтинга и хода создания государства; Реестр получает их только через публичные функции `00_core`.
- **Модули-сателлиты:** каждый может подключить к существующей или новой таблице собственный столбец, предоставив источник значения. Реестр не читает таблицы других модулей напрямую.
- **`01_map` и `02_bot`:** не требуются. Реестр не зависит от карты и бота.
- **Расчёт хода:** Реестр в нём не участвует и не имеет шага в Tick DAG.

## ГРАНИЧНЫЕ СОСТОЯНИЯ (сквозные для модуля)

- **В таблице «Игроки» всегда есть минимум одна строка** — сам смотрящий игрок.
- **Государств нет:** таблица «Государства» показывает надпись «Государств пока нет».
- **Фильтр или поиск ничего не нашли:** вместо строк — «Ничего не найдено» и кнопка «Сбросить».
- **Не удалось загрузить таблицу:** сообщение об ошибке и кнопка «Повторить»; если данные уже были показаны, они остаются на экране.
- **ВК недоступен:** раздел 5; таблица открывается с запасным видом профилей.
- **Длинное имя игрока или название государства:** обрезается многоточием, полное значение показывается при наведении.
- **Слишком много строк:** показываются первые строки по порядку по умолчанию, счётчик «Показано N из M» отражает фактическое состояние. Предел задаётся конфигом.
- **Игрок удалил государство:** при следующей загрузке оно исчезает из «Государств», а у владельца в «Игроках» в столбце «Государство» стоит прочерк.
- **Сброс мира администратором:** игроки сохраняются, государства исчезают вместе со всем остальным игровым состоянием мира.
- **Смена хода при открытом окне:** данные не меняются до открытия вкладки заново или кнопки «Обновить».
- **Ошибка в описании таблиц (конфиг):** сервер не запускается; игрок этого не видит.
- **У игрока нет государства:** окно и все данные доступны полностью.

## Решения, переданные в Spec (не геймдизайн)

1. **Факты ВК (задача REG-0, без кода).** По первоисточникам dev.vk.com проверить метод получения профилей (`users.get`): допустимый ключ (ключ сообщества), число пользователей за вызов, поля малой аватарки, ответ для удалённых и заблокированных страниц, коды ошибок и лимиты. Результат — `docs/02_SYSTEM_SPECS/03_registry_vk_facts.md`; Spec строится по нему.
2. **Данные в `00_core` (одна миграция, на ревью Lead).** Колонки уровня и судейского рейтинга у игрока с жёсткими границами на уровне БД и схемы; колонка хода создания у государства; восстановление хода создания существующих государств по журналу ходов (`tick_log`); публичные функции чтения «все игроки» и «все государства» для сателлитов.
3. **Собственные данные Реестра.** Одна таблица профилей ВК (внешний ключ только на `players`), фоновая задача получения вне Tick DAG, срок обновления, размер пакета запросов и поведение при ошибках — в конфиге. Собственный небольшой клиент ВК без обращения к `02_bot`.
4. **Конфиг и схема.** `configs/03_registry.yaml` с парной схемой: описание таблиц (идентификатор, заголовок, иконка), столбцов (идентификатор, заголовок, тип, источник значения, признаки сортировки, фильтра, поиска, ширина, заглушка), предел строк, параметры профилей ВК, положение ряда вкладок. Ошибка в конфиге останавливает запуск.
5. **API и поставщики.** Чтение описания таблиц и строк целиком одним ответом; сортировка и фильтры на клиенте; сервер отдаёт для каждого значения и отображаемую форму, и ключ сортировки (дата — готовая запись словами плюс ключ). Реестр поставщиков значений столбцов по образцу существующих реестров точек расширения.
6. **Нумерация.** Номер игрока вычисляется при чтении по порядку присоединения (время первого входа, затем идентификатор); номер государства — по порядку формирования (ход создания, затем время создания, затем идентификатор). Отдельных колонок номеров не вводится.
7. **Клиент.** Общий компонент таблицы, зависящий только от типов столбцов; панель Реестра исключается из правила перенаправления в `AppShell` (как панель карты), чтобы игрок без государства мог открыть окно; временная кнопка входа — один компонент по образцу `MapEntryButton`; при желании — вход по хэшу `#registry` (как `#map`).
8. **Дата словами.** Форматирование игровой даты по-русски выполняет сервер; учесть, что календарь `00_core` допускает год с малым значением.
9. **Режим окна.** Блок таблицы занимает высоту окна за вычетом шапки и ряда вкладок; страница приложения не прокручивается.
