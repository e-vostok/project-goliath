## 1. Цель
Новое государство появляется в игре только после того, как администратор рассмотрел анкету или прошли сутки без его ответа. На время рассмотрения провинции, цвет и оба названия заявителя зарезервированы, а территория видна на карте жёлтым пунктиром.

Дословные требования — `docs/03_ROADMAP/path_to_1_0.md`, п. 4.4; правила рассмотрения — `docs/03_ROADMAP/00_core.md`, расширение «Государства, изображения, заморозка, тексты». Здесь только состав, решения и приёмка. Слово «анкета» везде означает заявку на регистрацию государства (решение 31.10.2026); «ссылка на историю» остаётся ссылкой на историю и не переименовывается.

## 4. Риски и неизвестные
1. Картинки сейчас принадлежат государству (`nation_images.nation_id` NOT NULL), а государства до принятия нет. Нужна миграция и перенос картинок при принятии — самая крупная правка версии (ед. 4). Проверка: миграция на PostgreSQL, тест сброса мира и удаления игрока, класс NEEDS LEAD AI REVIEW.
2. Удержание территории через «отменить — отправить снова»: каждая отправка запускает новые сутки, поэтому игрок без государства может держать территорию бесконечно. Закрываем сначала наблюдением (в журнале видны циклы), предел вводим, только если появится на практике.
3. Приложение предполагает «нет государства — показать регистрацию». Состояние «анкета на рассмотрении» — третье; его нужно пройти по всем окнам, адресам хеша и сервисам, которые читают государство игрока. Проверка: перечень мест в ед. 2, браузерная проверка в ед. 7.
4. Автоприём без свидетелей: конфликт при принятии (провинцию или цвет занял администратор через панель) сорвёт создание. Закрывается тем, что панель уважает чужой резерв (ед. 5, 9), и тестом на гонку на PostgreSQL.
5. Таймер рассмотрения идёт по реальному времени фоновой задачей, вне Tick DAG (как часы приказов). Исключение записывается в Spec (ед. 2).
6. Не проверено: открытие окна анкеты ссылкой из панели (вкладка браузера без запуска ВК). Ссылка вида `vk.com/app<id>#…` из бота работает; из панели проверяется на приёмке, запасной путь — копирование ссылки.
7. Администратор может быть заявителем или единственным администратором: заявитель не рецензент для себя; если других администраторов нет — автоприём.
8. Выкладка: теги переставлены при сжатии истории; старый скрипт на сервере остановится на `git fetch --tags` (ед. 1).
9. Нагрузка карты: внешняя граница резерва считается по `borders.json`; замер в браузере обязателен (ед. 8).

## 5. Критерии приёмки (проверяет Project Owner в настоящем ВК)
1. Новый игрок проходит регистрацию, в конце нажимает «Отправить анкету»; приходит сообщение бота со ссылкой на анкету.
2. При открытии приложения вместо «Штаба» виден экран его анкеты со статусом «на рассмотрении».
3. Другой игрок на карте видит жёлтый пунктир вокруг зарезервированной территории, белое свечение провинций и подсказку при наведении; не может выбрать эти провинции, этот цвет и эти названия.
4. На рассмотрении анкету править нельзя; игрок нажимает «Отменить» — пунктир на карте исчезает, провинции, цвет и названия свободны, администратору окно показывает «отозвана игроком».
5. Администратор получает сообщение бота, щит в «Штабе» подсвечен; по ссылке открывается окно анкеты, администратор видит всё, включая картинки.
6. Администратор возвращает анкету с причиной; игроку приходит сообщение; резерв исчез (пунктир пропал, провинции свободны).
7. Игрок исправляет и отправляет снова; снова идут проверки и сутки; администратор принимает; государство появилось в Реестре, «Штаб» доступен, картинки на месте.
8. Анкета без ответа принимается сама через 24 часа; в журнале пометка «принято автоматически»; игроку приходит сообщение.
9. Панель: «Государства» → «Анкеты» — список ссылок, щелчок открывает окно; плитка «Бот» показывает числа.
10. Шкала рейтинга в Реестре; прежние функции в обеих темах; мобильное приложение ВК не сломано.
