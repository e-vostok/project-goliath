# 03_ROADMAP / 00_core

## Архитектурная цель модуля

Заложить фундамент проекта: идентификация игрока через VK (без пароля),
доменные сущности `Player` / `Nation` / `Province`, универсальный примитив
«механический деятельный акт» (`ScheduledAction`), Tick DAG-оркестратор
с точкой расширения для будущих модулей-сателлитов, собственный игровой
календарь. По завершении модуля игрок может: открыть клиент, автоматически
зарегистрироваться, создать/отредактировать/удалить государство, и увидеть,
как срабатывает ход (даже без единого подключённого модуля-сателлита —
тик просто не находит зарегистрированных обработчиков фаз и сразу переходит
к `finalize_tick()`).

### Расширение v0.3.0 (часть 1): сведения о государстве

Государство получает описательные сведения: имя и должность лидера и обязательную ссылку на историю (статью ВКонтакте). Регистрация делится на два окна с переключением стрелками. Правила — Game Bible §2, §3, §8 и Spec 1.1 (Части 1–5). Новых таблиц и шагов Tick нет: три поля добавляются к `nations`, изменяются сразу, в расчётах Tick не участвуют. Остальные пункты v0.3.0 (население и уровень развития провинций, флаг и портрет) — отдельные следующие расширения, в эту часть не входят.

### Расширение v0.8.0: «Регистрация 2.0»

Государство получает полный набор описательных сведений и регистрируется в окне из четырёх вкладок: «Основные данные и символика», «Руководство», «История и культура», «Территории». Правила — Game Bible §2, §3, §7, §8, §9 и Spec 1.3 (Части 1–5, Приложение A). Главное: краткое название (уникальное) и флаг из каталога готовых картинок; пол, портрет, биография и способ смены лидера; необязательные девиз, описание, ссылка на гимн; ровно пять стартовых провинций, столица и её название; правило различимости цветов в OKLab с готовой палитрой. Одна миграция (`0011`), новых таблиц и шагов Tick нет. Загрузка собственных картинок игроками — версия 0.9.0. План версии — `docs/04_VERSIONS/0.8.0.md`.
