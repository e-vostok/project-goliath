## Статус

Модуль 03_registry (окно «Реестр»: таблицы-справочники «Игроки» и «Государства», вкладки-иконки, сортировка и фильтры, имена и аватарки ВК).
Входы: Bible `docs/01_GAME_BIBLE/03_registry.md` (утверждена 13.10.2026), Spec 1.0 `docs/02_SYSTEM_SPECS/03_registry.md` (утверждён 13.10.2026), конфиг `configs/03_registry.yaml` и схема `backend/src/modules/_03_registry/config_schema.py` (подготовлены и проверены; коммитятся вместе с Issue 1).
Зависимость: `00_core` (закрыт). Модули `01_map` и `02_bot` не требуются.
Релиз: выпущен в v0.7.0 (17.10.2026) вместе с модулем `04_orders`.

Состояние на 17.10.2026: модуль реализован (REG-0, Issues 1–5) и выпущен в релизе 0.7.0.

Работа делится на **пять Issues и одну исследовательскую задачу (REG-0)**. Версии идут сквозной нумерацией проекта: каждый PR, меняющий поведение, поднимает PATCH (0.6.1, 0.6.2, …); релиз модуля — MINOR 0.7.0 в Issue 5.

## Архитектурная цель

Игрок нажимает «Реестр» и видит таблицу всех игроков (с государством и без) или всех государств. Таблица прокручивается внутри своего блока, не растягивая окно; столбцы сортируются и фильтруются, общий поиск находит игрока или государство по имени. Вкладки-иконки находятся вверху окна. Имя и аватарка ВК каждого игрока подтягиваются с серверов ВК в фоне; пока их нет, показывается «Игрок №N». Состав таблиц задаётся конфигом: столбец с уже существующими данными добавляется правкой YAML без изменения интерфейса, а новая механика подключает свои данные короткой функцией-источником.

## Известные риски

1. **Факты ВК проверены в REG-0** по документации; без реальных вызовов остались три пункта UNVERIFIED (см. Spec, Приложение V). Реальное поведение обнаружится только в Issue 4 и при первом запуске на сервере; все три исхода обработаны защитными ветками, худший случай — правка абзаца Spec.
2. **Дата формирования у существующих государств приблизительная.** Ход создания восстанавливается по журналу ходов (ручные запуски хода могут сдвинуть его). Для государств, созданных после Issue 1, значение точное.
3. **Адреса аватарок ВК** документацией не описаны (срок жизни неизвестен). Адрес обновляется по `profiles.ttl_hours`; при необходимости срок уменьшается правкой конфига (трек «А»). Политики CSP в Caddy сейчас нет; если её добавят, нужно разрешить `*.userapi.com`, `pp.vk.me`, `vk.com`.
4. **Правила платформы о показе имён и фото.** По решению Project Owner имена и аватарки видны всем вошедшим в приложение. REG-0 (R8): правила платформы это не запрещают; профиль удаляется по требованию игрока. Рекомендация — упомянуть показ имени и аватарки в политике конфиденциальности приложения.
5. **Календарь.** Начало эпохи в `configs/00_core.yaml` сейчас `2040-01-01`, поэтому игровые даты выглядят как «1 января 2040 г.». Меняется быстрым треком «А» в любой момент и Реестр не блокирует.
