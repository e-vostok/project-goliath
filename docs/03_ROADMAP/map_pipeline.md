# 03_ROADMAP / map_pipeline

## Статус

Служебный технический трек (не игровой модуль в терминах Full-Stack Vertical Slices — нет таблиц БД, нет тика, нет интерфейса, поэтому у него нет Game Bible и System Spec). Контракт трека — **Приложение A** к `docs/02_SYSTEM_SPECS/01_map.md`; формулы — Spec 01_map, Часть 3 (3.1, 3.2, 3.6, 3.7).

Обслуживает модуль `01_map` (`docs/03_ROADMAP/01_map.md`): выпускает файлы `data/map/manifest.json`, `geometry.json`, `ids.lock.json`, которые сервер загружает при старте.

## Архитектурная цель

Один воспроизводимый запуск превращает исходный SVG MapChart, перечень провинций игрового поля и ручные поправки в готовые данные карты: узлы суши и моря с постоянными номерами, граф связей, упрощённые контуры. Результат детерминирован (два запуска на одних входах дают файлы, совпадающие побайтно), входные файлы инструмент не изменяет, в базу данных не пишет.

Инструмент запускается вручную при изменении входов (граница, поправки, названия) — не при старте сервера и не в рабочей среде. Сервер читает только готовые файлы и не зависит от тяжёлых библиотек геометрии.

## Границы затрагиваемых директорий

- `tools/map_pipeline/` — новое: код инструмента, собственные зависимости (`requirements.txt` с геометрическими библиотеками), собственный конфиг `pipeline_config.yaml` и его Pydantic-схема, тесты
- `data/map/` — новое: `source/map.svg`, `boundary.yaml`, `overrides.yaml`, `ids.lock.json`, `manifest.json`, `geometry.json`, `README.md` (авторство и лицензия)
- `.gitignore` — выходная папка промежуточных файлов и отчётов инструмента
- Не затрагиваются: `backend/`, `frontend/`, `configs/` (параметры инструмента не входят в `configs/01_map.yaml`), любые миграции
