# 03_ROADMAP / admin_panel

## Статус

Служебный технический функционал (не игровой модуль в терминах Full-Stack Vertical Slices —
не проходит все 5 онтологических критериев, поэтому не имеет Game Bible и System Spec).

## Архитектурная цель

Прямой контроль над тестовым циклом без ожидания суточного тика: ручной запуск хода,
просмотр состояния/tick_log, сброс состояния до дефолтов — через защищённые (только для
админа) JSON-эндпоинты, без экранов VKUI. Расширяемость для будущих модулей — через реестр
хуков (AdminRegistry) по аналогии с TickOrchestrator: новый модуль регистрирует свой
reset/state-hook одной строкой, без переделки панели.

Формат вывода: все времена в admin-ответах — строки `YYYY-MM-DD HH:MM:SS` в игровой
зоне `tick.tick_timezone` под обычными именами полей; в БД хранится UTC.

## Границы затрагиваемых директорий

- backend/src/core/admin/ — новое: security.py, registry.py, router.py
- backend/src/modules/_00_core/ — правка: hook-функции reset/state_view + регистрация в lifespan
- backend/tests/core/admin/ — новое
- .env в корне репозитория (gitignored): ADMIN_VK_USER_IDS

### Расширение «Админ-панель и управление администраторами» (запрошено Project Owner 19.10.2026; не в плане, порядок решает план версии)

Общее: панель остаётся только для администраторов (проверка на сервере, не только скрытие кнопок); каждое действие пишется в журнал администратора (кто, что, когда, над чем). Правки чужих данных идут только через `service.py` модуля-хозяина (инвариант суверенности): панель не пишет в чужие таблицы напрямую.

- **Переформатировать админ-панель.** Маленькая кнопка открытия, панель открывается в отдельном окне, интерфейс упрощён до необходимого минимума (что именно необходимо — по аудиту в плане версии «единый интерфейс»). Риск: «новое окно» во ВК неоднозначно (выпадающее окно приложения или отдельная вкладка браузера, которая не получает данные запуска ВК и подписанную сессию) — ИССЛЕДОВАНИЕ перед проектированием (решение Project Owner 19.10.2026: исследование записывается в бэклог отдельной единицей типа ИССЛЕДОВАНИЕ, одно ТЗ, документ-результат); правило ширины 910 px касается всех окон, кроме карты, и для панели нужно решение отдельно.
- **Назначение администраторов.** Администратор назначает игрока администратором через панель (поиск по игроку, подтверждение, журнал). Сегодня список администраторов приходит из окружения (`.env`, `ADMIN_VK_USER_IDS`): нужно решить, где хранится правда (таблица или окружение) и как гарантировать, что нельзя остаться без администратора.
- **Снятие администраторов.** Снять администратора через панель; запрещено снимать самого себя, если он последний; корневой администратор из окружения не снимается через панель. Порядок: сначала назначение, затем снятие.
- **Создание государства администратором.** Инструмент создания государства от имени выбранного игрока без ограничений игрока (в обход анкеты и рассмотрения), но с теми же проверками формата и различимости цветов; идёт через сервис `00_core` и пишется в журнал. Решить: нужен ли тот же набор полей или упрощённый.
- **Передача секторов государству.** Выбрать сектор(ы) (провинции) и государство; сервер проверяет, что сектор свободен или явно подтверждено изъятие у другого государства; права на изменение `provinces.nation_id` у `00_core` (сервис), см. также INV-14 о судьбе столицы при смене владельца.
- **Исключение секторов из государства.** Снять сектор(ы) с государства; нельзя оставить государство без столицы без явного решения (INV-14), нельзя оставить пустое государство без подтверждения; журнал обязателен.
- **Инструментарий балансировки игры с автоматической симуляцией.** Панель запускает автоматическую симуляцию на копии мира и показывает результат (экономика, сражения, рейтинг) для проверки баланса до изменения конфигов. Единый пункт для разделов «Админ-панель» и «Рейтинг и баланс» из запроса Project Owner. Зависимость: симулировать пока нечего — экономика, армии и сражения не реализованы; сначала нужна формальная модель баланса (Bible), детерминированный запуск тика на копии БД (инвариант Tick DAG это допускает) и воспроизводимые числа (фиксированное зерно). Не брать в версию без модуля экономики (согласовано Project Owner 19.10.2026: пункт ждёт экономику, армии и сражения).
- **Трекер багов.** Окно для приёма сообщений о багах и неисправностях от игроков (короткая форма: что случилось, где, скриншот-ссылка; автоматически сохраняются версия, окно, время, игрок), список и статусы для администратора («новое», «принято в бэклог», «исправлено», «не воспроизводится»), уведомление автору при смене статуса через бота. Пока записи из трекера переносятся в бэклог вручную. Решить: хранить в базе приложения (рекомендуется) или во внешнем трекере; предел сообщений на игрока в сутки против спама; не принимать личные данные.
