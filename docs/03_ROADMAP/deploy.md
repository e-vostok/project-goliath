# 03_ROADMAP / deploy

## Статус

Служебный инфраструктурный трек (не игровой модуль: нет Game Bible, таблиц БД и фазы тика). Контракт — `docs/02_SYSTEM_SPECS/deploy.md` (версия 1.0, отклонения зафиксированы в §9).

**На 05.10.2026:** боевой сервер работает (`https://eurocon.website`, Timeweb Cloud, Москва, Docker Compose), вход из ВК проверен, суточный ход выровнен на 00:00 по Москве и прошёл автономно (проверено 05.10.2026), ежедневный бэкап с внешней зашифрованной копией на Google Диск включён. v0.5.0 выложен на сервер; Issues DEP-1…DEP-7 закрыты — трек завершён, ниже остаются хвосты M1 и бэклог.

## Архитектурная цель

Боевой сервер (пока он же staging) на одном VPS в РФ: Docker Compose (`db`, `migrate`, `backend` с одним воркером, `caddy`), один домен, автоматический HTTPS. Обновления накатываются из GitHub одной командой с бэкапом, миграциями и проверкой здоровья; суточный ход работает автономно и защищён от двойного запуска; есть бэкапы с проверенным восстановлением.

## Предусловия (вне трека, трек Б) — закрыты

- Удаление государства с `scheduled_actions`: в `main` (миграция 0004 + обнуление в `NationService.delete`).
- Драйвер PostgreSQL для alembic и логгеры (`env.py`): задача FIX-ENV, смёржена. Причина падения миграций в образе: версии библиотек не были зафиксированы, в образе оказалась SQLAlchemy 2.1.x, где «голый» `postgresql://` означает psycopg3.

## Backlog & Tech Debt

- Базовые образы: Node 20 снят с поддержки — перейти на Node 22/24 LTS; закрепить теги образов точными версиями (python:3.12.15-slim, postgres:16.15, caddy:2.11.6). Тег caddy:2 сам перескочил 2.10.2 → 2.11.6 2 октября.
- Хэши в lock-файлах (`--generate-hashes`); автообновления зависимостей (Dependabot) — отдельным решением.
- Локальная разработка на Windows не использует lock (uvloop только для Linux): версии у разработчика могут отличаться от боевых, истина — CI.
- При остановке контейнера посреди хода строка `RUNNING` в `tick_log` остаётся навсегда: помечать такие строки `FAILED` при старте (только под advisory lock).
- Стартовая проверка секрета ищет слова `dev`/`test` как подстроки: для ключа в base64 возможен редкий ложный отказ (для hex-ключа невозможен). Ослабить до точного совпадения, если станет мешать.
- `/api/v1/health` читает YAML-конфиг на каждый запрос: закэшировать, если появится частый внешний монитор.
- CI: запускать `map_pipeline` (~5 минут) только при изменениях в `tools/`, `data/map/`, `configs/`.
- Сборка образов в GitHub Actions и загрузка на сервер из реестра (если на сервере не хватает памяти для сборки или Docker Hub недоступен).
- Заголовки `X-Frame-Options`/`frame-ancestors` — после проверки в живом ВК.
- Внешний монитор доступности `/api/v1/health` и оповещения (Telegram/ВК — в спринте бота). Следить за отзывом токена Google Диска (смена пароля Google): проверять `LAST_OK` и `cron.log`.
- Скрыть кнопку «Сбросить мир» в интерфейсе, когда `ADMIN_ALLOW_RESET=false` (сейчас сервер отвечает 403 `RESET_DISABLED`, интерфейс показывает сырую ошибку на английском).
- Ограничение частоты запросов к `/api/v1/auth/vk`.
- Отдельный staging рядом с боевым — перед настоящим запуском для игроков.
- Регулярная автоматическая проверка восстановления бэкапа.
- Чистый сброс мира перед настоящим запуском (счётчик ходов сейчас 1 из-за выравнивающего хода): временно включить `ADMIN_ALLOW_RESET=true`, сбросить, выключить.
- Заменить `tick_interval_hours` в миграции 0001 (первый ход на свежей базе «через 24 часа») на `next_tick_after()` — тогда выравнивающий ход не понадобится (см. `docs/03_ROADMAP/admin_panel.md`).
- Встроить предпроверку retired_report в deploy.sh (запускать до остановки backend, останавливать выкладку при СТОП), чтобы не делать её вручную.
- Логи приложения уровня INFO не попадают в `docker compose logs`: uvicorn настраивает только свои логгеры (`uvicorn.*`), а в коде нет `logging.basicConfig` — строки вида «01_map started», «Tick N completed» теряются (доходят только WARNING+). Задать конфиг логирования при старте (basicConfig/uvicorn `--log-config`).
- Пользовательские тексты: переименование Goliath → EUROCON (отдельная небольшая задача).
