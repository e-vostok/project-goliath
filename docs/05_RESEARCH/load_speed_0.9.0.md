# Диагностика скорости загрузки — версия 0.9.0, единица 12c

Дата замера: 22.10.2026. Замер делал агент Devin по ТЗ единицы 12c. Это первый
документ в папке `docs/05_RESEARCH/` — раньше результаты небольших
исследований записывались прямо в файлы версий (раздел «Результаты
приёмки»); по ТЗ эта записка лежит отдельным файлом здесь.

## Как измеряли

- Локальная сборка «как на сервере»: `npm run build` в `frontend/`, раздача
  через `vite preview` (порт 4173, HTTPS) + настоящий бэкенд на SQLite
  (копия `dev.db`, миграции до head). Так что все запросы — и статика, и
  API — настоящие, с настоящими размерами и заголовками.
- Браузер: настоящий Chrome через Playwright. Замеры при двух профилях
  сети (эмуляция через CDP `Network.emulateNetworkConditions`):
  - **Fast 3G** — задержка (RTT) 150 мс, приём 1,6 Мбит/с, отдача 0,75
    Мбит/с;
  - **Regular 4G** — задержка 20 мс, приём 4 Мбит/с, отдача 3 Мбит/с.
- Время указано от начала загрузки страницы.
- Две важные оговорки про сравнение с боевым сервером:
  1. Локальный `vite preview` работает по HTTP/1.1 (не больше ~6
     параллельных соединений). Боевой Caddy по HTTPS работает по HTTP/2
     (и HTTP/3): все параллельные запросы идут по одному соединению без
     очереди. Значит на боевом сервере пачки мелких запросов будут чуть
     быстрее, чем в замере; время передачи крупных файлов — примерно
     такое же.
  2. Локально API-ответы жмёт сам бэкенд (gzip), статику жмёт preview.
     На боевом Caddy включены zstd и gzip — zstd жмёт JSON чуть лучше
     gzip. Размеры в таблице — переданные по сети байты (сжатые), в
     скобках — размер после распаковки.

### Повторный визит (та же сессия браузера)

Локальный `vite preview` отдаёт статике `no-cache` — при перезагрузке он
перепроверяет всё и многое качает заново. На боевом Caddy картина другая
и лучше (см. раздел про сервер): всё под `/assets/*` помечено
`immutable`, значит JS, CSS, шрифты, логотип и рельеф при повторном
запуске **вообще не запрашиваются** — берутся из кэша браузера. Геометрия
и границы тоже `immutable` (заголовок ставит сам бэкенд) — повторно не
скачиваются. Реально при повторном входе идут по сети: `index.html`
(ревалидация), `auth/vk`, горстка мелких API (~3 КБ) и **манифест заново,
103 КБ** — его ETag живёт только в памяти вкладки, при новом запуске
приложения `If-None-Match` отправить нечего.

## Что медленно и почему (по выигрышу в секундах на Fast 3G)

1. **Геометрия карты — 852 КБ по сети (2,7 МБ JSON).** Самый большой
   объект загрузки: на 3G качается ~6,3 с, на 4G ~2,6 с. Внутри —
   координаты всех 1067 узлов с точностью, которая для рисования
   избыточна.
2. **Рельеф стартует в самом конце цепочки.** Картинки рельефа (804 КБ)
   начинают качаться только после того, как доехал JSON геометрии и
   смонтировался `MapView` — на 3G это ~9,4 с. Сами они докачиваются за
   ~4 с → итог ~14 с. Рельеф физически может стартовать сразу после
   манифеста (пути к файлам зашиты в бандле) — это дало бы ~4–5 с к
   «карте с рельефом» даром.
3. **Границы карты — 424 КБ (1,3 МБ JSON).** Ещё ~4 с на 3G, идут
   параллельно с геометрией и делят с ней канал.
4. **Логотип 94 КБ PNG на экране загрузки** — на 3G прилетает ~1,1 с и
   часто опаздывает к самой карточке; до его прихода на экране загрузки
   вместо логотипа пустое место.
5. **Шрифты стартуют после CSS без предзагрузки.** На 3G фирменные
   шрифты карточки (Fira Medium + JetBrains Mono, 85 КБ) прилетают через
   ~1 с после появления карточки — видимый «перескок» текста (FOUT; в
   пропадание текста — FOIT — не уходит, везде `font-display: swap`).
   Надпись «PAX ATOMICA» (Big Shoulders, 15 КБ) перескакивает уже на
   экране загрузки.
6. **JS-бандл — 176 КБ одним куском.** Карточке не нужны карта, Реестр,
   приказы и админ-блок, но они в том же файле: ~0,9 с на 3G плюс время
   разбора. Крупные составляющие (исходный объём до минификации): VKUI
   314 КБ, @remix-run/router 194 КБ (тащит vk-mini-apps-router),
   react-dom 131 КБ, иконки VK 78 КБ, свой код ~500 КБ (из них MapView
   74 КБ).
7. **Манифест 103 КБ при каждом запуске** — нужен карточке ради названий
   провинций (~5 КБ полезного текста). На 3G ~0,6–1,3 с фоновой загрузки;
   при повторных входах повторяется, т.к. ETag не переживает перезапуск.
8. **Мелочи:** `favicon.ico` → 404 (лишний запрос, ~0,2–0,3 с слот на
   3G); `admin/me` ходит у всех игроков и получает 403 (один лишний
   запрос не-админу).

## Шрифты — что есть и что грузится

- Все шрифты — **свои файлы** в `frontend/public/assets/fonts/` (16
  WOFF2, ~368 КБ суммарно). Сторонних хостов (Google Fonts и т.п.) нет —
  внешних задержек на чужие серверы нет вообще.
- Постерный шрифт «PAX ATOMICA» — **Big Shoulders Display 800** (15 КБ),
  грузится при отрисовке экрана загрузки/верхней полосы.
- Текстовые шрифты интерфейса: заголовки — **Fira Sans Condensed Medium**
  (40 КБ), цифры/код — **JetBrains Mono** (45 КБ). Основной текст —
  **системный стек** (-apple-system/Roboto), качается 0 байт.
- Шрифты карты (12 из 16 файлов в папке — PT Sans Narrow, Roboto
  Condensed, PT Mono, Share Tech Mono, IBM Plex Mono и курсы Fira)
  описаны в `MapView.tsx`, но качаются только те, что реально рисуют
  подписи. По конфигу `configs/01_map.yaml` все три слоя подписей сейчас
  стоят на `pt_mono` → при открытии карты докачивается **один**
  `ptmono-regular.woff2` (36 КБ). Остальные 11 файлов на диске сервера
  есть, но по сети не идут.
- `font-display: swap` — везде (шрифты интерфейса и карты). Невидимого
  текста нет; есть мигание «системный → фирменный» через ~1 с после
  появления карточки на 3G.
- `<link rel="preload">` на шрифты **нет** — старт только после разбора
  CSS; на 3G это заметная пауза.
- Особенность карты: `ensureMapFont` ждёт PT Mono до 3 с и только потом
  рисует подписи — медленный шрифт тут отодвигает появление подписей, а
  не текст интерфейса.
- Нюанс кэша: файлы шрифтов лежат под `/assets/` и в проде получают
  `immutable` на год, хотя имена **не** содержат хеша. Замена файла под
  тем же именем не дойдёт до игроков до истечения года — правило:
  переименовывать при замене (или версионировать имя).

## Рельеф и данные карты

- Рельеф: два WebP с альфой, печёт `tools/map_pipeline/build_relief.py`,
  имена с хешем (`relief.playable.6ca9911a512d.webp` и
  `relief.inactive.4280659e6843.webp`). Размеры: 427 КБ / 377 КБ —
  формат сжат хорошо, проблема не в формате, а в моменте старта и
  избыточном разрешении фоновой картинки:
  - `inactive` (фон мира за игровым полем) — **6004×4633 px**: для
    декоративной подложки это в 3–5 раз плотнее, чем её видно даже на
    большом окне;
  - `playable` (рельеф игрового поля) — 3822×3697 px, ближе к нужному.
- Данные карты (API): manifest 792 КБ → 103 КБ gzip; geometry 2,67 МБ →
  852 КБ gzip; borders 1,28 МБ → 424 КБ gzip; state <1 КБ. Сжатие —
  GZipMiddleware бэкенда; в проде Caddy дополнительно умеет zstd.
- Заголовки (проверено замером, не теорией): geometry/borders —
  `Cache-Control: public, max-age=31536000, immutable` и `ETag` = версия;
  manifest — `no-cache` + `ETag` (ревалидация 304 работает, но только
  внутри одной вкладки — см. выше).
- Повторный визит: в проде геометрия, границы и рельеф берутся из кэша
  браузера без запросов (immutable). По сети остаются только мелкие API и
  манифест.
- Когда начинается загрузка данных карты: **только при открытии вкладки
  «Карта»** (проверено замером — на экране входа geometry/borders/relief
  по сети не уходят). Исключение — manifest: его на входе тянет карточка
  государства ради названий провинций.

## JS-бандл

- Сборка: **один** файл `index-*.js` 549 КБ (176 КБ gzip) + один
  `index-*.css` 381 КБ (48 КБ gzip, почти весь — стили VKUI).
  Код-сплиттинга нет; Vite честно предупреждает «chunk > 500 kB».
- Доминируют (по исходному объёму в source map): `@vkontakte/vkui` 314
  КБ; `@remix-run/router` 194 КБ (зависимость vk-mini-apps-router);
  `react-dom` 131 КБ; `@vkontakte/icons` 78 КБ; `vk-mini-apps-router` 46
  КБ; `vk-bridge` 27 КБ. Свой код ~500 КБ, из них карта (MapView +
  labels + stateNames + PanelMap + ProvincePicker) ≈ 175 КБ и
  админ-блок 15 КБ.
- Вывод: больше половины бандла (~52 % исходного объёма) — библиотеки ВК
  и react; заметная часть своего кода (карта, Реестр, приказы, админ) на
  экране входа не нужна.

## Что делает сервер для статики (по файлам репозитория)

В `deploy/` лежит **`Caddyfile`, не nginx** — в ТЗ написано «nginx», в
проекте фронт раздаёт Caddy 2 (`frontend/Dockerfile`: сборка →
`caddy:2-alpine`, `dist` → `/srv`).

- Сжатие: `encode zstd gzip` на весь сайт, включая проксируемые ответы
  `/api/*` (у бэкенда уже есть свой gzip — пережатия не страшно, Caddy
  отдаст как есть или сожмёт до zstd при поддержке клиента; Chrome ≥123
  zstd понимает).
- Кэш: всему ответу по умолчанию `Cache-Control: no-cache`; исключение —
  путь `/assets/*` → `public, max-age=31536000, immutable`. Туда попадают
  и собранные с хешем файлы Vite, и шрифты/логотипы/рельеф из `public/`
  (см. нюанс про нехешированные шрифты выше).
- API: `/api/*` проксируется на `backend:8000`, заголовки бэкенда
  (immutable у geometry/borders, ETag у manifest) проходят нетронутыми.
- HTTP/2 и HTTP/3: явно в конфиге не прописаны — у Caddy они включены по
  умолчанию на HTTPS (порт `443/udp` в compose открыт под HTTP/3). Это
  хорошо: все параллельные запросы мультиплексируются в одно соединение.
- Brotli в `encode` нет (стандартная сборка Caddy его не сжимает сам;
  zstd для Chrome покрывает ту же роль).

## Предложения

Отсортировано по ожидаемому выигрышу на «плохой» сети. Оценки — по
замеру, не обещания.

1. **Уменьшить `geometry` (и `borders`).** Округлить координаты до 2–3
   знаков и/или упростить полилинии в map_pipeline; в перспективе —
   бинарный формат или нарезка на тайлы. Выигрыш: −30–50 % к самому
   большому файлу = **−2…3 с на 3G** при открытии карты. Риск: видимое
   упрощение форм границ, нужен пересчёт выпечки и тест INV-M*. Размер:
   **L**.
2. **Стартовать скачивание рельефа раньше.** Пути к файлам зашиты в
   бандл (`relief/manifest.json`) — `new Image()` можно запускать сразу
   при монтировании `PanelMap` (или preload), не дожидаясь геометрии и
   `MapView`. Выигрыш: рельеф появляется на **~4–5 с раньше** на 3G (с
   ~14 с к ~9 с) и на ~2 с на 4G — нулевая цена байтов. Риск: почти
   нет, картинки просто начнут качаться параллельно JSON. Размер: **S**.
3. **Перепечь `relief.inactive` в меньшем разрешении.** 6004×4633 для
   декоративного фона — перебор; ~2400–3000 px по ширине достаточно и
   при открытии «на весь экран». Выигрыш: ~200–250 КБ = **~1–1,5 с на
   3G**. Риск: лёгкая размытость фона при сильном зуме за пределами
   игрового поля (там уже нет деталей). Размер: **S–M** (одна строка в
   pipeline + пересчёт).
4. **Код-сплиттинг бандла.** `React.lazy`/динамические `import()` для
   карты, Реестра, приказов и админ-блока: экран входа получает
   каркас+карточку (~половина бандла). Выигрыш: **~0,5–0,9 с до первого
   экрана** на 3G и меньше работы парсеру. Риск: рефакторинг точек
   монтирования, тесты на ленивые панели. Размер: **L**.
5. **Предзагрузка 2–3 ключевых шрифтов.** `<link rel="preload"
   as="font" crossorigin>` на Big Shoulders 800 (15 КБ) и Fira Sans
   Condensed Medium (40 КБ) — убирает «перескок» текста на входе.
   Выигрыш: стилизованный текст на **~0,5–1 с раньше** на 3G. Риск:
   шрифты конкурируют за канал с JS — поэтому только два маленьких
   файла, не весь комплект. Размер: **S**.
6. **Логотип экрана загрузки → WebP/SVG.** 94 КБ PNG → ~15–30 КБ.
   Выигрыш: логотип виден на ~0,5–0,7 с раньше и перестаёт опаздывать к
   карточке. Риск: нет (тот же арт, другой формат; фолбэк — PNG).
   Размер: **S**.
7. **Кэшировать ETag манифеста между запусками.** Положить
   `{etag, body}` в `sessionStorage`/`localStorage` — при повторных
   входах `If-None-Match` даёт 304 (~0,2 КБ вместо 103 КБ). Выигрыш:
   **~0,5–1,3 с на 3G при каждом повторном запуске**. Риск: маленький —
   при 200 после 304-логики уже есть фолбэк на полный ответ; важно
   инвалидировать при смене версии приложения. Размер: **S**.
8. **Названия провинций без полного манифеста.** Либо отдать
   `province_id → name` прямо в `/nations/me` (пара килобайт), либо лёгкий
   `/provinces/names`. Выигрыш: −~95 КБ с входа = **~0,5 с на 3G**; минус
   — карта при открытии всё равно скачает манифест (сейчас он уже тёплый
   в session cache). Риск: правка DTO и карточки. Размер: **M**.
9. **Мелочи.** Добавить favicon (убрать 404); `admin/me` дергать только
   для админов (или кэшировать 403 на сессию). Выигрыш: по ~0,2 с слота.
   Размер: **S**.

Что делать **не** предлагаю: внешний CDN для шрифтов (свои WOFF2 уже
оптимальны), `font-display: optional/block` (swap честнее для
стратегии), preconnect — сторонних хостов просто нет.

## Что проверить на сервере владельцу

Локально всё проверено, кроме поведения боевого Caddy (на сервер не
заходили). Команды выполнять на своём компьютере в PowerShell или
терминале, подставив домен:

1. **Кэш и сжатие статики (ожидаем `immutable` + zstd/gzip):**
   ```
   curl -sI "https://<домен>/assets/index-<хеш>.js" -H "Accept-Encoding: zstd, gzip"
   ```
   Смотреть строки `cache-control: public, max-age=31536000, immutable`
   и `content-encoding: zstd` (или `gzip`). Хеш файла подсмотреть в
   DevTools → Network или в HTML страницы.
2. **Рельеф — те же проверки:**
   ```
   curl -sI "https://<домен>/assets/map/relief.playable.6ca9911a512d.webp"
   ```
   Ожидаем `cache-control: … immutable`, `content-type: image/webp`.
3. **HTTP/2 (или HTTP/3):**
   ```
   curl -s -o NUL -w "protocol=%{http_version} total=%{time_total}s\n" "https://<домен>/"
   ```
   Ожидаем `protocol=h2`. Или проще: в Chrome DevTools → Network →
   колонка Protocol — должно быть `h2`/`h3`.
4. **Заголовки API карты** (нужен токен — в DevTools → Network → любой
   запрос `/api/` → Request Headers → скопировать `authorization`):
   ```
   curl -sI "https://<домен>/api/v1/map/geometry/2c9fddf246c5" -H "authorization: Bearer <токен>"
   ```
   Ожидаем `cache-control: public, max-age=31536000, immutable` —
   значит бэкендовские заголовки доезжают через прокси.
5. **Реальная картина глазами (самый важный пункт):** в Chrome DevTools
   → Network → Disable cache + троттлинг «Fast 3G», открыть приложение
   внутри ВК и сверить порядок/размеры с таблицей выше; затем вкладка
   «Карта» — смотреть `geometry`, `borders`, `relief.*`. Если на боевом
   числа заметно хуже локальных — проблема в канале/сервере, а не в
   приложении; если совпадает — работают предложения выше.
6. **Повторный вход:** закрыть мини-апп и открыть снова (не F5) при
   включённом кэше — в Network файлы `/assets/*`, `geometry`,
   `borders`, `relief` должны стоять `(disk cache)`/`(memory cache)`
   без строки запроса. Если вместо этого у них статус 200 с телом —
   immutable не доехал, и это надо чинить в Caddyfile.

Дата замера: 23.10.2026, та же методика, что и основной замер
(`vite preview` + настоящий бэкенд на SQLite, Chrome через Playwright,
CDP-профиль Fast 3G). «До» — сборка `origin/main`, «после» — ветка
единицы 10, тот же игрок без государства (вход → экран регистрации).

Реализованы предложения 2, 5, 6, 7 и 9:

- **Шрифты (5).** `<link rel="preload" as="font">` на Big Shoulders
  Display 800 и Fira Sans Condensed Medium в `index.html`: запросы
  стартуют при ~0,2 с вместо ~1,5–1,9 с (раньше ждали разбора CSS).
  Фирменный Fira Medium готов к ~2,15 с (было ~2,69 с); оба шрифта
  успевают до появления карточки — перескока текста при замере не было
  (до: Fira приходил через ~0,6 с после карточки).
- **Логотип (6).** `logo-*.webp` 76×76 — 2,7/4,0 КБ вместо 94 КБ PNG,
  PNG оставлен фолбэком через `<picture>`. Логотип прилетает к ~1,9 с —
  до карточки (~2,15 с), раньше опаздывал (конец загрузки ~2,6 с при
  карточке ~2,1 с). Предзагрузку тёмной темы не добавили: тема решается
  только JS (localStorage `pax.theme` + схема ВК), без JS не узнать.
- **favicon (9).** `public/favicon.ico` (16/32 px, белая марка на тёмной
  подложке) + `<link rel="icon">`: 200 `image/x-icon` вместо 404/фолбэка
  на index.html. Caddyfile не тронут — `/favicon.ico` не подпадает под
  `/assets/*` immutable, получает обычный `no-cache`.
- **`admin/me` (9).** Ответ прокета кэшируется в sessionStorage под
  хешем `sub` токена: «не админ» пропускает запрос при повторном входе
  в той же вкладке, «админ» перепроверяется молча. Замер: 2 запроса при
  первом входе (блок смонтирован на двух панелях) → 1, при перезаходе
  в той же вкладке 1 → 0.
- **Рельеф раньше (2).** Общий одноразовый промис загрузки в
  `lib/relief.ts`; запуск — из `loadGeometryCached` (монтирование
  панели карты, `rules.relief` уже известен), `useRelief` дожидается
  тот же промис — по одному запросу на файл. Старт рельефа: ~9,4 с →
  **~2,9 с** (сразу после манифеста, параллельно геометрии); конец
  загрузки ~13,3–13,6 с → ~10,2–10,9 с. «Карта с рельефом» целиком:
  13,8 с → 13,4 с — дальше её держат геометрия и декодирование, а не
  рельеф (честно: выигрыш к полной карте меньше обещанных 4–5 с).
- **ETag манифеста между запусками (7).** `{etag, body}` зеркалится в
  localStorage под ключом `pax.map.manifest:<версия приложения>` —
  повторный запуск шлёт `If-None-Match`: манифест 200/103 КБ → **304**
  (проверено вторым запуском в новой вкладке). Повторное «карта с
  рельефом»: 13,8 с → 12,8 с (~−1 с на ревалидации).

Итого на входе на 3G: карточка видна примерно так же (~2,1 с), но без
прыгающих шрифта и логотипа; лишних запросов меньше; на карте рельеф
начинает качаться на ~6,5 с раньше; повторный запуск экономит ~103 КБ
и ~1 с. Заметного ухудшения ни одна метрика не показала.
