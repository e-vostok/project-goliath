## [0.5.0] — 01_map

Полировка карты: рамка вида, граница игрового поля версии 2, выведенные
узлы, единый цвет воды. Спецификация 01_map — v1.10.

- Отдаление ограничено рамкой `view.frame`; панорама зафиксирована на
  рамке (`pan_margin_fraction: 0`).
- Граница поля версии 2: из игры выведены 56 провинций суши и 2 морские
  зоны (`sea_atl_africa`, `sea_iceland`); поправка границы у Александрии;
  узлов 1123 → 1065 (1030 суши, 35 морей); 58 выведенных id остаются в
  `ids.lock.json`.
- При запуске приложение удаляет невладельческие строки выведенных узлов
  из `provinces` (строка лога `Retired map nodes removed: N`); отказывается
  стартовать, если выведенная провинция имеет владельца или записи журнала
  (`RETIRED_PROVINCE_OWNED` / `RETIRED_PROVINCE_HISTORY`). `/map/state`
  игнорирует владельцев выведенных провинций.
- Читаемая преддеплойная команда `python -m src.modules._01_map.retired_report`
  (в Docker: `docker compose run --rm backend python -m src.modules._01_map.retired_report`).
- Вся вода рисуется одним цветом (`colors.inland_water` = `colors.sea`);
  классификация заливов/озёр и слой `sea_water` остаются в коде; мелкие
  острова сохраняют форму (упрощение с учётом площади); морские зоны больше
  не перекрывают кромки суши.
- Прототип рельефа не включён (архив в ветке `archive/relief-prototype`).
- Инженерное: в репозиторий влит контур деплоя (трек deploy, PR #46–#53):
  Docker-образы, CI, продакшн-гарды, lock-файлы зависимостей, скрипты и
  ранбук (`docs/deploy_runbook.md`). Боевая среда этим релизом не
  затрагивается.

## [0.4.0] — 01_map

Карта мира: игровое поле из узлов суши и моря, граф связей, раскраска по
владельцам, журнал владения и интерфейс карты. Выбор провинций при
регистрации государства теперь делается кликом по карте.

- Данные карты: 1123 узла (1086 провинций суши и 37 морских зон) и 3229
  связей четырёх типов (сухопутные, береговые, морские, проливы) в
  `data/map/`. Файлы строго проверяются при запуске сервера (схема,
  связность, контрольные суммы входных файлов); любая ошибка останавливает
  запуск с понятным сообщением.
- Инструмент `map_pipeline` (`tools/map_pipeline/`) превращает исходный SVG
  карты в готовые файлы `data/map/`; границы поля, ручные связи, проливы и
  названия задаются в `boundary.yaml` и `overrides.yaml`. Номера узлов
  зафиксированы в `ids.lock.json` и не меняются при перегенерации.
- Серверная часть: сервис карты `MapService` (соседи, проливы, связные
  компоненты, кратчайший путь); журнал владения `map_ownership_log`
  (миграция 0006) с запросом «кто владел провинцией на ход N»; две точки
  расширения в `00_core` (слушатели смены владельца и проверки регистрации
  без обратной зависимости ядра от карты); проверки регистрации
  `PROVINCE_NOT_LAND` и `STARTING_GROUP_NOT_CONNECTED` (стартовая группа
  провинций должна быть сухопутной и связной).
- API: `GET /api/v1/map/manifest` (ETag и ответ 304), `GET /api/v1/map/geometry/{version}`
  (неизменяемый кэш), `GET /api/v1/map/state?turn=` (текущее и прошлое
  состояние по журналу), `POST /api/v1/map/starting-group/check`; поле
  `kind` у провинций; сжатие ответов.
- Клиент: экран карты на VKUI с масштабированием и перетаскиванием, поиском
  по названиям, подсказкой при наведении и карточкой узла по клику,
  полноэкранным режимом, входом по ссылке `#map` и временной кнопкой
  «Карта», автообновлением раскраски после смены хода.
- Регистрация государства: ручной ввод номеров провинций убран; выбор — в
  отдельном окне с картой (счётчик «Выбрано N из M», индикатор связности,
  проверка сервером перед закрытием), выбранные провинции показываются
  названиями с кнопкой снятия; ошибки провинций выводятся под полем.
- Инженерное: запуск `alembic` берёт ту же базу, что и приложение (больше
  никакого молчаливого отката на SQLite в памяти); сквозной тест приёмки на
  настоящей карте и настоящей базе (вход → регистрация с отказами → состояние
  карты → смена хода → прошлое состояние → удаление государства → отказ
  запуска при испорченной карте) на SQLite и PostgreSQL. Автотесты: backend
  550 на SQLite и 38 на реальном PostgreSQL, frontend 192.
- Известные ограничения (в бэклоге `docs/03_ROADMAP/01_map.md`): подписи на
  карте на среднем масштабе перекрываются (план — «Подписи v2»); при выборе
  провинций блок названий сдвигает карту; названия узлов пока латиницей.

## [0.3.0] — 00_core

Расширение v0.3.0 (часть 1): государство получает описательные сведения,
регистрация становится двухоконной, а тестовый контур — честным прогоном на
реальном PostgreSQL.

- Регистрация государства в два окна со стрелками «назад»/«вперёд» и
  индикатором «Шаг N из 2»: окно 1 — название, цвет, провинции, имя и
  должность лидера; окно 2 — ссылка на историю. Данные сохраняются при
  переключении, отправляется один запрос.
- Имя и должность лидера государства: проверки длины и символов на сервере
  (коды `LEADER_NAME_INVALID`, `LEADER_TITLE_INVALID`), отображение в профиле
  и в форме редактирования.
- Обязательная ссылка на историю государства — статья ВКонтакте; формат
  проверяется по разрешённым доменам из конфига (`nation.history_url_*`),
  ошибка `HISTORY_URL_INVALID` подсвечивается у нужного поля.
- Новый эндпоинт `GET /api/v1/nations/rules` (`NationRulesDTO`) — клиент
  получает лимиты и правила с сервера и не дублирует числа у себя.
- Профиль государства (лидер и ссылка на историю) показан в админском
  просмотре состояния.
- Сквозные тесты и страж расхождения схемы на реальном PostgreSQL
  (`pytest -m postgres`): `DATABASE_URL_TEST` включает набор,
  `REQUIRE_POSTGRES_TESTS=1` превращает отсутствие URL в падение,
  `PG_TEST_REVISION` позволяет проверить страж на неактуальной ревизии.

## [0.2.0] — 00_core

Первый полный вертикальный срез игры: модуль `00_core` доведён до состояния,
в котором мир живёт сам — серверный ход проходит по расписанию без участия
игроков.

- Авторизация через VK: проверка подписи launch-параметров (HMAC-SHA256,
  свежесть `vk_ts` до 30 минут), выдача краткосрочного Bearer-JWT.
- Жизненный цикл государства: создание, редактирование и удаление нации с
  резервированием провинций и проверкой уникальности имени/цвета;
  запланированные действия игрока (`scheduled_actions`).
- Тик-движок: детерминированный оркестратор по фазам `TickPhase`, атомарный
  откат хода при ошибке обработчика, журнал `tick_log` с полной историей
  попыток (включая неудачные повторы).
- Автоматическое расписание хода: фоновый планировщик запускается вместе с
  сервером, выполняет просроченный ход один раз при старте, после сбоя ждёт
  настроенную паузу и пробует снова — ход не зависит от присутствия игроков.
- Десктоп-клиент на VKUI: экраны создания и управления государством,
  auth-gate, обработка серверных ошибок по кодам `ErrorResponse.code`.
- Инженерная надёжность: миграции доведены до полного соответствия моделям
  (внешние ключи, первичный ключ и автоинкремент `tick_log`, UNIQUE-индексы);
  тест-страж сравнивает схему свежемигрированной БД с моделями и ломает
  сборку при любом будущем расхождении. Весь набор тестов — 110 штук —
  прогоняется на реальной базе без моков.
